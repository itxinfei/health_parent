### 1.2 术语表
| 术语 | 含义 |
|---|---|
| 检查项（CheckItem） | 一项具体的体检项目（如身高、白细胞计数） |
| 检查组（CheckGroup） | 若干检查项的集合（如血常规） |
| 套餐（Setmeal） | 若干检查组的集合，面向会员售卖 |
| 预约设置（OrderSetting） | 某日期开放的可预约名额 |
| 会员（Member） | C 端用户（来自微信/手机号），系统服务对象 |
| 订单（Order） | 会员对某套餐的预约记录 |
| 到诊（Visit） | 订单状态为「已到诊」 |
| 健康档案 | 会员在平台的健康数据总集（基本信息 + 动态信息 + 病史 + 报告 + 评估） |
| 体检报告（Report） | 一次体检的结构化检查结果 + 附件（PDF/图片） |
| 健康评估 | 通过问卷/量表对会员健康状态进行量化评测（心理测评、中医体质、指标等） |
| 量表（Scale） | 标准化的评估问卷（如 SCL-90、中医体质九型） |
| 问卷引擎 | 可配置题目/选项/评分规则，支撑多种量表与自定义问卷 |
| 评估建议 | 依据评估结果自动或人工给出的健康建议 |
| 人群分类 | 按评估/标志将会员归入不同群体（用于干预与统计） |
| 干预方案（Plan） | 针对会员制定的一套健康管理措施（运动/膳食/随访等） |
| 健康方案 / 模板 | 可复用的干预方案模板 |
| 随访日记 | 对会员随访过程的记录 |
| 知识库 | 疾病库、健康方案库、健康资讯等可复用知识内容 |
| 工作台 | 管理后台首页，聚合今日业务数据与平台概况 |
| 后台（B 端） | 供健康管理机构员工使用的管理后台 |
| C 端 | 供会员使用的移动端（H5） |

## 2. 项目概述

### 2.1 背景
原项目「传智健康」为 Dubbo + Zookeeper 的 SOA 老系统（Spring5 / MyBatis3 / JDK8 / 全 XML），仅实现了「登录 + 预约」两三个功能，但配套 Axure 原型（`manage/`）与 C 端原型（`weixin/`）已勾画出一套完整的**健康管理系统**（7 大后台模块 + C 端 6 入口）。

本项目做**学习型全重写**，采用现代分布式友好技术栈（RuoYi-Vue-Plus）从零搭建，并以 AI 大模型全栈开发。功能范围经成熟产品调研确认，见 `18-调研参考与对标`。

### 2.2 目标
- 交付可运行的健康管理平台：**管理后台（B 端，7 模块）+ 会员移动端（C 端）**。
- 技术栈现代化、工程规范统一、代码可维护、可测试。
- 一套业务内核（模块化单体）同时服务 B 端与 C 端 API。
- 修正原项目全部已知缺陷（见 `15` 第 5 节、`16`）。

### 2.3 业务范围（本期）

平台由 **7 个后台模块 + 1 组统计分析 + 1 个 C 端**构成：

| # | 模块 | B 端（管理后台） | C 端（移动端） | 文档 |
|---|---|---|---|---|
| 1 | 工作台 | 今日预约/执行/评估汇总、平台概况 | — | `06` |
| 2 | 会员管理 | 会员档案、动态信息、病史、报告上传、会员统计 | 健康档案查看 | `07` |
| 3 | 预约管理 | 预约设置、预约列表、到诊登记、套餐/检查组/检查项 | 套餐浏览、预约下单 | `08` |
| 4 | 健康评估 | 问卷设置、题库、SCL-90、中医体质、指标、评估建议、人群分类 | 评估问卷作答 | `09` |
| 5 | 健康干预 | 干预方案、制定方案、健康方案、模板、随访日记、运动库、膳食库 | 干预计划查看 | `10` |
| 6 | 知识库 | 疾病库、健康方案库、健康资讯 | 健康资讯浏览 | `11` |
| 7 | 系统设置 | 用户/角色/菜单/部门/岗位/字典/参数/日志/文件/定时任务 | — | `12` |
| — | 统计分析 | 会员统计、套餐占比、运营数据、工作量统计、Excel 导出 | — | `06` |

### 2.4 角色
| 角色 | 说明 | 端 |
|---|---|---|
| 系统管理员 | 全部权限，含系统设置 | B 端 |
| 健康管理师 | 业务操作权限（会员/预约/评估/干预/知识库/统计） | B 端 |
| 会员 | 使用 C 端功能，登录后查看自己的档案/报告/评估/干预 | C 端 |

> 角色与权限基于菜单×按钮模型，见 `05`。

### 2.5 非目标（本期不做，YAGNI）
- 不做**在线支付**（预约免费，无支付模型）。
- 不做**企业团检**、**多机构/多城市**、**排队叫号**、**收费结算**、**体检工作站（PACS/LIS 对接）**。
- 不做**微服务拆分**（采用模块化单体，保持可拆分边界；不引入 MQ/注册中心/网关）。
- 不做低代码工作流引擎（不使用 RuoYi-Vue-Plus 的 WarmFlow 工作流；不使用多租户）。
- 不重写原库已冻结表结构（`t_*`）；仅新增表。

## 3. 交付形态
- 后端：以 **RuoYi-Vue-Plus 5.6.2** 为底座的项目，Maven 多模块（见 `02`）。
- 前端：管理后台 `plus-ui` 二次开发；C 端 `Vue3 + Vant`（见 `13`）。
- 部署：Docker Compose 本地起 MySQL8 / Redis7 / MinIO（见 `02`）。
