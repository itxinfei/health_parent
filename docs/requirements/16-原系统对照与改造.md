# 16. 原系统对照与改造

> 文档编号：16
> 上级：[需求与开发规范总纲](./README.md)
> 关联：01、02、04、15

## 1. 目的
记录原系统「传智健康」（Dubbo + Zookeeper SOA）到新系统（RuoYi-Vue-Plus 模块化单体）的**模块映射、技术迁移、表处理与缺陷修正**，供重写与迁移参考。

## 2. 原系统结构

原系统**完整保留在本仓库 `legacy/` 下**，不在 Maven reactor 内（根 `pom.xml` 无 `legacy` 模块），不参与构建，仅作迁移参照。

| 原模块 | 仓库内路径 | 职责 |
|---|---|---|
| `health_common` | `legacy/backend/health_common` | 实体、常量、工具 |
| `health_interface` | `legacy/backend/health_interface` | Dubbo 服务接口 |
| `health_service_provider` | `legacy/backend/health_service_provider` | Dubbo 服务实现 + MyBatis Mapper |
| `health_backend` | `legacy/backend/health_backend` | 后台管理（Spring MVC + 页面），`.do` 接口，包 `com.pangzhao` |
| `health_mobile` | `legacy/backend/health_mobile` | C 端 H5（含接口） |
| `health_job` | `legacy/backend/health_job` | Quartz 定时任务 |
| 建表脚本 | **`legacy/backend/health.sql`** | 15 张 `t_*` 表（冻结表字段真值，见 `04` §2） |
| `manage/` | `legacy/prototype/manage` | Axure 后台原型 |
| `weixin/` | `legacy/prototype/weixin` | C 端原型页 |

### 2.1 如何使用 `legacy/`（强制）
- **可以查**：字段语义、业务规则、SQL 写法、边界条件、原型交互。`15` §0.3 处理顺序的第 ② 步「查现有代码」包含 `legacy/`。
- **禁止照搬**：`com.pangzhao` 代码、Dubbo 接口、`t_user/t_role/t_permission/t_menu` 体系、`.do` 路径、原页面 jQuery 写法。迁移必须按 `02`/`03`/`04` 的新规范重写。
- **禁止**把 `legacy/` 加入 `pom.xml` `<modules>` 或让 `xfjk-*` 依赖它。
- 机器检查（`15` §5.4）默认排除 `legacy/`，不代表它合规；它是待替换的旧资产，不是可参照的实现范例。

## 3. 模块 → 新结构映射
| 原 | 新 | 说明 |
|---|---|---|
| `health_common` | `xfjk-common`（框架内置） | 工具/常量/返回体由框架提供 |
| `health_interface` + `health_service_provider` | `xfjk-modules/xfjk-health-*` | 去 Dubbo，合为模块化单体，服务即 Spring Bean |
| `health_backend` | `xfjk-web`（后台前端）+ 业务模块 Controller | 后台前端为 **plus-ui 工程化 SPA**（Vite + Vue 3 + TS + Element Plus），`17` 决策 47 改判；决策 21 的静态无构建形态已推翻，见 `19` |
| `health_mobile` | `xfjk-app`（uniapp 3 + Vue 3 + TS） | 重构为微信小程序 / H5 双端（`17` 决策 22） |
| `health_job` | `xfjk-job`（SnailJob） | Quartz → SnailJob |

## 4. 技术迁移对照
| 维度 | 原 | 新 |
|---|---|---|
| 架构 | Dubbo + Zookeeper SOA | 模块化单体（可拆分边界） |
| JDK | 8 | **25** |
| 框架 | Spring 5 / Spring MVC | **Spring Boot 4.1.1**（底座 RuoYi-Vue-Plus 5.6.2 + 本项目升级，见 `17` 决策 20） |
| 权限 | Spring Security 5（XML） | **Sa-Token** + `sys_*` |
| ORM | MyBatis 3 + tk.mybatis（XML） | MyBatis-Plus |
| 连接池 | Druid | HikariCP |
| 定时 | Quartz | SnailJob |
| 缓存 | Jedis | Redisson / Spring-Cache |
| 存储 | Qiniu / FastDFS | MinIO / S3 |
| 返回体 | 自定义 | 框架 `R` / `TableDataInfo` |
| 配置 | jdbc.properties + XML 硬编码 | `application*.yml` + 环境变量 |

## 5. 表处理
| 类别 | 表 | 处理 |
|---|---|---|
| 业务冻结 | `t_checkitem`、`t_checkgroup`、`t_checkgroup_checkitem`、`t_setmeal`、`t_setmeal_checkgroup`、`t_ordersetting`、`t_order`、`t_member` | 保留，结构冻结，实体 `@TableField` 映射 |
| RBAC 废弃 | `t_user`、`t_role`、`t_permission`、`t_menu`、`t_user_role`、`t_role_permission`、`t_role_menu` | 废弃，由 `sys_*` 取代 |
| 新增 | 见 `04` §5 | 各模块新增表 |

## 6. 数据兼容与迁移
- **后台用户**：原 `t_user`（BCrypt `$2a$`）→ 迁移到 `sys_user`；密码哈希 `BCryptPasswordEncoder` 可直接 `matches`（`$2a` 前缀兼容）—— 已核验 `health.sql` 第 629~631 行。
- **角色/权限/菜单**：原 `t_role/t_permission/t_menu` 的语义重建为 `sys_role/sys_menu`（含按钮层），原关键字（如 `CHECKITEM_ADD`）映射为新 `perms`（如 `health:checkitem:add`），种子脚本下发。
- **会员**：`t_member` 原样保留；新增档案表以 `member_id` 关联。
- **订单**：`t_order` 原样保留。

## 7. 原缺陷修正
见 `15` §6（9 项），重写时逐项修正并纳入验收。统计侧的落点与修正口径见 `06` §1.2「原实现缺陷」表（到诊恒 0、会员近月跨年、月份标签错标、套餐 N+1、热门套餐分母与 TopN、`attention` 语义挪用）与 `06` §2.4 计数真值表。

## 8. 前端迁移
| 原页面 | 新页面 |
|---|---|
| 后台各管理页（JSP/HTML） | **目标形态**：`xfjk-web/src/views/**`（plus-ui 工程化 SPA，Vue 3 + Element Plus）；登录/首页/系统管理等页**直接复用上游视图**，业务页新写。规范见 `03` §9.1、逐页需求见 `19` §3 |
| C 端微信 H5 | `xfjk-app`：uniapp 3 + Vue 3 + TS，微信小程序 / H5 双端（见 `13`、`19` §4） |

> **现状（换栈前存量，2026-10-22 实测）**：`xfjk-web` 仍是 `login.html` + `pages/*.html` 共 **15 个静态页**（Vue 2 + Element-UI 2 UMD，无构建），已按 `19` 做过视觉与交互，但**仍在调用原系统 `.do` 接口**（28 个，后端无实现）；`xfjk-app` 仅 4 个路由。页面迁移完成 ≠ 功能迁移完成，接口侧改造是剩余主体工作。
>
> **换栈处置**：`17` 决策 47 已改判为 plus-ui 工程化 SPA，实施时这 15 页**原地废弃**——其中只有 5 页（`login.html`、`index.html`、`pages/checkitem.html`、`pages/checkgroup.html`、`pages/setmeal.html`）有真实后端实现需要迁移，其余 10 页是无后端接口支撑的空壳，不迁（逐页判定见 `17` 决策 47 与 `19` §3.2）。废弃页面在实施轮删除，历史形态用 `git show ecbbac2:xfjk-web/pages/<页>.html` 取回，**不得**在工作区留双份。

## 9. 验收
1. 原库业务表数据可直接被新系统读取（字段映射正确，含驼峰列名）。
2. 原 `t_user` 账号可登录新后台（密码兼容）。
3. 原角色/权限语义在新 `sys_role/sys_menu` 中重建完整。
4. 9 项原缺陷全部修正（见 `15` §6）。
