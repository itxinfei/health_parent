## 3. 行业共识（调研归纳）
1. **体检业务闭环**：检前（咨询/选套餐/预约）→ 检中（到院登记/检项执行）→ 检后（报告查询/解读/健康管理）。
2. 预约需选日期、确认体检人、短信确认，名额有上限。
3. 套餐按**适用人群（性别/年龄）**与检查项目组织，呈「套餐 → 检查组 → 检查项」层次。
4. 健康管理以**会员健康档案**为核心，延伸**风险评估 → 干预 → 随访 → 效果评估**闭环。
5. 后台普遍采用 **RBAC + 动态菜单 + 按钮级权限**（本底座已具备）。

## 5. 明确不做（超出本期范围）
| 项 | 理由 |
|---|---|
| 在线支付 | 原系统预约免费，无支付模型 |
| 企业团检、多机构/多城市 | 超出单一机构范围 |
| 排队叫号、收费结算、体检工作站（PACS/LIS 对接） | 超出本期范围 |
| 微服务化 / MQ / 网关 | 采用模块化单体，保持可拆分边界即可 |

## 6. 结论
本目录需求的功能模块、层次结构（套餐/检查组/检查项）、预约与名额模型、会员健康档案、评估→干预→随访闭环、报表维度、后台 RBAC 权限模型，均可对应到第 2 节成熟产品实践与项目原型，**需求合理、有据可依**；「本期实现 / 不做」边界已在 `01`、`18` 明确，无范围冲突。
