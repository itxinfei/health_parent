## 1. 用途与范围

对会员实施健康干预：维护**干预模板 / 健康方案**，为会员制定**个性化干预方案**，按国标口径执行**随访计划下发 → 随访任务 → 随访表单记录 → 达标判定**闭环，并维护**运动项目库、膳食库**。方案来源可为评估结果（`09`）、模板或人工。

## 3. 状态机

### 3.1 方案状态（`t_health_intervention_plan.status`）

| 当前 | 允许动作 | 迁移后 | 前置校验 |
|---|---|---|---|
| `draft` | 编辑、启用 | `active` | 会员存在、`end_date ≥ start_date`、至少 1 条明细 |
| `active` | 编辑（追加/差异更新明细）、完成 | `completed` | 完成时至少 1 条随访记录 |
| `active` | 终止 | `terminated` | 必填 `terminate_reason` |
| `completed` / `terminated` | 仅查看、新增随访（回写 `active`? **否**） | — | 已完成/终止方案禁止再挂任务与表单（`8004`） |

禁止：`completed → active` 回退；删除用 `del_flag` 逻辑删除（`04` §4）。

### 3.2 任务状态（`18` B12 三态，固定）

```
pending ──提交国标表单──▶ done
pending ──登记失访──────▶ lost
done / lost ──▶ 终态（不可再改，只能作废新表单重录）
```

- `pending` 且 `due_date < today` → `due_flag=1`，状态不变。
- `lost` 必须填 `lost_reason`（`8010`），且该年度达标统计计入**未达标**（B9）。
- 已存在表单的任务再次提交 → `8005`，禁止覆盖历史表单。

## 4. 判定算法

### 4.1 频次口径（B1/B2/B11）

- 原发性高血压患者：`times_per_year ≥ 4`，配置键 `health:followup:hypertension:times_per_year`（默认 4，`17` 决策 44）。若配置值 < 4 → 下发计划时返回 `8009`。
- 任务表按**自然年度**生成，`stat_year` 唯一归属，12 月生成的第 4 次任务不得排到次年 1 月（B2）。
- **自动随访触发率**（B11，供 `06` 统计）：
  `触发率 = 已生成任务的应随访人数 / 符合条件的在册人数 × 100%`，目标 ≥ 85%。分母定义固定为「命中该计划 `crowd_id`/`member_ids_json` 且持有 `active` 方案的高血压会员数」。

### 4.2 血压达标（B9，服务端唯一判定）

```
失访（task.status = lost 或 form.miss_flag = 1） → bp_achieved = 0            # 直接判未达标
否则：
  若 age_at_followup >= 65 → 达标 = (sbp < 150) AND (dbp < 90)
  否则                    → 达标 = (sbp < 140) AND (dbp < 90)
```
- 年龄按 `07` 档案 `birthday` 与 `followup_date` 计算周岁，档案缺生日 → `8012`（不允许默认档位）。
- 阈值走配置：`health:followup:bp:sbp_normal=140 / sbp_elder=150 / dbp=90`、`health:followup:bp:age_rule=65`（`18` A13 同源要求，禁止魔法数）。
- 比较为**严格小于**（等于 140/90 判未达标），与 B9 原文 `<` 一致。

### 4.3 生活方式目标达成（B10）

| 指标 | 达标条件 | 备注 |
|---|---|---|
| BMI | `bmi < 24` | 严格小于 |
| 心率 | `60 ≤ heart_rate ≤ 100` | 闭区间 |
| 运动 | `exercise_times_week ≥ 5` **且** `exercise_min_once ≥ 30` | 两条同时满足 |
| `target_achieved` | 上述三项全达标 且 `bp_achieved = 1` | 综合标记 |

- 方案若通过 `target_json` 自定义目标（如 `{"bmiMax":27,"hrMin":50,"hrMax":110,"exerciseTimesMin":3,"exerciseMinOnceMin":20}`），则以方案目标覆盖默认值，并把覆盖后的口径写入 `ref_target_json` 快照（可复现）。
- 缺失对应录入值 → 该项判定为 `NULL`（未知），不得当作达标或不达标计入统计。

## 5. 业务流程

### 5.1 由评估 / 模板生成方案

1. `source=assessment` 时校验 `source_record_id` 存在且属该会员（否则 `8004`）。
2. 选模板 → 复制模板明细到方案明细（含 `times_per_week/duration_min/target_*`），`template_version` 快照。
3. 方案保存与明细写入**同一事务**；明细更新走**差异更新**（删旧 + 插新，同 `08` §4.1 规则，禁止「只删不增」）。
4. 若模板带 `followup_times`，同步落方案 `followup_times`（B1 校验）。

### 5.2 一键下发（B12）

1. 计划 `status=draft` → `PUT /health/followup-plans/{id}/issue`。
2. 解析人群：`crowd_id` 走 `09` §2.12 关联表；`member_ids_json` 走显式名单；两者都空 → `8009`。
3. 会员去重后逐个 × `seq_no 1..times_per_year` 生成任务；已存在 `(plan_id, member_id, stat_year, seq_no)` 则**跳过不重复生成**（幂等，`gen_batch` 记本次批次）。
4. 更新 `status=issued`、`issue_time`、`issue_user_id`、`total_task_count`。
5. 全过程一个事务；返回 `{generated, skipped, members}` 三个计数。

### 5.3 随访执行

1. 从「我的待随访」取 `pending` 任务 → 填国标表单 → 提交。
2. 服务端：校验任务状态（`8004`/`8005`）、年度一致（`8003`）、值域（`8008`/`8007`）、体征必填（`8012`）、血压尾数偶数（`6007`）。
3. 计算 `bmi`、`age_at_followup`、`bp_achieved`、三项目标与 `target_achieved`，写 `ref_target_json`。
4. 同事务写 `t_health_followup`（通用记录，`task_id` 回填）+ `t_health_followup_form`，并更新任务 `status=done`、`done_time`、`form_id`，回写方案 `last_followup_date` / `next_followup_date`。
5. 失访登记：`PUT /health/followup-tasks/{id}/lost`，必填原因，不生成表单；该任务计入未达标（B9）。

### 5.4 与统计 / 其他模块衔接

- `06`：随访次数取自 `t_health_followup`；执行跟踪三态与触发率取自 `t_health_followup_task`；达标率分母为同期已随访 + 失访任务数（B9 失访计入未达标）。**分工**：判定与下发规则、触发率公式（B11）以本文为唯一来源（§4.1/§4.2/§4.3）；`06` 只定义这些指标在报表里的**聚合呈现与区间口径**（`06` §5.6），其中质控四率的分子分母另见 `06` §5.5。两处冲突时按「判定归 `10`、呈现归 `06`」处理并报告冲突，**不得**在两处各写一套公式，`06` 侧**不得**出现任何阈值数字。
- `09`：评估结论与建议可一键生成方案（`source=assessment`）；人群变更不追溯已下发任务。
- `07`：体征写入随访表，**不回写** `t_health_member_profile`（档案为最新自报值，随访为历史序列）；如需同步按 `07` §5 动态信息 1:1 更新规则单独触发。
- `11`：宣教条目（`education`）引用 `t_health_advice_template` / `t_health_disease`，`ref_id` 必须校验存在。
- `13`：C 端只读本人方案与随访摘要。

## 8. 错误码（沿用 `03` §3 的 8xxx 块）

| code | 含义 |
|---|---|
| 8001 | 干预方案不存在或已停用（已用） |
| 8002 | 模板被方案引用，不可删除 |
| 8003 | 随访表单年度非法（跨自然年度，B2） |
| 8004 | 任务/方案状态不允许该操作 |
| 8005 | 任务已完成，禁止重复提交表单 |

## 10. 验收（逐条打勾）

**方案与模板**
- [ ] 模板 CRUD + 明细保存 + 发布/复制版本生效；模板被方案引用时删除返回 `8002`。
- [ ] 由模板生成方案，条目逐条复制且 `source_item_id` 可追溯；`target_json` 落方案快照。
- [ ] 方案明细编辑为差异更新（删旧 + 插新），无「只删不增」缺陷（对照 `08` §4.1 同族缺陷）。
- [ ] 状态机 §3.1 生效：`completed/terminated` 方案再挂任务或表单返回 `8004`。

**随访计划与任务（B12）**
- [ ] 一键下发按自然年度生成 `times_per_year` 条任务，`due_date` 等差且不跨年。
- [ ] 重复下发同一 `(计划,会员,年度,次序)` 幂等：`generated` 增量 0、`skipped` 计数正确。
- [ ] 任务状态仅三态，逾期通过 `due_flag` 表达；构造逾期数据验证 `status` 未被写第四值。
- [ ] 失访必须填原因（`8010`），且该任务在统计中计入未达标（B9）。

**国标表单（B2~B8）**
- [ ] `followupDate` 与 `stat_year` 不一致返回 `8003`（构造跨年用例）。
- [ ] `symptomCodes` 含 `1`（无症状）且同时选其他症状 → `8008`。
- [ ] 值域校验逐栏生效：`followWay∈{1,2,3}`、`saltIntake∈{1,2,3}`、`medicineAdherence∈{1,2,3}`、`adverseReaction∈{1,2}`、`visitClassify∈{1,2,3,4}`。
- [ ] 用药 4 组提交返回 `8007`；`adverseReaction=2` 而 `adverseDesc` 空 → `8008`。
- [ ] `sbp=137`（尾数奇）返回 `6007`；`sbp/dbp` 缺失或 `heartRate/weightKg` 缺失返回 `8012`。
- [ ] `bmi` 与 `ageAtFollowup` 由服务端算，接口拒绝并忽略前端传入值。

**达标判定（B9/B10）**
- [ ] 年龄 64 岁、`138/84` → 达标；年龄 65 岁、`148/88` → 达标；年龄 65 岁、`152/88` → 未达标；`140/85`（年龄 <65）→ 未达标（严格小于）。
- [ ] 档案缺生日 → `8012`，不得默认走 `<65` 档。
- [ ] BMI=24.00 → `bmiAchieved=0`；心率 60 与 100 边界 → `hrAchieved=1`；运动 5 次/30 分钟 → 达标，5 次/25 分钟 → 不达标。
- [ ] `target_achieved` 需四项全达标；任一录入缺失时该项为 NULL 且不计入达标。
- [ ] §7 样例（58 岁、138/84、BMI 25.51、运动 4 次）断言结果与出参完全一致。

**统计与配置**
- [ ] `/health/followup-tasks/statistics` 返回应随访 / 已随访 / 失访 / 触发率四项，触发率按 §4.1 公式（B11）。
- [ ] 阈值改动只改 `18` 与 `sys_config`/`t_health_scale_config` 侧配置，代码 diff 为 0。
- [ ] 健康管理师仅见本部门会员任务与表单（`05` 数据权限）。

## 11. 约束与禁止

- 随访方式、症状、生活方式、服药依从性、随访分类的**值域固定为 `18` B3~B8 的数字码**，禁止自造取值或改用中文串入库；字典在 `12` 登记。
- 任务状态**只有** `pending/done/lost` 三态（B12），禁止新增状态值；逾期一律用 `due_flag`。
- 血压达标与目标达成**必须由服务端计算**并写 `ref_target_json` 快照（B9/B10），禁止采信前端传入的判定结果。
- 失访一律计入未达标（B9），禁止用「跳过 / 不计入分母」处理。
- 血压尾数必须为偶数（B5）；`bmi` 由服务端算，与 `07` §2.2 同一校验实现复用，禁止两处各写一份。
- 表单以自然年度归属（B2），禁止生成跨年度记录或把 12 月任务排到次年。
- 用药组数至多 3 组（B8），第 4 组及以后无承载列，禁止塞进 `drug_other` 规避校验。
- 方案明细/模板明细更新一律**差异更新**；写操作（方案 + 明细、表单 + 通用记录 + 任务状态 + 方案回写）必须同一事务，禁止部分落库。
- `recorder/owner/executor` 一律取当前登录人，禁止由请求体传入（`03` §6）。
- 明细 `ref_id`（运动/膳食/疾病/知识）必须校验引用存在，禁止悬空引用（`11`）。
- 干预模块不得读写冻结表结构（`04` §2.1）；会员侧只按 `member_id` 关联。
- C 端仅返回本人方案与随访摘要，禁止通过 `memberId` 参数越权（`07` §8 同族约束）。
- 本期**不做** C 端打卡、电子签名、转诊流程对接、其他病种表单，禁止实现期自行扩范围（§1.2）。
