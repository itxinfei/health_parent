# 10. 健康干预

> 文档编号：10
> 上级：[需求与开发规范总纲](./README.md)
> 关联：03、04、05、07、09、11、13、18
> 模块：`com.xinfei.health.intervention`

## 1. 用途
对会员实施健康干预：维护**干预模板/健康方案**，为会员**制定个性化干预方案**，记录**随访日记**，并维护**运动项目库、膳食库**。方案可来源于评估结果或人工制定。

## 2. 数据表
见 `04` §5.4：`t_health_plan_template`、`t_health_plan_template_item`、`t_health_intervention_plan`、`t_health_intervention_item`、`t_health_followup`、`t_health_exercise`、`t_health_diet`。疾病引用知识库 `t_health_disease`（见 `11`）。

### 2.1 关键列
| 表 | 关键列 |
|---|---|
| plan_template | `id`、`name`、`code`、`category`、`crowd_id`(适用人群)、`content`(总述)、`status`、`remark` |
| plan_template_item | `id`、`template_id`、`item_type`、`ref_id`(引用运动/膳食/疾病/知识)、`content`、`frequency`、`target`、`sort` |
| intervention_plan | `id`、`plan_no`、`member_id`、`template_id`、`name`、`source`(评估/模板/人工)、`start_date`、`end_date`、`status`(进行中/已完成/已终止)、`objectives`、`operator` |
| intervention_item | `id`、`plan_id`、`item_type`、`ref_id`、`content`、`frequency`、`target`、`sort` |
| followup | `id`、`plan_id`、`member_id`、`followup_date`、`content`、`member_feedback`、`measure`(测量数据)、`recorder` |
| exercise | `id`、`code`、`name`、`type`、`intensity`、`duration`、`calories`、`description` |
| diet | `id`、`code`、`name`、`type`、`calories`、`ingredients`、`description` |

- `item_type`：`exercise`（运动）/`diet`（膳食）/`followup`（随访）/`medication`（用药）/`education`（宣教）。
- 新增表均含审计字段与 `del_flag`（见 `04` §4）。

## 4. 业务规则
- **制定方案**：可选择模板一键生成条目，也可自定义；`source` 记录来源（评估/模板/人工）。若来源于评估，关联 `assessment_record`（可扩展字段）。
- 模板/方案明细的 `ref_id` 指向运动/膳食/疾病/知识条目，业务层校验引用存在性。
- **同会员同一时间**可存在多条进行中方案（场景允许）；如需唯一性约束由配置决定（见 `17`）。
- **随访**：需关联方案与会员；记录测量数据（如血压/血糖）用于效果跟踪；`recorder` 为当前操作人。
- **删除**模板前校验是否被方案引用；删除方案前校验是否存在随访记录（存在则禁止或级联，按配置）。
- **工作量统计**中"随访次数"来源于 `t_health_followup`（见 `06`）。
- 数据权限：健康管理师默认仅见本部门会员方案。

## 5. 页面（后台）
干预方案列表、制定方案（选模板/自定义 + 条目编辑）、健康方案（模板管理）、随访日记、模板管理、运动项目库、膳食库。

## 6. 验收
1. 模板 CRUD 与明细保存正确。
2. 由模板一键生成会员方案，条目正确复制。
3. 方案状态流转（进行中/完成/终止）正确。
4. 随访新增/编辑/删除正确，并能按会员/方案查询。
5. 运动库/膳食库 CRUD 生效，可被方案引用。
6. C 端会员可查看本人方案与随访记录；越权被拒。

## 7. 约束与禁止
- 方案/模板/条目/随访的写操作必须**同一事务**，禁止部分落库。
- 明细 `ref_id`（运动/膳食/疾病/知识）**必须校验引用存在**，禁止悬空引用。
- 随访 `recorder` 取**当前登录人**，禁止由前端传入伪造。
- 删除模板/方案前**必须做引用校验**（被方案引用/存在随访）。
- 同会员"多条进行中方案"是否允许按 `17` 决策执行，**禁止擅自加唯一约束**。
- 数据权限：健康管理师默认仅见本部门方案；C 端仅返回**本人**方案。
