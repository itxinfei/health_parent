# 04. 数据库设计

> 文档编号：04
> 上级：[需求与开发规范总纲](./README.md)
> 关联：03、05、07~12
> 说明：本文件为**全局数据库约定与表清单**；各表的完整字段定义随对应功能模块文档给出（`07`~`12`）。

数据库共分三类表：**① 框架系统表 `sys_*` / `gen_*`；② 原库冻结业务表 `t_*`；③ 各模块新增表。**

---

## 1. 框架系统表（`sys_*` / `gen_*`）

由 RuoYi-Vue-Plus 提供，**直接沿用**，承载系统管理与权限，替代原库 `t_user/t_role/t_menu/t_permission` 等 RBAC 表（见 §3 废弃说明）。

| 分组 | 表 | 用途 |
|---|---|---|
| 用户权限 | `sys_user`、`sys_role`、`sys_menu`、`sys_dept`、`sys_post` | 用户/角色/菜单/部门/岗位 |
| 用户权限关联 | `sys_user_role`、`sys_role_menu`、`sys_role_dept`、`sys_user_post` | 关联表 |
| 字典参数 | `sys_dict_type`、`sys_dict_data`、`sys_config` | 字典与参数 |
| 通知日志 | `sys_notice`、`sys_logininfor`、`sys_oper_log` | 公告、登录日志、操作日志 |
| 文件 | `sys_oss`、`sys_oss_config` | 文件记录与存储配置 |
| 客户端 | `sys_client` | 多端登录配置（PC / App，见 `05`） |
| 社交登录 | `sys_social` | 三方登录（预留） |
| 定时任务 | `sys_job`、`sys_job_log` | SnailJob 任务与日志 |
| 代码生成 | `gen_table`、`gen_table_column` | 代码生成器元数据 |
| 多租户（**停用**） | `sys_tenant`、`sys_tenant_package` | 不启用，保留不删（见 `02`） |

> 本系统**不使用多租户**；如框架建表脚本包含租户表，保留但不启用、不写数据。

## 2. 原库冻结业务表（`t_*`）

来自 `health.sql`，**结构冻结**：不改列、不加审计/逻辑删除列。实体用 `@TableField` 标注原列名，主键 `Integer` + `IdType.AUTO`（见 `03` §2.1）。

| 表 | 用途 | 所属模块 |
|---|---|---|
| `t_checkitem` | 检查项 | 预约管理 `08` |
| `t_checkgroup` | 检查组 | 预约管理 `08` |
| `t_checkgroup_checkitem` | 检查组-检查项关联 | 预约管理 `08` |
| `t_setmeal` | 套餐 | 预约管理 `08` |
| `t_setmeal_checkgroup` | 套餐-检查组关联 | 预约管理 `08` |
| `t_ordersetting` | 预约名额设置 | 预约管理 `08` |
| `t_order` | 预约订单 | 预约管理 `08` |
| `t_member` | 会员（基础档案） | 会员管理 `07` |

> 字段定义见原 `health.sql`，本文档对应模块章节复述关键点（含驼峰列名与 `reservations` 可空的注意项）。

## 3. 废弃表说明（原 RBAC）

原库下列 RBAC 表**废弃、不再使用**，由 `sys_*` 取代（见 `05`、`16`）：

`t_user`、`t_role`、`t_permission`、`t_menu`、`t_user_role`、`t_role_permission`、`t_role_menu`。

- 原库 `t_user` 与 C 端会员 `t_member` 是**两类主体**：`t_user`（后台员工）→ 迁移概念到 `sys_user`；`t_member`（C 端会员）→ 保留。
- 迁移/初始化策略见 `16` 与 `17`。

---

## 4. 新增表约定（强制）

新增表统一遵守（见 `03` §2.2）：

1. 命名 `t_health_<实体>` 或 `<模块>_<实体>`（全小写 + 下划线），表名简洁达意。
2. 主键：`id BIGINT`，**雪花 ID**（`@TableId(type = IdType.ASSIGN_ID)`）。
3. 审计字段（框架 `BaseEntity`）：`create_dept`、`create_by`、`create_time`、`update_by`、`update_time`。
4. 逻辑删除：`del_flag CHAR(1)`（`0` 存在 / `2` 删除）+ `@TableLogic`。
5. **不加 `tenant_id`**（不使用多租户）。
6. 时间用 `datetime`（`LocalDateTime`）；日期用 `date`（`LocalDate`）。
7. 外键：**应用层维护逻辑关联，不建物理外键**（与框架一致）。

## 6. 主键与关联说明
- 冻结表主键 `Integer`，新增表主键 `Long`（雪花）。跨类型关联时以**逻辑 id** 关联（如 `member_id BIGINT` 关联 `t_member.id INT`），应用层转换，不建物理外键。
- 会员相关新表以 `member_id` 关联 `t_member.id`。
- 评估/干预/报告以 `member_id` 关联会员；问卷/量表内部以 `questionnaire_id`/`question_id` 关联。

## 7. 初始化与迁移脚本（强制）
- 分两个**幂等**脚本：`schema`（建表）与 `seed`（种子），可重复执行。
- 脚本**只允许新增表**；禁止改动冻结表 `t_*` 结构；禁止在生产库直接 DDL。
- 种子含：`sys_*` 基础数据、`health:*` 菜单与权限点、业务字典、示例账号/会员。
- 脚本规范详见 `03` §13；表清单以本文件 §5 为准，命名 `t_health_<实体>`。

## 8. 验收
1. 初始化脚本可建出全部 `sys_*` 框架表 + 原 8 张业务表 + 新增表。
2. 新增表含审计字段、逻辑删除、雪花主键，符合 §4 约定。
3. 各模块文档中的表清单与本文件 §5 一致，无重名/遗漏。
