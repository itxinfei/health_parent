## 1. 用途与定位

### 1.1 范围
管理后台的两块能力：
1. **工作台**（`main.html` 承载）：今日业务概况、平台存量、待办摘要、趋势图。
2. **统计分析**（`stat.html` 承载）：`18` G1 的 12 类报表 + 质控四率（G5）+ 工作量三口径与三环节（G3/C10）+ 检出率（G4）+ 四层阳性分列（G2）+ Excel 导出。

本模块是**全项目唯一的跨模块只读聚合模块**：不写业务表、不拥有业务数据、不提供 C 端接口（`13` R3）。

|---|---|---|---|
| 1 | `ReportServiceImpl` 到诊条件写 `orderStatus="到诊"` | 冻结表实际值为 `已到诊` ⇒ 到诊数恒 0 | §2.4 计数真值表，判据固定 `已到诊` |

### 1.3 关键裁定（实现期不得再拍板）
| ID | 裁定 | 理由 |
|---|---|---|
| **R1** | **到诊计数的唯一判据是 `t_order.orderStatus = '已到诊'`**（冻结列，值域三值 `已预约/未到诊/已到诊`，`18` C4 的新状态不落在该列）。`flow_status` **不得**用于反推到诊 | `t_order.orderStatus` 是 `varchar(8)` 且禁 `ALTER`（`04` §2.1）；`flow_status` 有九值且含 `已取消/延期`，与「是否到院」不同维度 |
| **R2** | 预约量按 `t_order.orderDate`（`DATE`）落自然日；**不按** `create_time` | 与 `08` §5.3 名额口径一致，避免「昨日下单今日检」被双计 |
| **R3** | 时间区间一律由服务端 `StatPeriodResolver` 由 `periodType` 解析为 `[beginDate, endDate]`（闭区间，`DATE` 粒度），**禁止**前端传裸日期参与今日/本周/本月判定 | 原实现把周一/月末算法散在 `DateUtils`；`15` 禁止魔法值 |
| **R4** | 本周 = **周一 00:00 起**（沿用原系统 `getThisWeekMonday` 语义并写死为口径）；不做 `firstDayOfWeek` 可配 | 可配会致历史报表口径漂移；如需变更须先改本文并留 `17` 决策 |
| **R5** | **比率类指标分母为 0 时返回 `null`**，前端显示 `—`；**禁止**返回 `0`、`0.00%` 或抛异常 | 0% 与「无数据」语义不同，属统计报表最常见误读 |
| **R6** | 报表类型、工作量口径、质控率类型、时间口径**四类枚举落字典**（`health_report_type` / `health_workload_caliber` / `health_qc_rate_type` / `health_stat_period`，值域见 §14 补丁，落点 `12` §3.11）。**代码禁止硬编码中文报表名** | 消除 `12` §3.10 缺口 2；满足 `03` §2 字典优先 |
| **R7** | 统计**不做行级数据权限**（不做 `@DataColumn`），只做入口权限点（§3.1）。`deptId`、`operatorId`、`memberId` 等入参仅作为**筛选条件**，不构成越权边界 | 本模块输出为聚合数与个人绩效计数，不含可识别个体的医疗结果（P07/P08 例外，须按 §3.1 附加权限） |
| **R8** | 跨模块取数**只经 `02` §3.2 的 service 接口**，禁止直查他模块表。依赖未就绪的报表**返回 `6105` 并在 `msg` 指明缺失的 service**，禁止用空数据假装成功，也禁止为过测而直连表 | `14` §1 可维护；`02` §3.2「不暴露 Mapper/Entity」 |
| **R9** | 本期**实时聚合为主**；快照表 `t_health_stat_snapshot` **只允许**两类写入：质控四率（G5）、检出率（G4），按 `(report_type, stat_date, dim_json)` upsert 且**必须可整段重算**（幂等）。工作台概览用 Redis 缓存 60 秒 | 无调度依赖即可验收；快照只作回溯，不作唯一数据源 |
| **R10** | 导出统一 `POST`（框架 `ExcelUtil.exportExcel`），**禁止**保留原 `window.location.href` 的 GET 下载方式 | 框架导出全部为 `@PostMapping("/export")`（实测 `SysConfigController:50`）；GET 下载无法带鉴权头与筛选体参数 |

### 1.4 做 / 不做
**本期做**：工作台（指标卡 + 待办 + 趋势）、12 类报表（P01~P12，其中依赖未建模块的按 §2.2 分级交付）、四层阳性分列（G2）、工作量三口径 + 三环节（G3/C10）、质控四率（G5）、检出率（G4）、报告分值统计维度（G6，**只统计不分派**）、随访触发率与达标率复用（B11/B9）、Excel 导出、两类快照。

**本期不做**（须与 `18` §5.3 一致）：
- 按报告分值**自动分配**总检人员（G6 的分配逻辑，属后续版本）。
- 智能报表/BI 自助拖拽、图表配置持久化、报表订阅邮件。
- 收费、退费、发票、单位对账相关金额统计（`18` §5.2 D-26/D-27）。
- 排队叫号与导检负荷实时看板（D-28）。
- 多院区/集团化汇总（D-32）。
- MQ 或异步大宽表预计算（本期不引入，见 R9）。

### 2.4 计数真值双轨表（`orderStatus` 与 `flow_status`）
| 统计指标 | 判据（唯一） | 禁用做法 |
|---|---|---|
| 预约数 | `t_order.orderDate` 落在区间 | 用 `create_time` |
| 到诊数 | `t_order.orderStatus = '已到诊'` 且 `orderDate` 落区间 | `orderStatus='到诊'`（原缺陷 1）；用 `flow_status` 反推（R1） |
| 未到诊数 | `t_order.orderStatus = '未到诊'` | 用 `flow_status='已取消'` 冒充 |
| 取消数 | `t_health_order_ext.flow_status = '已取消'`（依赖 `08`） | 改冻结列（禁 `ALTER`、禁扩值域） |
| 延期数 | `t_health_order_ext.flow_status = '延期'` 或 `postpone_count > 0`（两者分别出数，列名 `postponeFlow`/`postponeTimes`） | 只取其一 |
| 检查中/待总检/已总检/已打印/已发放 | `t_health_order_ext.flow_status` 九值逐值计数 | 用 `t_health_report.status` 与 `flow_status` 混填同一列 |
| 完成体检数 | `t_health_report.status IN ('已总检','已打印','已发放')` | 用 `t_order.orderStatus`（该列无此语义） |

> `flow_status` 九值与 `t_health_report.status` 六值的**单向映射**以 `12` §3.3 为唯一来源；本文不重复列值域，报表分组一律取字典。

### 2.5 本模块自有表（唯一允许写入的表）

本模块是**只读聚合模块**，全库只写这一张表。除本表外，对任何业务表的 `INSERT/UPDATE/DELETE` 均属违规（§13 第 1 条）。

**`t_health_stat_snapshot`（报表结果快照）** —— 字段级规格（本节为唯一真值；`04` §5.6 只登记表名、唯一键与指向本节的指针，已按此回写）：

| 列 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | BIGINT | ✔ | 雪花 `@TableId(type = IdType.ASSIGN_ID)` |
| `report_type` | varchar(8) | ✔ | 值域 `health_report_type`（`12` §3.11），本期**只允许** `P05`/`P06`（检出率 G4）与质控四率（G5）写入（R9） |
| `stat_date` | date | ✔ | 统计基准日（区间末日，由 `StatPeriodResolver` 给出，R3） |
| `period_type` | varchar(16) | ✔ | 值域 `health_stat_period`（`12` §3.11），标识本行按哪种区间算出 |
| `dim_key` | varchar(64) | ✔ | 维度标识（如 `dept:102`、`disease:C03`、`qc:timely`），用于列表筛与人工核对；无维度汇总行固定 `ALL` |
| `dim_json` | text | ✔ | 完整维度快照（`{"deptId":102,"batchId":null}`），参与唯一键，**必须**按键名字典序序列化，禁止手工拼接 |
| `metric_json` | text | ✔ | 指标结果快照（`{"personCount":12,"itemTimes":15,"rate":0.0312}`），分母为 0 的比率在此存 `null`（R5） |
| `num_value` | decimal(12,4) | | 单值指标（检出率/四率）冗余一份，供排序与索引查询，多值指标为空 |
| `source` | varchar(8) | ✔ | `实时聚合` / `重算`，标识本行由报表请求顺带写入还是由回溯任务重写 |
| `calc_time` | datetime | ✔ | 本次计算时间（区别于 `create_time`，重算不改 `create_time`） |
| 审计 | `create_dept`/`create_by`/`create_time`/`update_by`/`update_time` + `del_flag` | ✔ | 框架 `BaseEntity` + `@TableLogic`（`04` §4） |

唯一约束：`uk_report_type_date_dim`（`(report_type, stat_date, dim_json(64))`）—— `dim_json` 取前缀长度 64 参与索引（MySQL 对 `text` 建索引须指定前缀；若维度快照超 64 字符须先做 SHA-256 截断并在此列注明哈希前缀，**禁止**为省事把整列改成 `varchar(64)` 导致写入截断）。

索引：`idx_type_date`（`(report_type, stat_date)`）供回溯查询。

写入与重算规则（幂等，实现期不得再拍板）：
1. 写入按 `(report_type, stat_date, dim_json)` **upsert**（`INSERT ... ON DUPLICATE KEY UPDATE`），同一区间重复出数**不得**产生第二行。
2. 任一行**必须可整段重算**：删掉某日快照后重跑报表，结果逐字段一致。做不到即为实现缺陷，禁止用「快照为准」掩盖聚合口径错误。
3. 快照只作**回溯与导出复用**，**禁止**作为报表唯一数据源；报表接口每次仍走实时聚合，快照仅在其命中且 `calc_time` 落在同一区间时才允许回填。
4. 脚本/DDL 见 `04` §7；本期不建 `t_health_workload_stat`。

**`t_health_workload_stat` 本期不建表**：工作量（G3/C10）按 R9「实时聚合为主」直接出数，`04` §5.6 原登记为「可选；优先实时聚合」，本模块裁定后置到后续版本（若出现「跨月工作量对账」需求再建，届时须给出与上表相同的幂等键）。此裁定已回写 `04` §5.6（该行加删除线并注明后置条件），§12 验收清单同步改为「只建一张」。若需正式留痕，须在 `17` 增补一条决策记录。

### 5.2 四层阳性分列（`18` G2）
| 层 | 出参键 | 判据（SQL 条件封闭） | 说明 |
|---|---|---|---|
| 层一 普通科室小项阳性 | `layer1ClinicalItem` | `t_health_report_item` 中 `result_type IN ('0','1')` **且** `t_checkitem.type='1'`（检查）**且** `abnormal_flag IN ('1','2','3','4','6')` | 数值与定性项均计入；`abnormal_flag='5'`（阴性）不计 |
| 层二 检验小项阳性 | `layer2LabItem` | 同上但 `t_checkitem.type='2'`（检验） | `t_checkitem.type` 值域两值固定、禁扩（`12` §3.4） |
| 层三 影像科室检查统计 | `layer3Image` | `result_type='3'` | 影像**无 `abnormal_flag` 强制语义**，本层统计「检查人次」与「结论异常人次」（`abnormal_flag IN ('3','4')`）两列 |

- 计数单位**双列输出**：`personCount`（去重 `member_id`）与 `itemTimes`（明细行数）。单出「人次」会被误读为人数。
- `ref_configured='0'` 的明细（`18` D2）只可能被标为 `abnormal_flag='3'`，计入层一/层二；**不得**因未配置区间而排除。

### 5.3 检出率（`18` G4，分母写死）
```
某疾患检出率 = 该疾患阳性人数 / 同期受检总人数 × 100%
```
| 术语 | 本项目的唯一口径 |
|---|---|
| 该疾患阳性人数 | `t_health_report_conclusion`（`final_flag='1'`）中 `conclusion_dict_id` = 该疾患的**去重 `member_id` 数**；结论词缺失时退化为 `t_health_report_item.abnormal_flag IN ('4','6')` 且 `item_ids` 关联该疾患 | 
| 同期受检总人数 | 同期内 `t_health_report.check_date` 落区间且 `status IN ('已总检','已打印','已发放')` 的**去重 `member_id` 数**（一人多份报告计一次） |
| 同期 | 报表筛选区间；与分子同区间，**不得**分子用明细时间、分母用报告时间 |

- 未出报告者不进分母（避免「已预约未检」拉低检出率）。
- 分母 0 → `null`（R5）。
- 团体报表（P12）复用同一公式，分母追加 `batch_id` 限定（`20` §团体报告口径指向本节，见 §14）。

### 5.4 工作量（`18` G3 + C10 + G6）
字典 `health_workload_caliber` 六值固定：
| 值码 | 名称 | 判据 | 归属键 |
|---|---|---|---|
| `today_unchecked` | 今日未检 | 报告 `check_date=today` 且明细 `item_status='未检'` | `dept_id` |
| `today_checked` | 今日已检 | 明细 `check_time` 落今日且 `item_status='已检'` | `doctor`、`dept_id` |
| `past_checked` | 往期已检 | `check_time < today` 且 `item_status='已检'`，按筛选区间 | 同上 |
| `first_check` | 初审量 | `t_health_report.first_check_by` + `first_check_time` 落区间 | `user_id` |
| `summary_check` | 总检量 | `summary_by` + `summary_time` | 同上 |
| `final_check` | 终审量 | `final_check_by` + `final_check_time` | 同上 |

- 「今日未检」**按项目数**、已检按「项目人次」，三列在响应里必须带 `unit` 标注（`ITEM` 或 `PERSON`），否则不可比较。
- 人员归属：明细 `doctor` 是**姓名快照**（`07` §2.7），姓名列重复时以 `create_by` 为准并在报表出 `userId`；两者都缺 → 归入 `UNKNOWN` 行，**不得**丢弃。
- 报告分值（G6）作为**排序与分组维度**：
```
reportScore = abnormalCount × weight:abnormal
            + majorPositiveCount × weight:positive
            + criticalCount × weight:major
```
  计数分别取 `t_health_report_item` 中 `abnormal_flag` 非 `0`、`major_positive='1'`、`critical_flag='1'` 的行数；权重取 `sys_config`（§3.2）。分值**只用于统计与排序**，自动分派属后续版本（`18` §5.3）。

### 5.5 质控四率（`18` G5 + C8）
字典 `health_qc_rate_type` 四值固定。时限键：`health:qc:dept_deadline_hours`、`health:qc:summary_deadline_days`（`12` §4.2）。
| 率 | 值码 | 分子 | 分母 |
|---|---|---|---|
| 合格率 | `qualified` | 同期已总检报告中，无 `revoke_flag='1'` **且**无 `send_back_flag='1'` 的报告数 | 同期 `status IN ('已总检','已打印','已发放')` 报告数 |
| 及时率 | `timely` | `first_check_time` 距 `check_date` ≤ 科室时限 **且** `summary_time` 距 `first_check_time` ≤ 主检时限 **且** `final_check_time` 非空的报告数 | 同上 |
| 漏检率 | `missed` | 进入 `待总检` 及以后状态、其明细中 `item_status='未检'` 的**项目行数** | 分子所在报告的应检项目行数（口径由 `health:stat:miss_rate_item_denominator` 切换：`SETMEAL` = 套餐展开数；`REPORT` = 报告明细行数） |
| 危急值处理率 | `critical_handled` | `t_health_critical_log` 中 `handle_result` 非空 **且** `receiver_confirm_time` 非空 | 同期 `report_time` 落区间的登记总数 |

- 四率均为 `decimal(5,4)` 原值 + 展示百分号两位小数；分母 0 → `null`（R5）。
- 及时率**必须**同时满足三段才算及时，任一段缺失即计为不及时（不是「未统计」）。
- 漏检率分子分母**必须**同一口径（`18` C2 的真实差错：延期未录入会被报告默认显示「未见异常」，故 `item_status='延期'` **单独成列**，不并入漏检，见 P10）。
- 结果按 R9 写 `t_health_stat_snapshot`。

### 5.6 随访指标（`18` B11/B9，只引用不重述）
| 指标 | 来源 | 本文用法 |
|---|---|---|
| 自动随访触发率 | `10` §4.1 公式与分母定义 | 工作台卡 6 与报表列，目标线取 `health:followup:trigger_rate_target` |
| 三态分布 | `t_health_followup_task.status`（`pending/done/lost` 固定，`12` §3.3） | 报表列 `pendingCount/doneCount/lostCount` |
| 逾期数 | `due_flag=1 AND status='pending'` | 逾期不是第四态（`10` §3.2） |
| 血压达标率 | `10` §4.2 判定 + `10` §6「达标率分母 = 同期已随访 + 失访任务数」 | 报表列 `bpAchievedRate`，`bp_achieved` 由 `10` 服务端计算，本模块只读 |
| 生活方式达标率 | `10` §4.3（B10） | 读 `target_achieved` |

> 本节**不出现任何阈值数字**；公式若与 `10` 冲突，以 `10` 为唯一来源并报告冲突。

### 5.7 评估指标（`09` §6.1 的 `GET /health/assessments/statistics`）
评估人数、筛查阳性率、`severity` 五档分布由 `09` 的 `GET /health/assessments/statistics` 出数，本模块**只做呈现与聚合拼装**，不重算：
- 阳性判据按 `18` A10（`t_health_assessment_record.positive_flag`），严重度取 `severity`（`12` §3.7 `health_severity` 五值）。
- 本模块请求 `09` 接口时必须带同一区间参数，避免两处时间口径不一致。

### 5.8 统一呈现规则
| 情形 | 服务端出参 | 前端显示 |
|---|---|---|
| 分母为 0 | 字段存在、值 `null` | `—` |
| 依赖模块未就绪 | 该字段不出现 + 整请求若全部依赖缺失则 `6105` | `—` 并在列头提示「依赖未就绪」 |
| 计数为 0 | `0` | `0` |
| 比率 | `decimal(5,4)`，如 `0.0312` | `3.12%` |
| 身份证/手机号（仅 P07/P08/P12 含） | 按 `health:export:mask_level` 与 `health_export_mask` 三值脱敏（`03` §脱敏） | 列表与导出同样脱敏 |

各报表输出列（口径已在上文定义，此处只列字段）：

**P01 体检人数统计** — `rows[{period, orderCount, visitCount, noVisitCount, finishCount, printCount, issueCount, cancelCount, postponeFlowCount, postponeTimesCount}]`；`period` 由 `dim` 参数（`DAY/MONTH`）决定格式。

**P02 综述汇总** — `rows[{conclusionType, reportCount, personCount, conclusionFinalCount}]`；`conclusionType` 值域 = `health_total_conclusion`（`18` F14 三值）。

**P03 阳性结果汇总** — `layers{layer1ClinicalItem, layer2LabItem, layer3Image, layer4DeptSummary}`，每层 `rows[{deptId, deptName, itemCode?, itemName?, abnormalCount, personCount, itemTimes}]`；顶层另有 `totalPersonCount`（去重到人的合计，不等于四层相加）。

**P04 体检疾患清单** — `rows[{conclusionDictId, conclusionName, conclusionType, grade, personCount, itemTimes, reportCount}]`；`grade` 取 `health_abnormal_grade`（A/B，`18` D6）。

**P05 疾病人数统计** — `rows[{diseaseCode?, conclusionDictId, name, personCount, detectionRate, rank}]`；`detectionRate` 严格按 §5.3。

**P06 疾病分布统计** — `rows[{sex, ageRange, maritalStatus, personCount, detectionRate}]`；`sex` 展示口径按 `18` H14 与 `12` §3.6，`ageRange` 由服务端按 `birthday` 计算 5 岁一档（档宽写死在本节，改档须改本文）。

**P07 个人数据分析** — `data{memberId, archiveNo, name(脱敏), reportCount, reports[{reportId, reportNo, checkDate, conclusionType, conclusionFinal, abnormalCount, majorPositiveCount, criticalCount, reportScore}], items[{itemName, unit, refRange, resultsByReport}]}`；权限按 §3.1 双权限点。

**P08 历年指标趋势** — `data{archiveNo, checkitemId, itemName, unit, points[{checkDate, reportNo, result, abnormalFlag, edgeFlag}]}`；按 `archive_no` 归并（`18` F5 一号制），`edge_flag='1'` 须随点返回（`18` D3）。

**P09 弃检统计** — `rows[{deptId?, checkitemId?, itemName, setmealId?, batchId?, discardTimes, personCount, discardRate, reasonDist[{reason, count}}]}]`；`discardRate` 分母同 §5.5 漏检率口径键；`reason` 取 `discard_reason`（`item_status='弃检'` 时必填，`18` C2，缺失计数进 `REASON_MISSING` 行）。

**P10 延期统计** — `rows[{deptId?, itemName?, postponeTimes, personCount, restoredCount, stillPostponeCount, avgDelayDays}]`；`restoredCount` 取 `t_health_item_reset_log.action='延期恢复'`；**延期不并入漏检**（§5.5）。

**P11 项目超标统计** — `rows[{checkitemId?, itemName, resultType, abnormalTimes, personCount, gradeADist, gradeBDist, criticalTimes, majorPositiveTimes, edgeTimes}]`；按 `abnormalTimes` 降序取 TopN（N 走 `health:stat:hot_setmeal_top` 之外的独立参数 `topN`，默认 20，上限 200）。

**P12 单位/团体报告** — `data{batchId, batchNo, companyName, planCount, memberCount, registeredCount, visitedCount, finishedCount, issueCount, completeRate, diseaseSpectrum[{name, personCount, detectionRate}], deptStats[{deptName, personCount, abnormalTimes}]}`；`detectionRate` 按 §5.3 加分母 `batch_id`；疾病谱与阳性分析按 `18` G7，**不含任何费用列**（`18` D-26）。

## 9. 字段校验与错误码

校验规则见 §6 共享参数表；本节登记本模块专属码。

**段位说明（重要）**：`03` §3 规定新模块用 `MMNNN` 五位码。`06` 若照此写为 `06001`，作为 `Integer` 传输时**等价于 `6001`**，与会员块（`6001~6013`）直接冲突。故本文破例：**统计模块占用 `6xxx` 段内未被任何文档登记的 `6101~6115`**，并在 `03` §3 与本节双登记；`6001~6013` 归 `07`、`6101~6115` 归 `06`，两段不重叠；其余新模块仍必须用 `MMNNN` 五位码。此例外已列入 §14 补丁第 1 项。

| code | 含义 | 触发点 |
|---|---|---|
| `6101` | 报表类型非法 | `reportType` 不在 `health_report_type` 值域 |
| `6102` | 统计区间非法 | `periodType` 非法，或 `custom` 缺日期、起止倒置 |
| `6103` | 统计区间跨度超限 | 超过 `health:stat:max_range_days` |
| `6104` | 导出行数超限 | 超过 `health:stat:export_max_rows`，提示缩小范围或走异步 |
| `6105` | 报表数据源未就绪 | 依赖的跨模块 service 缺失（§2.2），`msg` 必须写出缺失接口名与所属文档 |
| `6106` | 快照不存在 | `snapshots` 查询无对应记录 |
| `6107` | 统计维度入参缺失 | P08 缺 `checkitemId`、P12 缺 `batchId`、P07 两者皆缺等 |
| `6108` | 报告分值配置非法 | §3.2 三个权重键全为 `0` 或不可解析（区别于 `12003` 的通用缺键） |
| `6109` | 字典与文档不一致 | `health_report_type`/`health_workload_caliber`/`health_qc_rate_type`/`health_stat_period` 值域与本文不一致（语义同 `12002`，本模块用于报表入口自检，禁止拿 `12002` 顶替以便定位） |

- 越权访问由框架返回 `403`，**禁止**另造业务码（与 `13` §8 同一原则）。
- 未在本表与 `03` §3 登记的码，**禁止**在代码中出现（`15`）。

## 10. Excel 导出规格
1. 方式：`@PostMapping("/health/stat/{reportType}/export")`，入参与查询接口相同（`@RequestBody`），`void export(Bo bo, HttpServletResponse response)`。
2. 实现：`ExcelUtil.exportExcel(list, sheetName, Vo.class, response)`（框架 `com.xinfei.common.excel.utils.ExcelUtil`）。
3. **文件名**：框架实测 `encodingFilename(sheetName)` 生成 `{uuid}_{sheetName}.xlsx`，且 `resetResponse` 为私有方法不可覆写 ⇒ 本模块**通过 sheetName 携带日期**：`sheetName = {报表名}_{yyyyMMdd}`，报表名取字典 `health_report_type` 的中文标签（不在代码里写字面量）。旧文档「文件名固定 `report_yyyyMMdd.xlsx`」不成立，本文更正。
4. 表头：由导出 VO 的 `@ExcelProperty` 决定；字典列用 `@ExcelDictFormat(dictType = "...")` + `ExcelDictConvert` 翻译，**禁止**导出原始码值；比率列导出为百分号字符串两位小数。
5. 脱敏：导出受 `health:export:mask_level` 控制，三值取 `health_export_mask`（`12` §3.6）；`明文(需权限)` 需另持 `health:memberreport:query`，且写 `@Log(businessType = BusinessType.EXPORT)` 留痕。
6. 行数：超过 `health:stat:export_max_rows` → `6104`，**禁止**静默截断（截断导出不完整数据比报错更糟）。
7. 前端：`js/api.js` 需为导出增加 `responseType: 'blob'` 分支——`api.js` 响应拦截器按 `code` 解信封，二进制流**没有** `code` 字段，必须绕过信封解析并触发下载，否则导出必然报错（这是本文与 `03` §9.1 的对接要求，列入 §14 补丁）。
8. 一致性验收：同一筛选条件下，导出文件数值必须与页面数值逐项相等（含 `—` 的处理，导出写空串不写 `null`）。

- **禁止**跨模块直查表与引入他模块 Entity/Mapper（R8，唯一例外见 §2.2 白名单与到期日）。
- **禁止**分母为 0 时返回 `0` 或抛异常（R5）；**禁止**把「依赖未就绪」伪装成空数据（R8）。
- **禁止**新增 `.do` 接口或保留原 `window.location.href` 式 GET 下载（R10）。
- **禁止**为提速引入 `@Scheduled`、`Thread`+`sleep` 轮询或 MQ 预计算；异步需求走 SnailJob 并在 `12` §6.1 登记（`12` §6.3）。
- **禁止**一次性全表加载：所有明细类报表必须分页，导出必须校验行上限（`14` §1）。
- **禁止**在报表或导出中输出可识别个体的医疗结果给无 `health:memberreport:query` 的调用方；身份证/手机号一律按 §5.8 脱敏。
- **禁止**把统计结果当医学结论（`18` §7）；报表文案不得出现「已确诊」类表述。
- 性能：`14` §1 要求 P95 < 500ms；聚合 SQL 必须命中索引（`check_date`、`item_status`、`flow_status`、`report_id` 建表时须带索引，见 `04` 补丁），**禁止** `SELECT *` 后在内存过滤分组。
