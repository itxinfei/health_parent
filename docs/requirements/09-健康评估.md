## 1. 用途与范围

## 3. 引擎设计

### 3.1 概念模型

```
questionnaire 1─N question 1─N question_option
questionnaire 1─N scale_factor（因子定义 + 条目数 + 常模）
questionnaire 1─N scale_rule （区间 → 等级/结论）
questionnaire 1─N scale_config（阈值/记分法，A13）
questionnaire 1─N suggestion  （因子/等级 → 建议）
member ──N record 1─N answer / 1─N factor ──N member_crowd
```

题目与因子解耦：因子归属只存在于 `t_health_question.factor_code`，**算分代码不得出现任何题号数组**——A14 的分配表是数据，不是代码常量。

### 3.2 计分类型（`scoring_type`）

| 值 | 产出 | 适用 |
|---|---|---|
| `sum` | 仅总分 + 等级 | 普通问卷 / 风险测评 |
| `factor` | 总分 + 各因子原始分与因子分 | SCL-90 |
| `scale` | 因子原始分 + **转化分** + 逐因子判定 + 总体判定 | 中医体质 |

### 3.3 反向计分（A2，实现前必须确认的顺序）

```
若 question.reverse_flag = 1：score = (answer_max_score + answer_min_score) − raw_score
SCL-90 / 中医体质（1~5）：1↔5、2↔4、3↔3、4↔2、5↔1
```
**先反向、再求和**（A2 原文口径）；`raw_score` 与 `score` 两列都要落库（§2.8），便于对账与单测复现。

### 3.4 数值与舍入约定（本文定稿）

- 除法结果一律 `BigDecimal`，`RoundingMode.HALF_UP`；因子分保留 3 位小数、转化分与总分保留 2 位、均分保留 2 位。
- **判定使用舍入后的值**（与展示一致，避免「显示 39.99 却判 ≥40」类争议）。
- 阈值比较的含/不含语义见 §2.5 约定（左闭右开 + 严格大于）。

## 4. 内置标准量表算分规格

### 4.1 SCL-90（`scale_type=scl90`，`18` A8~A15）

**输入约束**：90 题、全部 `required=1`、`type=single`、五级 1~5（`scl90.scoring.method=1to5` 写死；A8 的另一套 0~4 记分**禁止混用**，若需 0~4 输出仅在展示层做 `score − 1`，落库仍为 1~5）。

**计算步骤（顺序固定）**：

| 步 | 产出 | 公式 | 口径 |
|---|---|---|---|
| 1 | 校验完整性 | 90 题均有作答，否则 `7002`；分值越界 `7011` | A8 |
| 2 | 反向映射 | §3.3（SCL-90 标准无反向题，`reverse_flag` 全 0，机制保留给自定义问卷） | A2 |
| 3 | 总分 | `total = Σ score_i`，范围 90~450 | A15 |
| 4 | 总均分 | `avg = total / 90` | A15 |
| 5 | 阳性项目数 | `positive_count = count(score_i ≥ 2)` | A15 |
| 6 | 因子原始分 | 每因子 `raw_sum_f = Σ score_i (i ∈ 因子项集)` | A14 |
| 7 | 因子分（均分） | `factor_score_f = raw_sum_f / item_count_f` | A8 |
| 8 | 超常模标记 | `norm_exceed_flag = factor_score_f > norm_mean_f + norm_sd_f` | A11 + 本文定稿 |
| 9 | 筛查阳性 | `positive_flag = (total > 160) OR (positive_count > 43) OR (∃f factor_score_f > 2)` | A10 |
| 10 | 严重度分级 | §4.1.2 | A12 |
| 11 | 结论与建议 | §5.3 | — |

> **步骤 8 的解释声明**：`18` A11 只写「超常模即判该因子异常」，未给不等式方向；本文取**常模上界 X̄ + 1SD** 为唯一解释（配 `scl90.norm.exceed=upper`），并把它与步骤 9 的 `>2` 筛查线**分列为两个独立标记**（`norm_exceed_flag` / `positive_flag`），前端与报告不得混用为一个「异常」。若体检中心要求改用 `X̄ + 2SD` 或其他口径，改 `18` A11 与配置值，不改代码。

#### 4.1.2 心理严重度分级（`18` A12，取最高档短路）

设 `n2 = count(2 ≤ fs < 3)`、`n3 = count(3 ≤ fs < 4)`、`n4 = count(fs ≥ 4)`（`fs` 为因子分）：

| 优先级 | 等级 | 条件 |
|---|---|---|
| 1 | `severe` 重度倾向 | `n4 ≥ 1` **或** `n3 ≥ 3` |
| 2 | `moderate` 中度倾向 | `(1 ≤ n3 ≤ 2)` **或** `n2 ≥ 3` |
| 3 | `mild` 轻度倾向 | `1 ≤ n2 ≤ 2`（且不满足更高档） |
| 4 | `sub_health` 心理亚健康 | `1.5 ≤ avg < 2` 且无上述因子档 |
| 5 | `normal` | 其余 |

> A12 原文的「1~2 个因子均分 3~4 或 ≥3 个因子均分 2~3」按上表映射；判定按优先级**自上而下短路**，一条记录只出一个等级。`sub_health` 依赖总均分，与其他档不互斥时让位于更高档。

### 4.2 中医体质辨识（`scale_type=tcm9`，`18` A1~A7）

**输入约束**：60 条目、9 个亚量表（平和质 + 8 种偏颇），每亚量表 7 或 8 条目（A1），五级 1~5；带 `*` 条目标 `reverse_flag=1`（A2）。

**转化分（A3）**：

```
原始分 raw_k = Σ（该亚量表条目分，先按 §3.3 反向）
转化分 C_k = (raw_k − n_k) / (n_k × (5 − 1)) × 100 = (raw_k − n_k) / (n_k × 4) × 100
```

**判定顺序（不可交换）**：

1. 对 8 种偏颇逐一分档（A5）：`C ≥ 40 → 是`；`30 ≤ C < 40 → 倾向是`；`C < 30 → 否`。
2. 平和质（A4）：`C_平 ≥ 60 且 其余 8 种 C 均 < 30 → 是`；`C_平 ≥ 60 且 其余 8 种 C 均 < 40 → 基本是`；否则 `否`。
   —— 由该规则本身即得「存在偏颇 ≥40 时平和质必为 `否`」，**不得**先判平和再判偏颇。
3. 兼夹倾向（A6）：偏颇质中 `C ≥ 30` 的**种数** `≥ 2` → 判为兼夹倾向。`tcm_combine_json` 输出清单**排除主导体质本身**（只列兼夹项），但计数含主导项；该「计数含、清单不含」的语义为本文定稿，实现不得反推为「清单长度 ≥2」。
4. 主导体质 `tcm_primary`：取偏颇质中转化分最高者；若其 `< 40` 则只出「倾向」不出「是」；8 种偏颇全 `< 30` 且平和质为 `是/基本是` → 主体质为平和质。
5. 结论文案由 §2.5 `tcm_convert` 类规则 + §2.10 建议模板产出，文案形态如「基本是平和质，有痰湿质倾向」。

**单元测试基线（`18` A7，必须落为断言，禁止改数）**：

| 用例 | 输入（转化分） | 期望输出 |
|---|---|---|
| TC-A7-1 | 平和 75、气虚 56、痰湿 12、余 6 种 < 30 | `tcm_primary=qixu`、`tcm_level=yes`、平和质判定 `否`（**不得判平和质**） |
| TC-A7-2 | 平和 75、痰湿 32、余 7 种 < 30 | 平和质 `基本是`、`tcm_level=tendency`、结论含「有痰湿质倾向」 |

**A16 缺口**：逐条目 → 亚量表归属、以及哪些条目带 `*` 反向，公开来源未给一致表（`17` §2 待确认 11）。引擎**不得**内置题号常量，必须由 `t_health_question.factor_code + reverse_flag` 驱动；题库导入须由业务方按 ZYYXH/T157-2009 原表核对，导入脚本须输出「9 个亚量表条目数 = 60、每条有 `factor_code`」的对账结果（`04` §7 本期种子必备数据）。

### 4.3 普通问卷 / 风险测评

`category=question`、`scoring_type=sum`，仅产总分与等级；原型的「风险测评」归入此类（不新建第四套 `scale_type`）。多选求和按选项 `score` 累加；本期不做权重矩阵。

## 5. 评估流程

### 5.1 提交作答（C 端/后台代填，同一事务）

1. 校验问卷 `status=published`（否则 `7001`）；`is_public=0` 时 C 端不可见（`13`）。
2. 校验 `member_id` 存在（`6001`，`07` §7）。
3. **幂等**：同会员同问卷存在 `status=doing` 记录则复用并覆盖答案；已 `scored` 的记录禁止重复提交（`7010`）。
4. 完整性校验：必答题数 = `question_count`，缺答返回 `7002`；分值越界 `7011`；量表类问卷 `item_no` 覆盖不完整返回 `7004`。
5. 按 §4 算分，写 `t_health_assessment_answer`（逐题）、`t_health_assessment_factor`（逐因子）、更新 `t_health_assessment_record`，状态 `scored`。
6. 按 §5.3 匹配结论与建议，写 `suggestion_json` 快照。
7. 按 §5.4 计算人群并写 `t_health_member_crowd`（带 `source_record_id`）。
8. 全流程一个事务；任何一步失败整体回滚，**禁止部分落库**。
9. 返回结构化结果（§6.2）。

### 5.2 发布校验

`PUT /health/questionnaires/{id}/publish` 前必须通过：题目数一致、因子条目数求和一致、SCL-90 与 A14 逐因子比对通过、常模字段齐备、`scale_config` 必填键齐备、每条 `scale_rule` 区间左闭右开且 `min < max`。任一不过 → `7004`/`7005`/`7006`，并返回逐项错误清单（形态同 `20` §6 逐行标错）。

已发布问卷的题目/选项/规则**禁止原地修改**（`7007`），须 `POST /health/questionnaires/{id}/copy-version` 生成 `version+1` 草稿；历史评估记录按其快照版本查询，保证可复现。

### 5.3 结论与建议匹配

优先级：`(问卷, 因子, 等级) > (问卷, 因子) > (问卷, 等级) > (通用, 因子) > (通用)`；命中即取，同优先级按 `sort`。文案为空时不输出建议，**禁止代码兜底拼接诊断语**（承接 `07` §10）。

### 5.4 人群归类

评估完成后即时按 `t_health_crowd_rule` 求值；已存在同 `(member_id, crowd_id, source_record_id)` 则跳过（幂等）。人群条件可引用因子分、指标、报告字段（`07`）、档案字段（`07` §2.2）。`10` 干预模块按人群下发随访计划（`18` B12）。

## 11. 约束与禁止

- **量表题干、因子归属、条目数、阈值一律以 `18` §3.A 为准**；A16 未登记的中医体质逐条目归属与反向题号**禁止自编**，须等业务方标准原表（`17` 待确认 11）。
- **禁止在代码中出现题号数组、因子常量、阈值字面量**（`18` A13）：SCL-90 的 90 项分配、常模线、判定区间全部来自 `t_health_question.factor_code` / `t_health_scale_factor` / `t_health_scale_rule` / `t_health_scale_config`。
- **记分法项目内唯一**：SCL-90 与中医体质固定 1~5（`18` A8），禁止同一问卷混用 0~4；需要 0~4 展示时在接口出参层做换算并标注。
- 判定语义固定：`18` A4/A5/A6 的 `≥` 为含、A10 的 `>` 为**不含**；区间一律左闭右开（§2.5）。实现不得擅自把 `>` 改成 `≥`。
- 已发布问卷**禁止原地改**题目、选项、因子与规则；变更必须 `copy-version` 递增版本，保证历史记录可复现（§5.2）。
- 历史评估记录**禁止**因阈值/题库变更而被重算覆盖；重算能力本期不做（§1.2）。
- 提交作答必须**同一事务**，缺答/越界/配置不全禁止部分落库（§5.1 第 8 步）。
- 输出必须是**筛查/评估口径**，不得表述为医学诊断（承接 `07` §10、`18` D3）；文案来自规则与建议模板，禁止字符串拼接出「诊断」字样。
- `t_health_member_crowd` 写入必须带 `source_record_id`，禁止无来源归类；人群规则阈值禁止硬编码。
- 评估模块**不得**读写冻结表结构（`04` §2.1），会员侧数据只按 `member_id` 关联 `t_member` 与 `07` 的新表。
- C 端与 B 端的量表内部字段（判定规则、常模、因子码）一律不下发，防止前端自行算分（`03` §6）。
