# 07. 会员管理

> 文档编号：07
> 上级：[需求与开发规范总纲](./README.md)
> 关联：03、04、05、06、08、13
> 模块：`com.xinfei.health.member`

## 1. 用途
管理会员及**健康档案**：会员基础档案、动态信息、病史、体检报告（上传与结果）、会员标签/人群，以及会员统计。

## 2. 数据表
| 表 | 用途 | 类型 |
|---|---|---|
| `t_member` | 会员基础信息（冻结表） | 原库 |
| `t_health_member_profile` | 动态信息/健康状况（1:1 扩展） | 新增 |
| `t_health_member_history` | 病史 | 新增 |
| `t_health_report` | 体检报告主表 | 新增 |
| `t_health_report_item` | 报告明细 | 新增 |
| `t_health_member_tag` / `t_health_member_tag_rel` | 会员标签与关联 | 新增 |

### 2.1 `t_member`（原库冻结，保留列）
`id`(PK int)、`fileNumber`、`name`、`sex`、`idCard`、`phoneNumber`、`regTime`(date)、`password`、`email`、`birthday`(date)、`remark`。列名含驼峰，实体须 `@TableField` 显式标注。

### 2.2 `t_health_member_profile`（动态信息）关键列
`id`(雪花)、`member_id`、`height`、`weight`、`bmi`、`blood_pressure`、`heart_rate`、`blood_type`、`smoking`、`drinking`、`exercise_freq`、`sleep_hours`、`diet_habit`、`marital_status`、`occupation` + 审计字段。

### 2.3 `t_health_member_history`（病史）关键列
`id`、`member_id`、`type`（`disease` 疾病史 / `family` 家族史 / `allergy` 过敏史 / `surgery` 手术史 / `medication` 用药史）、`content`、`happen_date`、`remark` + 审计字段。

### 2.4 `t_health_report` / `t_health_report_item`
- report：`id`、`member_id`、`report_no`、`check_date`、`summary`、`conclusion`、`doctor`、`file_url`（PDF/图片附件）、`source`（上传/接口）、`status` + 审计字段。
- report_item：`id`、`report_id`、`checkitem_id`（可空，关联 `t_checkitem`）、`item_name`、`result`、`unit`、`ref_range`、`ref_min`、`ref_max`、`abnormal_flag`（`0` 正常 / `1` 偏高 / `2` 偏低 / `3` 异常）、`remark`。

## 4. 报告解析规则
- 结果文件格式（Excel/CSV）：列含 `检查项/结果/单位/参考范围`（表头可配置映射）。
- 解析流程：读取 → 匹配 `t_checkitem`（按名称/编码）→ 比对参考区间（`ref_min`/`ref_max`）→ 写 `abnormal_flag`（正常/偏高/偏低/异常）→ 生成 `t_health_report_item`。
- 解析失败或部分行异常：跳过异常行并返回明细（错误码 `9001`），不整体回滚已成功行（或按配置整体事务，见 `17`）。
- 附件（PDF/图片）存 MinIO（目录 `report/`），`file_url` 记录。

## 5. 业务规则
- 会员 `phoneNumber` 存在性：同一手机号在系统内视为同一会员（C 端注册/登录按手机号识别，见 `08`）。
- 删除会员前校验业务引用（订单/报告/评估/干预），存在则禁止删除并返回业务错误码。
- 动态信息 1:1，保存时不存在则插入、存在则更新（`member_id` 唯一）。
- 报告明细的 `checkitem_id` 可为空（如系统中无对应检查项时仅存名称）。
- 数据权限：健康管理师默认仅见本部门会员（见 `05` §2）。

## 6. 会员统计（并入 `06`）
- 新增会员趋势、会员总数、按性别/年龄段分布（可扩展）。

## 7. 验收
1. 会员 CRUD 生效；分页与模糊查询正确。
2. 动态信息保存与回显正确（1:1）。
3. 病史多类型增删改正确。
4. 报告上传成功、附件可下载；结果文件解析后明细与异常标记正确。
5. 删除有业务引用的会员被拦截。
6. 会员统计数值正确。

## 8. 约束与禁止
- 冻结表 `t_member` **禁止加列/改类型**；扩展一律走新表并以 `member_id` 关联。
- 报告附件与结果文件**必须走 OSS 抽象**（MinIO/S3），禁止本地磁盘裸存。
- 上传须校验**扩展名与大小**；附件下载/预览须鉴权。
- 删除会员**禁止级联硬删**他模块数据，必须先经引用校验（订单/报告/评估/干预）。
- 结果文件解析的异常行处理按 `17` 决策执行，**禁止静默丢弃**。
- 身份证/手机号等敏感字段输出须**脱敏**（见 `03` §6、`05` §7）。
- C 端档案/报告接口仅返回**本人**数据；禁止信任前端传入的 `memberId`。
