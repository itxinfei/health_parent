# 07. 会员管理与健康档案

> 文档编号：07
> 上级：[需求与开发规范总纲](./README.md)
> 关联：03、04、05、06、08、11、13、18、20
> 模块：`com.xinfei.health.member`
> 口径来源：`18` §3.F（档案与报告 F1~F14）、§3.D（结果判定 D1~D11）、§3.C（状态机与质控 C1~C10）。**只引用口径 ID，不复述阈值**。

## 1. 用途
会员与**健康档案**的总入口：基础档案、动态信息、病史、一号制档案号、档案完整度、体检报告（附件 + 结构化结果 + 五段正文 + 结论 + 签发链）、危急值登记、科室小结、会员标签。

本模块是**报告级数据的唯一落库点**：`08` 的到诊登记只建报告草稿，结果录入/判定/质控/结论/发放全部落在这里；`20` 的团体报告也从这里聚合。

### 1.1 实现现状（2026-10-23 校准）
**管理侧 `/health/members/**` 全部未实现**（无 MemberController，`t_health_*` 会员/报告侧表均未建）。例外：**C 端会员登录已入库**——`MemberLoginService` + `AppAuthController`（`/app/auth`）在 `xfjk-health-appointment` 内（2026-10-23 代码入库，未经联调实测）。`t_member` 已有 8 张冻结表之一，`docs/sql/01-schema.sql` 已建并有种子。

## 2. 数据表

### 2.1 `t_member`（冻结，只读结构）
`id`(PK int)、`fileNumber` varchar(32)、`name`、`sex`、`idCard` varchar(18)、`phoneNumber` varchar(11)、`regTime`(date)、`password`、`email`、`birthday`(date)、`remark`。

**冻结表缺口（本模块一切扩展存在的理由）**：
- 无 `archive_no` 独立列语义、`fileNumber` **无唯一约束且种子多为 NULL** → 一号制只能应用层 + 新表承载（`18` F5、`17` 决策 41、`04` §2.1）。
- 无婚姻、性生活史、妊娠状态、职业、血型、联系方式以外的任何档案字段 → `18` E11 的四维校验只能读扩展表。
- 禁止 `ALTER`/加索引；禁止用「同手机号视为同一会员」之外的自动合并（`18` F4 账号与档案分离）。

## 4. 报告解析规则（Excel/CSV 结果文件）
- 列格式：`检查项 / 结果 / 单位 / 参考范围`（表头可配置映射，`12` 字典 `health_report_header`）。
- 流程：读取 → 按名称或编码匹配 `t_checkitem` → 取 `t_health_checkitem_ext` 判 `result_type` → 按 §2.7 匹配参考区间（性别/年龄/生理状态，`18` D2）→ 写判定与异常标记 → 落 `t_health_report_item`。
- 匹配不到检查项：仍落库，`checkitem_id` 为空、`item_name` 用原文件值、`ref_configured=0`，并在返回明细中列为「未匹配」。
- **异常行处理**：逐行容错，跳过异常行并返回行级明细（`9001`），不整体回滚已成功行（`17` 待确认 1 的建议项，已按此实现口径）。
- 附件与结果文件都走 OSS 抽象；`file_url` 存 `sys_oss.oss_id`，返回时换签名 URL（与 `17` §1.2 第 2 条同规则）。
- 危急值与重大阳性在解析阶段即判定并触发 §5.5。

## 5. 业务规则

### 5.1 会员识别与合并
- 唯一识别键：**`idCard`**（按 `18` H13 校验合法性）。`phoneNumber` 相同仅作 C 端登录归一的辅助线索，**不得自动合并档案**（`18` F4 账号与档案分离）。
- `idCard` 建档后不可改；确需纠错走「新建 + 人工迁移申请」，本期**不做自动迁移**（记入 `17` 待确认）。
- 团检导入按 `20` §5.1 匹配/建档；个人下单按 `08` §5.3 步骤 4。

### 5.2 完整度与缺项
- 完整度实时计算，不落库；档案页显示 `已填/应填` 与缺项列表。
- 未标记且为空的必填项 → 档案页红色提示，报告不得签发（`6004`），除非有对应 `missing` 行说明原因。

### 5.3 结果判定（`18` D1~D3）
1. `result_type=0`（数值）：解析结果数字 → 按 `ref_min/ref_max` 比较 → `abnormal_flag ∈ {0,1,2}`；无法解析数字则 `3` 并要求人工确认。
2. `result_type=1`（定性）：只接受阳性/阴性/弱阳性 → `abnormal_flag ∈ {4,5,6}`（阳性/弱阳性同时置 `abnormal_flag=3` 以便统计阳性率）。
3. `result_type=2/3`（文本/影像）：不做数值判定，`abnormal_flag` 由医生选择。
4. `ref_configured=0` 一律不得判 `0 正常`（`18` D2）。
5. `edge_flag=1`（临界值）与基础值异常者须给复查提示（`18` D3），复查走 `08` §5.7。
6. 录入即时提示偏高/偏低（`18` D8），提示文案取 `ref_range` 原文。

### 5.4 结论与末次保存（`18` F7/F8/D9）
- 总检提交时写 `t_health_report_conclusion`：整段 `conclusion` 文本由条目拼接生成，保证「文本可打印、条目可统计」两套并存。
- 每次总检医生改结论，**旧条目 `final_flag` 置 0，新条目组置 1**，形成末次结论快照；`conclusion_final` 同步为末次整段文本。
- 同 `merge_group_id` 的条目视为一条合并结论展示（`18` D9），字典统一用词（`18` F8）。
- 结论条目全部来自 `t_health_conclusion_dict`；自由文本结论仅允许 `其他结论` 类型。

### 5.5 危急值与重大阳性（`18` D4~D7）
- 判定入口唯一：结果落库（录入或解析）时按配置的危急值线判定；命中即 `critical_flag=1`。
- 命中后**必须**在 30 分钟内完成登记与接收确认（时限来自本期实现约定，**不属于 `18` 口径**，已登记为待确认项）。
- 重大阳性（`major_positive=1`）：总检界面自动弹框要求填写处置意见，填写内容**跨医生可见**（`18` D7）。
- 危急值线为可配置默认值，上线前须院方核对本院目录（`17` 待确认 10）。
- 未处理的危急值进入质控报表（`18` G5 危急值处理率），清单入口 = `GET /health/criticals?handled=false`（§3.2.1）。

### 5.6 质控链（`18` C8~C10）
| 环节 | 责任人字段 | 时限口径 | 未达标处置 |
|---|---|---|---|
| 科室自查 | `first_check_by/time` | 按 `18` C8 | 计入及时率（`18` G5） |
| 主检审核 | `summary_by/time` | 按 `18` C8 | 同上；超时须填写原因 |
| 终审签发 | `final_check_by/time` | 按 `18` C8 | 未签发不得发放 |
- `revoke_flag=1` 期间科室方可改结果（`18` C9）；打回某科室用 `send_back_flag`。
- 初审不通过清单与三环节工作量可分别查询（`18` C10），报表口径见 `06` §5.5（质控四率：合格/及时/漏检/危急值处理）与 `06` §5.4（工作量六口径，含 `first_check`/`summary_check`/`final_check` 三环节）；时限阈值仍取 `12` §4.2 的 `health:qc:dept_deadline_hours`、`health:qc:summary_deadline_days`。

### 5.7 数据权限
- 健康管理师默认仅见本部门会员（`05` §2）；体检医师仅见本科目明细；主检医师见全报告。
- C 端一律只返回**本人**数据，禁止信任前端 `memberId`（`05` §7 第 2 条）。

### 5.8 会员停用与恢复（取代"删除会员"）
- **触发**：后台 `PUT /health/members/{id}/status`（权限点 `health:member:remove`），值 `member_status` `0↔1`，落 `t_health_member_profile`（§2.3）。无 profile 行的存量会员按 upsert 先建行再置状态。
- **停用的后果**（四处一致，缺一处即算未实现）：
  1. 后台会员列表默认 `WHERE member_status='0'`，需看停用者时显式传状态筛选；
  2. C 端登录与下单**拒绝停用会员** → `1002`（`03` §3「账号不可用/被停用」），禁止为此另开新码（`6014~6100` 空置不得占用，`03` §3）；
  3. 统计（`06`）会员数/建档数/人群分布**不含**停用者，历史报表快照不受影响；
  4. 已存在的订单、报告、评估、干预、团检名单**全部保留并可查**——停用是账号级开关，不是数据删除。
- **恢复**对称：置回 `0` 即重新出现在上述三处；操作写 `sys_oper_log`（框架留痕），本期不建独立状态流水表。
- **禁止**：对 `t_member` 执行 `DELETE`；为绕过外键而级联删 `t_order`；把停用实现为 `del_flag`（该列在 `t_member` 不存在）。

## 9. 验收
- [ ] 新增会员同事务产出 `t_member` + `archive_no` + `profile` 三行；档案号唯一且不可重复生成（`18` F5）。
- [ ] 同一身份证跨批次导入、C 端注册、人工建档三条路径都归一到同一档案号。
- [ ] **停用会员**（`PUT /health/members/{id}/status`）后：后台列表默认查不到、C 端登录/下单返 `1002`、统计不计入，但其历史订单与报告仍可查；恢复后三处同时回来（§5.8 四处一致）。**且**：`DELETE /health/members/{id}` 不存在（调用应 404），全库无对 `t_member` 的 `DELETE` 语句。
- [ ] 完整度显示 `已填/应填`；未标记的空白必填项阻止报告签发（`6004`）。
- [ ] 血压尾数非偶被 `6007` 拒绝（`18` B5 同规则）。
- [ ] 结果录入按 `result_type` 走 §5.3 三条分支；数值项判定值只由服务端产出。
- [ ] 匹配不到参考区间时 `ref_configured=0` 且绝不判「正常」（`18` D2）。
- [ ] 弃检未填原因被 `6009` 拒绝；延期项在报告中不得显示「未见异常」（`18` C2，与 `07` 校验联动）。
- [ ] 需双科室分检的项目，对侧未完成时本侧提交不得把项置为 `已检`（`18` C3）。
- [ ] 危急值命中即置 `critical_flag`，未登记/未确认的项在质控清单中可见，处理率统计口径可复算（`18` G5）。
- [ ] `GET /health/criticals?handled=false` 返回集合 = 「登记数 − 已填 `handle_result` 数」，与 `06` §5.5 危急值处理率的分子分母**同口径可对账**（同区间同数据两处结果必须一致）；`ruleCode` 传六码之外的值返回空集合并提示，`beginTime > endTime` 被 `400` 拒；出参不含 `idCard`/`phoneNumber`。
- [ ] 重大阳性在总检界面弹框，处置内容对其他医生可见（`18` D7）。
- [ ] 多异常合并为一条结论展示（`18` D9），字典用词统一（`18` F8）。
- [ ] 末次结论单独保存且历史可追溯（`18` F7）；改结论不影响历史条目。
- [ ] 已总检未撤销前科室改结果被拒（`18` C9）；撤销与打回均留痕。
- [ ] 三级质控责任人与时间齐全（`18` C8）；未终审签发的报告不可发放。
- [ ] 上次报告与历年趋势接口返回可比对结果（`18` D11）。
- [ ] 报告解析逐行容错，异常行返回明细，成功行不丢失（`9001`）。
- [ ] 附件与结果文件走 OSS；下载/预览需鉴权，发放件带水印（`18` F11）。
- [ ] 身份证/手机号在列表、详情、导出中均脱敏。
- [ ] C 端仅能取本人档案与报告（前端 `memberId` 不参与判断）。

## 10. 约束与禁止
- `t_member` **禁止加列/改类型/加索引**；扩展一律走本文件 §2 的新表并以 `member_id` 关联（`04` §2.1、`17` 决策 42）。
- **禁止**用 `t_member.fileNumber` 做唯一性判断；一号制唯一性只认 `t_health_member_archive_no`。
- **禁止**前端传入 `abnormalFlag`/`criticalFlag`/`abnormalGrade`，一律服务端判定。
- **禁止**把「无箭头」「无参考区间」呈现为「未见异常」（`18` D2/D3）。
- 结果文件解析的异常行**禁止静默丢弃**（`17` 待确认 1 已按逐行容错口径实现）。
- 报告附件与结果文件**必须**走 OSS 抽象（MinIO/S3），禁止本地裸存；上传校验扩展名与大小，下载/预览必须鉴权。
- **禁止删除会员**：`t_member` 无 `del_flag` 且被 `t_order` 物理外键引用，删除/级联硬删一律禁止；需要让某会员不可用时走 §5.8 **停用**，历史订单、报告、评估、干预、团检名单全部保留可查。
- **禁止**绕过三级质控直接置 `报告已发放`；也禁止在未撤销总检的情况下修改科室结果（`18` C8/C9）。
- 危急值与结论的医疗判断责任在医生；系统只提供判定辅助与留痕，**禁止**把自动判定表述为诊断结论（`18` §7「禁止医疗结论自动化免责」）。
- 身份证/手机号/姓名等敏感字段输出必须脱敏（`03` §6、`05` §7、`15` 安全红线）。
- C 端仅返回本人数据；禁止信任前端传入的 `memberId`。
