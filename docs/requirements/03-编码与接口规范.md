# 03. 编码与接口规范

> 文档编号：03
> 上级：[需求与开发规范总纲](./README.md)
> 关联：02、04、05、15

## 1. 命名规范
- Java 类 `PascalCase`；方法/变量 `camelCase`；常量 `UPPER_SNAKE_CASE`。
- 包名全小写；业务模块包 `com.xinfei.health.<module>`。
- 业务表沿用 `t_xxx`（原库冻结表）与新表前缀规范（见 `04`）；实体字段用 `@TableField` 显式标注列名。
- 布尔字段用 `isXxx` 或 `xxxFlag`。
- 禁止拼音缩写、禁止 `tmp`/`data1` 之类无意义命名。

## 2. 数据库与 ORM 规范

### 2.1 原库冻结表（`t_*`）
- **沿用 `health.sql` 原 schema**，表名/列名不变；**不新增任何列**（含审计/逻辑删除字段）。
- 原库存在驼峰列名（如 `orderDate`、`helpCode`、`member_id` 混用），因此：
  - 实体字段名与列名**完全一致**，每个字段用 `@TableField("列名")` 显式标注；
  - 该模块可单独关闭下划线转驼峰（避免歧义）。
- 主键类型 `Integer`（原库 `int auto_increment`），`@TableId(type = IdType.AUTO)`。
- 日期字段 `DATE` → `java.time.LocalDate`；`DATETIME` → `LocalDateTime`；**禁止 `java.util.Date`**。
- 枚举用字符串常量类（值与原库一致）：`已到诊`/`未到诊`、`电话预约`/`微信预约`。
- 逻辑删除：**原库表默认物理删除**（无 `deleted` 列）；删除关联时先清理中间表。

### 2.2 新增表
- 表名 `t_health_<模块>_<实体>`（或模块内简洁命名，全小写 + 下划线），见 `04`。
- 统一含框架 `BaseEntity` 审计字段：`create_dept`、`create_by`、`create_time`、`update_by`、`update_time`；逻辑删除 `del_flag`（`0` 存在 / `2` 删除）+ `@TableLogic`。
- 主键用**雪花 ID**：`Long id` + `@TableId(type = IdType.ASSIGN_ID)`。
- 审计字段由 MP 自动填充（框架 `InjectionMetaObjectHandler`）；时间统一 `LocalDateTime`。
- **不使用多租户**：新增表**不加 `tenant_id`**。

### 2.3 通用
- 分页统一 MP `IPage`，入参用框架 `PageQuery`（`pageNum`/`pageSize`/`orderByColumn`/`isAsc`），出参用 `TableDataInfo`。
- 查询一律 `LambdaQueryWrapper` / XML 参数绑定；**禁止字符串拼接 SQL**。
- 字典：固定枚举值优先用字典表（`sys_dict_type/sys_dict_data`）承载，前端用框架字典组件。

## 3. 统一返回与错误码

成功/失败统一结构（框架 `R<T>`）：
```json
{ "code": 200, "msg": "操作成功", "data": {} }
```
分页结构（框架 `TableDataInfo<T>`）：
```json
{ "code": 200, "msg": "查询成功", "rows": [], "total": 100 }
```

| code | 含义 |
|---|---|
| 200 | 成功 |
| 401 | 未登录 / 令牌失效（框架处理） |
| 403 | 无访问权限（框架处理） |
| 500 | 系统异常（框架默认） |
| 1001 | 用户名或密码错误 |
| 1002 | 账号不可用/被停用 |
| 2001 | 短信验证码错误或已过期 |
| 3001 | 检查项被检查组引用，不可删除 |
| 3002 | 检查组被套餐引用，不可删除 |
| 4001 | 套餐下存在预约，不可删除 |
| 5001 | 预约日期未设置 |
| 5002 | 预约日期名额已满 |
| 5003 | 重复预约（同会员/同日/同套餐） |
| 6001 | 会员不存在 |
| 7001 | 量表/问卷不存在或未发布 |
| 7002 | 评估作答不完整/无效 |
| 8001 | 干预方案不存在或已停用 |
| 9001 | 报告附件解析失败 |

> 业务错误码集中在 `com.xinfei.health.common.constant`（或各模块 `constant`）定义，避免魔法数字。

## 4. 异常规范
- 业务异常抛框架 `ServiceException(message)` 或 `ServiceException(code, message)`。
- 框架 `GlobalExceptionHandler` 全局捕获；参数校验异常 → 400/统一提示。
- 禁止在 Controller `try/catch` 后返回裸字符串；统一走异常或 `R`。
- **禁止吞异常**（`catch` 后不处理/不记录）。

## 5. 日志规范
- 使用 SLF4J（`@Slf4j`）；**禁止 `System.out.println`**。
- 关键业务节点记录 INFO；异常记录 ERROR 并带堆栈。
- 写操作接口加框架 `@Log(title = "...", businessType = BusinessType.XXX)` 记录操作日志。
- 日志中**禁止打印**密码、令牌、身份证完整值、手机号完整值（脱敏，可用框架 `@Sensitive`）。

## 6. 安全规范
- 密码用编码器（`BCryptPasswordEncoder` 兼容原库 `$2a$` 哈希，见 `17`）；禁止明文/可逆存储。
- 认证与鉴权用 **Sa-Token**（见 `05`）；接口权限注解 `@SaCheckPermission("health:member:list")`。
- C 端登录用短信验证码（存 Redis，5 分钟有效，一次性使用）。
- 短信统一走 `sms4j`：**开发环境用模拟实现**（仅日志输出验证码，不真实发送）；后期配置厂商密钥即可切换，不改业务代码。
- 外部配置（DB 密码、Redis 密码、MinIO 密钥、短信密钥）走环境变量/`.env`。
- 上传文件校验扩展名与大小；MinIO 桶最小权限（默认私有）。
- 写接口可加框架 `@RepeatSubmit`（防重复提交）、`@RateLimiter`（限流）。

## 7. API 规范
- **系统管理**：沿用框架 `/system/**`（用户/角色/菜单/部门/岗位/字典/参数/日志等）。
- **业务 B 端**：前缀 `/health/**`（如 `/health/members`、`/health/orders`、`/health/ordersettings`、`/health/setmeals`、`/health/checkitems`、`/health/checkgroups`、`/health/reports`、`/health/assessments`、`/health/plans`、`/health/knowledge`）。
- **C 端**：前缀 `/app/**`（如 `/app/auth/login`、`/app/setmeals`、`/app/orders`、`/app/reports`、`/app/assessments`、`/app/plans`、`/app/articles`、`/app/archives`）。
- RESTful：查询 `GET`、新增 `POST`、更新 `PUT`、删除 `DELETE`；资源用名词复数、路径全小写、多词用连字符。
- 登录统一放 `/{端}/auth/login`。
- 分页参数：`pageNum`（默认 1）、`pageSize`（默认 10）、`orderByColumn`、`isAsc`；模糊查询用业务字段名（如 `name`/`phone`）。
- 日期格式：`yyyy-MM-dd` / `yyyy-MM-dd HH:mm:ss`。
- 接口必须有 SpringDoc 注解（`@Tag`/`@Operation`）。

## 8. 缓存规范
- Key 命名 `模块:业务:标识`，如：`health:sms:order:{phone}`、`health:sms:login:{phone}`、`health:img:uploaded`、`health:img:used`。
- 值序列化用 JSON。
- 所有 Key 必须设置过期时间。
- 会话类由 Sa-Token 管理（见 `05`），业务代码不直接操作会话 Key。

## 9. 前端规范
- 后台：基于 `plus-ui`，工程化 Vite + TypeScript；**禁止**非工程化 jQuery/独立 HTML 页面。
- 目录遵循 plus-ui 约定：`api / views / components / store / router / utils / types`。
- 请求统一走 plus-ui 的 Axios 封装，自动带 token、统一处理 401/403/错误提示。
- 路由与菜单由后端 `sys_menu` 动态下发；按钮权限用指令 `v-hasPermi`。
- C 端：Vue3 + Vant，独立工程。

## 10. 文件存储规范
- 用 MinIO（或 S3 协议云存储）替代原 Qiniu/FastDFS；统一走框架 `xinfei-common-oss` 抽象。
- 命名：`UUID + 扩展名`，按业务目录隔离（`setmeal/`、`report/`、`avatar/` 等）。
- 上传成功后记 Redis 集合 `health:img:uploaded`；业务保存引用时记 `health:img:used`。
- 无效图片清理规则见 `08` 与 `12`（SnailJob 定时任务）。

## 11. 代码风格与注释（强制）
- 遵循阿里巴巴 Java 开发规范（P3C 思想）；缩进 **4 空格**，源文件 **UTF-8（无 BOM）**，换行 **LF**。
- 类与公共方法写简要 Javadoc；**禁止**把注释当作用户沟通手段（如 `// TODO 问用户`）。
- 用 Lombok（`@Data`/`@Slf4j` 等）消除样板；不得滥用或与框架冲突。
- 命名达意；禁止拼音缩写与无意义名（`tmp`/`data1`）。
- 前端遵循 plus-ui 的 ESLint/Prettier 配置，提交前通过校验；禁止关闭规则绕过。

## 12. 测试规范（强制）
- 框架：**JUnit 5 + Spring Boot Test**；Mock 用 **Mockito**；持久层用内嵌库或本地 MySQL。
- 命名：`*Test`；用例名体现"场景 + 预期"。
- **必须覆盖**：预约防超卖、删除引用校验、关联差异更新、评估计分、权限/越权。
- 运行命令：后端 `mvn -q test`（或指定模块）；前端以 plus-ui 脚本为准。
- **禁止**提交无断言或恒真的"空测试"；禁止为过测而删改业务逻辑。

## 13. SQL 与初始化脚本（强制）
- 目录：`docs/sql/` 或框架 `script/`，至少两个脚本：`01-schema.sql`（建表）、`02-seed.sql`（种子）。
- 脚本必须**幂等**、可重复执行（`CREATE TABLE IF NOT EXISTS`、`INSERT ... ON DUPLICATE KEY` 等）。
- 结构变更**只允许新增表**；`t_*` 冻结表**禁止 `ALTER`**；禁止在生产库执行 DDL。
- 种子必须含：`admin` 角色与账号、`health:*` 菜单与权限点、业务字典（见 `12` §4.1）。

## 14. 编码与路径
- 源码与文档统一 UTF-8；`.gitattributes` 规范换行。
- 代码内路径用 `/` 或 `java.nio.file.Path`；禁止硬编码盘符/绝对路径。
