# 12. 系统设置

> 文档编号：12
> 上级：[需求与开发规范总纲](./README.md)
> 关联：02、03、04、05
> 模块：`com.xinfei.system`（框架内置）+ `com.xinfei.job`

## 1. 用途
系统的组织、权限、字典参数、日志与定时任务维护。**直接使用 RuoYi-Vue-Plus 系统模块**，仅做必要的定制（业务字典、菜单与权限点、任务）。

## 2. 数据表
`sys_user`、`sys_role`、`sys_menu`、`sys_dept`、`sys_post`、`sys_user_role`、`sys_role_menu`、`sys_role_dept`、`sys_user_post`、`sys_dict_type`、`sys_dict_data`、`sys_config`、`sys_notice`、`sys_logininfor`、`sys_oper_log`、`sys_oss`、`sys_oss_config`、`sys_client`、`sys_job`、`sys_job_log`（见 `04` §1）。

## 3. 功能与接口（框架自带，`/system/**`）

| 功能 | 接口前缀 | 说明 |
|---|---|---|
| 用户管理 | `/system/user` | 增删改查、重置密码、分配角色/部门/岗位 |
| 角色管理 | `/system/role` | 增删改查、分配菜单权限、数据范围 |
| 菜单管理 | `/system/menu` | 目录/菜单/按钮，`perms` 权限标识 |
| 部门管理 | `/system/dept` | 树形组织，数据权限基础 |
| 岗位管理 | `/system/post` | 岗位维护 |
| 字典管理 | `/system/dict/type`、`/system/dict/data` | 业务字典 |
| 参数管理 | `/system/config` | 系统参数 |
| 通知公告 | `/system/notice` | 公告 |
| 操作日志 | `/system/operlog` | 操作审计 |
| 登录日志 | `/system/logininfor` | 登录审计 |
| 在线用户 | `/system/online` | 会话监控、踢下线 |
| 文件管理 | `/system/oss`、`/system/oss/config` | 文件记录与存储配置 |
| 客户端管理 | `/system/client` | 多端登录配置（见 `05`） |
| 定时任务 | `/monitor/job`（SnailJob 控制台） | 任务与日志 |
| 代码生成 | `/tool/gen` | 生成 CRUD 代码与页面 |

> 接口与权限沿用框架 `system:*`（如 `system:user:list`），无需重复定义。

## 4. 定制点

### 4.1 业务字典（`sys_dict_type` / `sys_dict_data`）
| 字典类型 | 用途 |
|---|---|
| `sys_user_sex` | 性别 |
| `health_member_sex` | 会员性别 |
| `health_order_status` | 订单状态（未到诊/已到诊） |
| `health_order_type` | 预约方式（电话预约/微信预约） |
| `health_report_abnormal` | 报告异常标记（正常/偏高/偏低/异常） |
| `health_question_type` | 题型 |
| `health_scale_type` | 量表类型（SCL-90/中医体质/自定义） |
| `health_plan_status` | 方案状态 |
| `health_item_type` | 干预条目类型 |
| `health_article_status` | 资讯状态 |

### 4.2 菜单与权限点
按 7 大模块建立目录/菜单/按钮，`perms` 见 `05` §3；通过 `sys_menu` 种子脚本下发。

### 4.3 定时任务（SnailJob）
| 任务 | 说明 | 频率 |
|---|---|---|
| 无效图片清理 | 清理 MinIO 中未被引用的套餐/资讯图片 | `0 0 3 * * ?`（每日 03:00，修正原 30 秒高频缺陷） |
| 报告解析重试（可选） | 解析失败的报告重试 | 按需 |

- 无效图片清理逻辑：Redis 集合 `health:img:uploaded`（全部已上传）与 `health:img:used`（已引用）求**差集** → 从 MinIO 删除 → 从 `health:img:uploaded` 移除；逐条 try/catch 记 ERROR，不中断整批。
- 任务用 SnailJob 注册（替代原 Quartz / `@Scheduled`）。

### 4.4 存储配置
默认 MinIO；可在 `/system/oss/config` 配置；业务上传统一走框架 OSS 抽象（见 `03` §10）。

## 5. 页面（后台）
框架自带系统管理页面（用户/角色/菜单/部门/岗位/字典/参数/公告/日志/在线用户/文件/客户端/定时任务）。

## 6. 验收
1. 用户/角色/菜单/部门/岗位/字典/参数 CRUD 生效。
2. 角色分配菜单后，对应账号菜单与按钮权限正确生效。
3. 操作日志、登录日志记录正确。
4. 在线用户可见并可踢下线。
5. 无效图片定时任务按每日 03:00 执行，已引用图片不误删。
6. 文件上传/下载经 OSS 配置生效。

## 7. 约束与禁止
- **优先使用框架能力，禁止重复造轮子**（用户/角色/菜单/部门/岗位/字典/参数/日志/在线用户/文件/客户端）。
- 修改框架核心代码须先获批（禁改清单见 `15` §5.2）；通过**扩展**而非直改框架类。
- 权限点**必须落在 `sys_menu`**（含按钮），禁止在代码里硬编码权限判断。
- 定时任务**必须用 SnailJob 注册**，禁止用 `@Scheduled` 做高频轮询（见原缺陷 9）。
- 固定值走 `sys_dict_*`，可调参数走 `sys_config`，**禁止散落魔法值/硬编码**。
- 存储配置走 `/system/oss/config`，**禁止**在代码写死桶名/密钥/Endpoint。
