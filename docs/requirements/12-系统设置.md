## 1. 用途与定位

本文件是全系统**配置资产的唯一登记表**：业务字典、系统参数、菜单与权限点、定时任务、文件存储与短信。

分工边界（不得越界）：

| 内容 | 唯一登记处 | 本文件的职责 |
|---|---|---|
| 业务口径与阈值数值 | `18` §3（A~H 组） | **只引用口径 ID**，不复述数值来源 |
| 字段的值域语义 | 各功能文档（`06`~`11`、`13`、`20`） | 收口为 `sys_dict_data` 可落库的键值 |
| 阈值/开关的承载位置 | **本文件 §4** | 定义 `config_key`、默认值、读取方 |
| 权限点 | 各功能文档接口清单 | 汇总为 `sys_menu` 种子与角色矩阵 |
| 错误码 | `03` §3 | 本模块自有块 `12001~12009` |

> 一句话：**`18` 说"是多少"，功能文档说"怎么用"，本文件说"配在哪、叫什么名、谁在读"。**

## 3. 业务字典全量清单

### 3.1 登记规则（强制）

1. 命名 `health_<域>_<语义>`，小写下划线；**禁止**与 §3.2 框架类型重名，插入前必须先 `select dict_type from sys_dict_type` 核对。
2. 值域**必须与功能文档逐字一致**：文档写 `已预约` 就存 `已预约`，不得自行换成 `1` 或英文；文档写码（如 B3 的 `1/2/3`）就存码，label 承载中文。判断依据看该字段的库类型——`char(1)`/`varchar(8)` 存码，`varchar(16)` 以上存中文串。
3. 每个 `dict_type` 的 `remark` 必须写「消费模块 + `18` 口径 ID」，反向可追溯。
4. 字典是**展示与录入的取值域**，不是判定逻辑：服务端判定分支一律读枚举常量或配置，**禁止**用 `dict_label` 字符串比较做业务判断（`03` §2）。
5. 新增状态值须先改功能文档 → 再改本表 → 再落种子，三者同一提交内完成。
6. `dict_code` 从 `100` 起顺序编号（现库 `max=38`），`dict_id` 从 `100` 起。
7. §3.3~§3.11 的表只规定**值域**，不规定 `dict_name` / `is_default` / `list_class` 三列，落地口径固定为：`dict_name` 取中文简名（如 `health_flow_status` → 就诊流程状态）；`is_default` **全表只有 `health_notify_way` 的「电话+系统推送」取 `Y`**（§3.6 明写「默认第三种」），其余一律 `N`；`list_class`/`css_class` 一律留 `NULL`，展示色由前端按值域自行映射。默认值取用**不得**依赖 `is_default`，一律走 §4 的 `sys_config` 或代码枚举。

### 5.5 启动自检（新增要求）

### 6.2 孤儿图片清理规则（唯一实现口径）

1. 取 `health:img:uploaded` 与 `health:img:used` 的**差集**。
2. 再按 `health:img:orphan_keep_days` 设保护期：上传时间距今 < 该天数的**跳过**（防「已上传、业务尚未保存」的正常竞态）。
3. 从 MinIO 删除 → 从 `health:img:uploaded` 移除该成员（**只删集合成员，不动 `health:img:used`**）。
4. 逐条 try/catch，异常记 ERROR 并继续；任务结束输出 `scanned/deleted/skipped/failed` 四计数。
5. 支持 `dryRun` 参数（默认 `true`）：只统计不删除，验证通过后再改 `false`；`dryRun` 非法值 → `12009`。

### 6.3 登记规范

- **禁止** `@Scheduled`、Quartz、`Thread`+`sleep` 轮询（`12` 原缺陷 9 与 `15` 红线）。

### 7.2 短信（框架现状 ≠ 本文档目标态，须分清）

| 路径 | 实测行为 | 结论 |
|---|---|---|
| `GET /resource/sms/code?phonenumber=` | 生成 4 位码 → 写 `global:captcha_codes:{phone}`，TTL **2 分钟**（`Constants.CAPTCHA_EXPIRATION`）→ 调 `SmsFactory.getSmsBlend("config1")` **真实发送**，失败即 `R.fail` | 框架**没有**开发环境模拟分支；`sms.blends` 密钥未填 ⇒ 该接口当前必然失败 |
| `05` §6 描述的 `health:sms:<scene>:{phone}`、5 分钟、开发环境日志模拟 | 属**业务侧待实现**目标态 | 属 `08` §5.3 下单验证码的实现范围，与框架登录短信**不是同一条链路** |

**本期口径**：

1. C 端短信登录与预约验证码走**业务侧自实现**（键 `health:sms:order:{phone}`，5 分钟，一次性），开发环境由 `SmsSender` 抽象在日志输出验证码；**不得**复用框架 `/resource/sms/code`。
2. 框架 `sys_client` 的 `app` 客户端 `grant_type` 已含 `sms`（实测），但该策略的**登录主体是 `sys_user`**，不能用于会员登录（`13` R2）；C 端一律走业务侧 `AppAuthController` + `MemberLoginService`。真实短信触达依赖厂商密钥，密钥未到位前**只有"送达"这一项未交付**，登录功能本身可在开发/测试环境从日志取码完成闭环（`13` R8、`05` §6）。
3. 发送必须带 `@RateLimiter`（框架实测为单号 60 秒 1 次），**禁止**绕过限流。

## 13. 约束与禁止

- **禁止重复造轮子**：用户/角色/菜单/部门/岗位/字典/参数/日志/在线用户/文件/客户端一律用框架能力；本模块新增接口只有 §8 两条。
- 修改框架核心类须先获批（`15` §5.2 禁改清单），通过扩展而非直改。
- 权限点**必须落 `sys_menu`**（含按钮），禁止代码硬编码权限判断；禁止只靠前端隐藏按钮实现权限。
- 字典与参数是**唯一取值来源**：禁止散落魔法值/硬编码枚举；判定逻辑禁止比较 `dict_label` 中文串。
- 阈值改动只改 §4 的 `sys_config`（或 `09` §2.6 的量表配置表），**禁止**为改一个阈值而发版；每次改动在 `17` §4 留痕。
- `sys_config` 的 `remark` 与字典 `remark` 不得留空——「谁在读、依据哪条口径」必须可反查。
- Redis 键（§4.4）与 `sys_config` 键是两个命名空间，**禁止**把 `health:img:*` 之类运行态键当参数配置登记或后台可编辑。
- **禁止**用 `sys_job`/Quartz/`@Scheduled` 表述或实现定时任务；调度只走 SnailJob（`sj_*`）。
- **禁止**在代码、文档、种子脚本写 MinIO/短信/DB 真实凭据；一律指路 `.env` 或 `sys_oss_config`。
- **禁止**在生产库执行 §11 脚本；种子脚本必须幂等且带精确 `WHERE`。
- 字典值域与功能文档冲突时，**以功能文档 + `18` 口径为准并回改本文件**，不得让实现期自行折中；`t_member.sex` 语义（§3.10 缺口 1）未确认前禁止用于任何禁忌判定。
