## 1. 底座选型（锁死）

本项目以 **RuoYi-Vue-Plus 5.6.2** 为唯一底座，在其上把包名整体重命名为 `com.xinfei`，并新增业务模块。

- 每个业务模块内部采用框架统一分层：`controller → service(接口+impl) → mapper → domain(Entity) / domain.vo / domain.bo`。
- 业务模块包：`com.xinfei.health.<module>`（`member`/`appointment`/`assessment`/`intervention`/`knowledge`/`enterprise`/`stat`）。
- **目标结构的业务模块共 7 个 `xfjk-health-*`，其中 `[未创建]` 6 个**（member / assessment / intervention / knowledge / enterprise / stat），`appointment` 已落地。**当前仓库中不存在的那 6 个须先获批准并同步更新本节**（见 `15` §0.4）。
- **`/app/**` C 端接口没有独立模块**：禁止新建 `xfjk-app` 后端模块或第二个启动入口。C 端接口按其**业务域**落在各自模块的 controller 里，与后台接口同模块、不同路由前缀——依据 `13` 的页面归属：档案/报告 → `xfjk-health-member`（P11）、评估 → `xfjk-health-assessment`（P16）、干预方案 → `xfjk-health-intervention`（P19）、资讯 → `xfjk-health-knowledge`（P21）、套餐与下单 → `xfjk-health-appointment`。跨域取数走对方 `service` 接口（§3.2），**不直连对方表**。

## 3. 依赖方向与跨模块协作（强制）

### 3.1 编译期依赖（单向、无环）

```
xfjk-admin → xfjk-modules/业务模块 → xfjk-common（及框架 system）
```

- `xfjk-common` 不依赖任何业务模块。
- 业务模块只依赖 `xfjk-common`（及必要的框架 `xfjk-system` 只读能力），**业务模块之间不建立编译期依赖**。
- **禁止**跨模块访问他人的 Mapper / Entity。
- **禁止循环依赖**（编译期与 Spring Bean 注入均不得成环）。

### 3.2 跨模块协作方式

业务天然存在跨模块读写（如预约下单需会员、干预方案需评估结果、统计需会员/订单）。统一按下列方式处理，**不得**用模块间编译依赖解决：

| 场景 | 协作方式 |
|---|---|
| 跨模块只读组装（如 C 端套餐详情三级结构） | 在各模块 `service` 接口暴露只读方法，调用方按接口注入；或由 `xfjk-admin` 应用层组合 |
| 跨模块引用校验 / 契约查询（删除套餐前校验订单等） | 被依赖模块 `service` 接口中提供"使用校验"方法，调用方按接口注入，**不直接读其表** |

- 业务模块对外只暴露 `service` 接口与只读 VO/DTO，**不暴露 Mapper/Entity**。
- 预定义跨模块接口（**命名固定，实现于数据拥有模块**；调用方不得另造同义名，否则 `06` §2.2 的分级交付与 `6105` 缺接口提示无法落地）：
  - `MemberQueryService`（`07` member 提供）：预约/评估/干预/统计读取会员。
  - `SetmealUsageService`（`08` appointment 提供）：套餐是否被订单引用（删除校验）；`06` 亦用它补齐套餐维度名称，**替代原 N+1 循环查名**（`15` §6 缺陷 5）。
  - `CheckGroupUsageService`（`08` appointment 提供）：检查组是否被套餐引用。
  - `OrderQueryService`（`08` appointment 提供）：统计读取订单/到诊（到诊判据固定 `t_order.orderStatus='已到诊'`，`06` R1，**不得**由 `flow_status` 反推）。
  - `AssessmentResultService`（`09` assessment 提供）：干预/统计读取评估结论与人群分类。
  - `ReportQueryService`（`07` member 提供，🆕 本期须新增）：统计读取报告主表/明细/科室小结/结论条目/危急值登记（`06` P02~P11、四层阳性、质控四率）。
  - `FollowupStatService`（`10` intervention 提供，🆕 本期须新增）：统计读取随访任务三态、触发率、达标率（阈值一律由 `10` 服务端计算，`06` §5.6 只引用不重述）。
  - `BatchStatService`（`20` 团检提供，🆕 本期须新增）：统计读取单位/批次/分组维度（`06` P12）。
- 上述接口未就绪时，统计侧**返回 `6105` 并在 `msg` 写明缺失接口名与所属文档**，禁止直查他模块表、禁止用空数据假装成功（`06` R8、`06` §9）。四张冻结表的**只读聚合例外**及其到期日见 `06` §2.2。

## 4. 分层规范

| 层 | 职责 | 禁止 |
|---|---|---|
| Controller | 参数校验、调用 Service、返回 `R`（分页 `TableDataInfo`） | 禁止写业务逻辑、禁止直接调 Mapper |
| Service | 业务逻辑、事务边界 | 禁止返回 Entity 给外部（转 VO/BO） |
| Mapper | 数据访问（MP + 自定义 XML） | 禁止写业务判断 |
| Entity | 与表 1:1 | 禁止带非表字段 |
| BO/VO | 入参/出参 | 禁止复用作 Entity |

## 5. 配置与环境
- `application.yml` + `application-dev.yml` / `application-prod.yml` 分层（框架约定）。
- 敏感项（DB/Redis/MinIO/短信）走环境变量或 `.env`，禁止硬编码（原项目缺陷 8，见 `16`）。
- 本地依赖用 `docker-compose.yml`（MySQL8 / Redis7 / MinIO）。
- **开发/测试中间件主机**：`192.168.20.130`（内网）。`application-dev.yml` 的 DB/Redis/MinIO 指向该机；生产环境另配，禁止复用。
- **接口加密**：`api-decrypt.enabled` 当前为 **`false`**（内网开发/测试限定，`CryptoFilter` 不注册，前端走明文 JSON）。**前端必须同步**：plus-ui 的 `.env.development` / `.env.production` 中 `VITE_APP_ENCRYPT` 上游默认 `true`，**本项目必须改为 `false`**，否则前端加密请求而后端不解密，`/auth/login` 直接 403。**对外部署前必须两侧同时恢复**，见 `17` 决策 23/47、`15` §5 DENY。
- **前端网关（工程化 SPA 形态）**：`xfjk-web/nginx.conf` 必须做两件事——① 把 `VITE_APP_BASE_API` 前缀（开发 `/dev-api`、生产 `/prod-api`）反代到 `xfjk-admin:8080` 并**剥掉该前缀**；② SPA history 模式回退 `try_files $uri $uri/ /index.html`，否则刷新子路由 404。旧的 `\.do$` 规则与单列 `location /auth/`（`17` 决策 24）**随静态页形态一并作废**——`/auth/**` 已落在 `/prod-api` 前缀之内。
- **其余 env 对齐项**：`VITE_APP_CLIENT_ID` 沿用现值（与 `sys_client` 一致，见 §5.1）；`VITE_APP_SSE=true` 与后端 `sse.enabled: true` / `sse.path: /resource/sse` 对应；`VITE_APP_TITLE` / `VITE_APP_LOGO_TITLE` 上游默认「RuoYi-Vue-Plus多租户管理系统」，须改为本项目名。逐条清单见 `17` 决策 47。
- 框架默认端口、上下文路径、Sa-Token 配置以框架约定为准。

> **本表不写任何口令值**。口令一律从「真值来源」列指向的文件/表读取，本机开发时另建 `.env`（不入库）承载；`03` §6 规定外部配置走环境变量。下表只登记**地址、端口、键名与机制**——这些是不会泄露的东西，也是最容易踩坑的东西。

| Redis | `192.168.20.130:6379`，db 0 | 同上 `spring.data.redis.password` |
| MinIO（S3 API） | `192.168.20.130:9005`，bucket `ruoyi`，accessKey `ruoyi` | 库表 `sys_oss_config`（`config_key=minio`，`status=0` 为默认启用）。**当前阻塞**：服务端不认该 key，上传报 `Access Key Id you provided does not exist`，待运维核对真实 key |
| 管理端登录 | 后台账号 `admin` | `sys_user.user_id=1`，口令哈希为 RuoYi 种子值（`$2a$` BCrypt，兼容原库，见 `16` §6）。明文口令**不入文档也不入库**，本机放 `.env` 或直接问运维 |
| 新增用户初始密码 | `sys_config` 行 `sys.user.initPassword` | 值经 `/system/config` 接口或库表读取（该键本身在 `12` §4.3 登记为框架内置项） |
| 客户端 ID | 请求头 `clientid` = `e5cd7e4891bf95d1d19206ce24a7b32e`，须与 token 内 `clientid` 一致 | `sys_client` + `xfjk-web/.env.{development,production}` 的 `VITE_APP_CLIENT_ID`（该值与 plus-ui 上游默认值相同，不用改）。**这是公开客户端标识，不是凭据**（`03` §9.3），可明文登记 |
| 验证码 | `captcha.enable` 默认 `true`（`type: math`）；本地调试用启动参数 `--captcha.enable=false` 临时关闭，**不改配置文件** | `xfjk-admin/src/main/resources/application.yml` |

- **MinIO 端口分工（易踩坑，已实测）**：`:9005` 是 MinIO S3 API；`:9000` 是本项目的 `xfjk-gateway` 容器，直接访问会返回 `{"code":401,"msg":"非法来源请求，请通过网关访问"}`。
- **`sys_oss_config.endpoint` 不能带协议头**：`OssClient.getEndpoint()` 会用 `is_https` 自行拼 `http://` / `https://`，写成 `http://ip:port` 会得到 `http://http://ip:port` 而无法解析。库里 `image` 那一行（未启用）仍是带协议头的历史种子值，照抄会复现该故障。
- **改 `sys_oss_config` 必须走接口，不要直接改库**：`OssFactory` 从 Redis 全局缓存 `sys_oss_config` 读取，缓存只在 `SysOssConfigServiceImpl` 增删改时写入，`/resource/oss/config` 没有刷新缓存端点；直接 UPDATE 后需重启或清该缓存键才生效。
- **尚未启动的可选服务**：SnailJob 服务端（`192.168.20.130:17888`，客户端 gRPC 心跳持续 `UNAVAILABLE`，不阻断业务）、Spring Boot Admin（`:9090`）。
