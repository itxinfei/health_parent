## 1. 底座选型（锁死）

本项目以 **RuoYi-Vue-Plus 5.6.2** 为唯一底座（`5.X` 分支，`Spring Boot 3.5 / JDK17`），在其上把包名整体重命名为 `com.xinfei`，并新增业务模块。

| 层级 | 选型 | 版本/说明 |
|---|---|---|
| 语言/运行时 | **JDK** | 17 |
| 主框架 | **Spring Boot** | 3.5.x |
| 构建 | **Maven 多模块** | 3.9+ |
| Web 容器 | **Undertow**（框架默认） | 基于 XNIO |
| 权限认证 | **Sa-Token + JWT 静态模式** | 非 Spring Security |
| ORM | **MyBatis-Plus** | 含分页/乐观锁/多租户等插件 |
| 连接池 | **HikariCP** | 框架默认 |
| SQL 监控 | **p6spy** | 完整 SQL 与耗时 |
| 多数据源 | **dynamic-datasource** | 单库为主，保留扩展能力 |
| 缓存/会话 | **Redis 7.x + Redisson** | Redisson 为客户端 |
| 数据库 | **MySQL** | 8.0 |
| 定时任务 | **SnailJob** | 替代原 Quartz / `@Scheduled` |
| 数据校验 | **Jakarta Validation** | 支持国际化 |
| 对象转换 | **MapStruct-Plus**（框架默认） | 简化 DTO/VO 映射 |
| 接口文档 | **SpringDoc + javadoc** | 零侵入 |
| Excel | **FastExcel**（原 EasyExcel） | 支持合并单元格、字典翻译 |
| 对象存储 | **MinIO / S3 协议** | 替代原 Qiniu/FastDFS |
| 短信 | **sms4j** | 多厂商融合，开发环境模拟 |
| 工具库 | **Hutool + Lombok** | — |
| 三方登录 | **JustAuth** | 预留（本期仅短信登录） |
| 监控 | **SpringBoot-Admin + Actuator**（框架默认） | 运维可选 |
| 前端-后台 | **plus-ui**：Vue3 + Vite + TS + Element Plus + Pinia + Vue Router + Axios | 官方配套 |
| 前端-C 端 | **Vue3 + Vant** | H5 |

**明确不启用**的框架能力：
- **多租户**（`ruoyi-common-tenant` / `@TenantLine`）：本系统面向单一健康管理机构。若框架默认启用，须在配置中关闭并移相关依赖，见 `17`。
- **工作流（WarmFlow）**：本期无审批流，移除 `ruoyi-workflow` 依赖。
- **MQ / 注册中心 / 网关**：不引入。

> **约束**：不得引入上表之外的第三方依赖；确需引入必须先说明理由并获批准（见 `15`）。

## 2. 包名与模块结构

- **包名根**：`com.xinfei`
- **groupId**：`com.xinfei`
- **artifactId 前缀**：`xfjk-`

将 RuoYi-Vue-Plus 的 `org.dromara` 与 `ruoyi-*` 按官方「项目路径修改」指南整体重命名后，结构如下（新增业务模块置于 `xfjk-modules` 下）：

```
xfjk-health-parent
├── xfjk-admin                     唯一启动/聚合模块（main、application.yml）
├── xfjk-common                    通用能力（多子模块，框架内置）
│   ├── xfjk-common-core           基础工具、常量、返回体 R / 分页、异常
│   ├── xfjk-common-web            全局异常、拦截器、CORS、XSS
│   ├── xfjk-common-mybatis        MP 配置、分页/字段填充、数据权限
│   ├── xfjk-common-redis          Redisson / Spring-Cache 封装
│   ├── xfjk-common-satoken        Sa-Token 集成、登录用户工具
│   ├── xfjk-common-security       权限校验（@SaCheckPermission 二次封装）
│   ├── xfjk-common-oss            文件存储（MinIO / S3）
│   ├── xfjk-common-excel          FastExcel 封装
│   ├── xfjk-common-sms            sms4j 集成（含开发模拟）
│   ├── xfjk-common-log            操作日志
│   ├── xfjk-common-doc            SpringDoc 配置
│   └── ...（翻译/脱敏/加解密/幂等/限流/SSE/WebSocket 等按需）
├── xfjk-modules                   业务模块聚合
│   ├── xfjk-system                系统管理（用户/角色/菜单/部门/岗位/字典/参数/日志等，框架内置）
│   ├── xfjk-generator             代码生成器（框架内置）
│   ├── xfjk-job                   定时任务（SnailJob 执行端，框架内置）
│   ├── xfjk-health-member         业务：会员管理 / 健康档案 / 报告
│   ├── xfjk-health-appointment    业务：预约管理（预约设置/订单/套餐/检查组/检查项）
│   ├── xfjk-health-assessment     业务：健康评估（问卷引擎/量表/建议/人群分类）
│   ├── xfjk-health-intervention   业务：健康干预（方案/模板/随访/运动库/膳食库）
│   ├── xfjk-health-knowledge      业务：知识库（疾病库/健康方案/资讯）
│   └── xfjk-health-stat           业务：工作台与统计分析
└── xfjk-extend                    扩展服务（可选）
    ├── xfjk-monitor-admin         SpringBoot-Admin 服务端
    └── xfjk-snailjob-server       SnailJob 服务端
```

- 每个业务模块内部采用框架统一分层：`controller → service(接口+impl) → mapper → domain(Entity) / domain.vo / domain.bo`。
- 业务模块包：`com.xinfei.health.<module>`（`member`/`appointment`/`assessment`/`intervention`/`knowledge`/`stat`）。

## 3. 依赖方向与跨模块协作（强制）

### 3.1 编译期依赖（单向、无环）

```
xfjk-admin → xfjk-modules/业务模块 → xfjk-common（及框架 system）
```

- `xfjk-common` 不依赖任何业务模块。
- 业务模块只依赖 `xfjk-common`（及必要的框架 `xfjk-system` 只读能力），**业务模块之间不建立编译期依赖**。
- **禁止**跨模块访问他人的 Mapper / Entity。
- **禁止循环依赖**（编译期与 Spring Bean 注入均不得成环）。

### 3.2 跨模块协作方式

业务天然存在跨模块读写（如预约下单需会员、干预方案需评估结果、统计需会员/订单）。统一按下列方式处理，**不得**用模块间编译依赖解决：

| 场景 | 协作方式 |
|---|---|
| 跨模块只读组装（如 C 端套餐详情三级结构） | 在各模块 `service` 接口暴露只读方法，调用方按接口注入；或由 `xfjk-admin` 应用层组合 |
| 跨模块引用校验 / 契约查询（删除套餐前校验订单等） | 被依赖模块 `service` 接口中提供"使用校验"方法，调用方按接口注入，**不直接读其表** |

- 业务模块对外只暴露 `service` 接口与只读 VO/DTO，**不暴露 Mapper/Entity**。
- 预定义跨模块接口（命名示意，实现于数据拥有模块）：
  - `MemberQueryService`（member 提供）：预约/评估/干预/统计读取会员。
  - `SetmealUsageService`（appointment 提供）：套餐是否被订单引用（删除校验）。
  - `CheckGroupUsageService`（appointment 提供）：检查组是否被套餐引用。
  - `OrderQueryService`（appointment 提供）：统计读取订单/到诊。
  - `AssessmentResultService`（assessment 提供）：干预/统计读取评估结论与人群分类。

## 4. 分层规范

| 层 | 职责 | 禁止 |
|---|---|---|
| Controller | 参数校验、调用 Service、返回 `R`（分页 `TableDataInfo`） | 禁止写业务逻辑、禁止直接调 Mapper |
| Service | 业务逻辑、事务边界 | 禁止返回 Entity 给外部（转 VO/BO） |
| Mapper | 数据访问（MP + 自定义 XML） | 禁止写业务判断 |
| Entity | 与表 1:1 | 禁止带非表字段 |
| BO/VO | 入参/出参 | 禁止复用作 Entity |

## 5. 配置与环境
- `application.yml` + `application-dev.yml` / `application-prod.yml` 分层（框架约定）。
- 敏感项（DB/Redis/MinIO/短信）走环境变量或 `.env`，禁止硬编码（原项目缺陷 8，见 `16`）。
- 本地依赖用 `docker-compose.yml`（MySQL8 / Redis7 / MinIO）。
- 框架默认端口、上下文路径、Sa-Token 配置以框架约定为准。

## 6. 版本与构建约束（精确，锁定）

| 项 | 取值 |
|---|---|
| JDK | **17** |
| RuoYi-Vue-Plus | **5.6.2**（`5.X` 分支） |
| Spring Boot | 随 5.6.2（3.5.x），**不得擅自升降** |
| Maven | 3.9+ |
| Node / pnpm | Node **18+** / **pnpm**（plus-ui 约定） |
| MySQL / Redis | 8.0 / 7.x |

- 后端各库版本**以 5.6.2 的 `pom.xml` 为准**；前端**以 plus-ui 的 `package.json` 为准**。
- **禁止**擅自升降版本、替换依赖、或修改锁文件做无关变更；确需变更先获批（见 `15` §2）。
- **重命名范围**：仓库/模块目录、artifactId、groupId、Java 包均改为 `xinfei` / `com.xinfei`；**框架核心类逻辑不改动**，仅改标识与包路径。
- 原项目名 `传智健康` / `health_parent` 仅作历史参照，新代码一律用 `xfjk-health-*`。

## 7. 验收（阶段 0）
1. 底座重命名后 `mvn clean install` 全模块编译通过。
2. `docker-compose up -d` 起 MySQL/Redis/MinIO，应用可连上。
3. 启动 `xfjk-admin`，Swagger/SpringDoc 可见接口分组。
4. 框架自带登录（`/system/auth/login` 或重命名后等价路径）可登录并返回 token。
5. 关闭多租户、移除工作流后，系统仍正常启动。
