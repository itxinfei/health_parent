## 1. 底座选型（锁死）

本项目以 **RuoYi-Vue-Plus 5.6.2** 为唯一底座，在其上把包名整体重命名为 `com.xinfei`，并新增业务模块。

> **底座之上的版本升级（已批准）**：本项目在 5.6.2 基础上自行升级了运行时与主框架至 **JDK 25 / Spring Boot 4.1.1（Spring Framework 7.0.9）**，并随之迁移到 **Jackson 3**（包名 `tools.jackson`）。这不是换底座，而是本项目对底座的受控升级，批准记录与回滚代价见 `17` 决策 20。升级后需自行验证上游兼容性，不得假定与官方 5.6.2 文档一致。

## 2. 包名与模块结构

- **包名根**：`com.xinfei`
- **groupId**：`com.xinfei`
- **artifactId 前缀**：`xfjk-`

将 RuoYi-Vue-Plus 的 `org.dromara` 与 `ruoyi-*` 按官方「项目路径修改」指南整体重命名后，结构如下（新增业务模块置于 `xfjk-modules` 下）：

```
xfjk-health-parent
├── xfjk-admin                     唯一启动/聚合模块（main、application.yml）
├── xfjk-common                    通用能力（多子模块，框架内置）
│   ├── xfjk-common-core           基础工具、常量、返回体 R / 分页、异常
│   ├── xfjk-common-web            全局异常、拦截器、CORS、XSS
│   ├── xfjk-common-mybatis        MP 配置、分页/字段填充、数据权限
│   ├── xfjk-common-redis          Redisson / Spring-Cache 封装
│   ├── xfjk-common-satoken        Sa-Token 集成、登录用户工具
│   ├── xfjk-common-security       权限校验（@SaCheckPermission 二次封装）
│   ├── xfjk-common-oss            文件存储（MinIO / S3）
│   ├── xfjk-common-excel          FastExcel 封装

├── xfjk-modules                   业务模块聚合
│   ├── xfjk-system                [已存在] 系统管理（用户/角色/菜单/部门/岗位/字典/参数/日志等，框架内置）
│   ├── xfjk-generator             [已存在] 代码生成器（框架内置）
│   ├── xfjk-job                   [已存在] 定时任务（SnailJob 执行端，框架内置）
│   ├── xfjk-demo                  [已存在] 框架演示模块（不参与业务，勿作为实现范例）
│   ├── xfjk-health-member         [未创建] 业务：会员管理 / 健康档案 / 报告
│   ├── xfjk-health-appointment    [未创建] 业务：预约管理（预约设置/订单/套餐/检查组/检查项）
│   ├── xfjk-health-assessment     [未创建] 业务：健康评估（问卷引擎/量表/建议/人群分类）
│   ├── xfjk-health-intervention   [未创建] 业务：健康干预（方案/模板/随访/运动库/膳食库）
│   ├── xfjk-health-knowledge      [未创建] 业务：知识库（疾病库/健康方案/资讯）
```

- 每个业务模块内部采用框架统一分层：`controller → service(接口+impl) → mapper → domain(Entity) / domain.vo / domain.bo`。
- 业务模块包：`com.xinfei.health.<module>`（`member`/`appointment`/`assessment`/`intervention`/`knowledge`/`stat`）。
- **[未创建] 的 6 个 `xfjk-health-*` 模块是目标结构，当前仓库中不存在**；新建模块须先获批准并同步更新本节（见 `15` §0.4）。

## 3. 依赖方向与跨模块协作（强制）

### 3.1 编译期依赖（单向、无环）

```
xfjk-admin → xfjk-modules/业务模块 → xfjk-common（及框架 system）
```

- `xfjk-common` 不依赖任何业务模块。
- 业务模块只依赖 `xfjk-common`（及必要的框架 `xfjk-system` 只读能力），**业务模块之间不建立编译期依赖**。
- **禁止**跨模块访问他人的 Mapper / Entity。
- **禁止循环依赖**（编译期与 Spring Bean 注入均不得成环）。

### 3.2 跨模块协作方式

业务天然存在跨模块读写（如预约下单需会员、干预方案需评估结果、统计需会员/订单）。统一按下列方式处理，**不得**用模块间编译依赖解决：

| 场景 | 协作方式 |
|---|---|
| 跨模块只读组装（如 C 端套餐详情三级结构） | 在各模块 `service` 接口暴露只读方法，调用方按接口注入；或由 `xfjk-admin` 应用层组合 |
| 跨模块引用校验 / 契约查询（删除套餐前校验订单等） | 被依赖模块 `service` 接口中提供"使用校验"方法，调用方按接口注入，**不直接读其表** |

- 业务模块对外只暴露 `service` 接口与只读 VO/DTO，**不暴露 Mapper/Entity**。
- 预定义跨模块接口（命名示意，实现于数据拥有模块）：
  - `MemberQueryService`（member 提供）：预约/评估/干预/统计读取会员。
  - `SetmealUsageService`（appointment 提供）：套餐是否被订单引用（删除校验）。
  - `CheckGroupUsageService`（appointment 提供）：检查组是否被套餐引用。
  - `OrderQueryService`（appointment 提供）：统计读取订单/到诊。
  - `AssessmentResultService`（assessment 提供）：干预/统计读取评估结论与人群分类。

## 4. 分层规范

| 层 | 职责 | 禁止 |
|---|---|---|
| Controller | 参数校验、调用 Service、返回 `R`（分页 `TableDataInfo`） | 禁止写业务逻辑、禁止直接调 Mapper |
| Service | 业务逻辑、事务边界 | 禁止返回 Entity 给外部（转 VO/BO） |
| Mapper | 数据访问（MP + 自定义 XML） | 禁止写业务判断 |
| Entity | 与表 1:1 | 禁止带非表字段 |
| BO/VO | 入参/出参 | 禁止复用作 Entity |

## 5. 配置与环境
- `application.yml` + `application-dev.yml` / `application-prod.yml` 分层（框架约定）。
- 敏感项（DB/Redis/MinIO/短信）走环境变量或 `.env`，禁止硬编码（原项目缺陷 8，见 `16`）。
- 本地依赖用 `docker-compose.yml`（MySQL8 / Redis7 / MinIO）。
- **开发/测试中间件主机**：`192.168.20.130`（内网）。`application-dev.yml` 的 DB/Redis/MinIO 指向该机；生产环境另配，禁止复用。
- **接口加密**：`api-decrypt.enabled` 当前为 **`false`**（内网开发/测试限定，`CryptoFilter` 不注册，静态前端走明文 JSON）。**对外部署前必须连同前端加密一起恢复**，见 `17` 决策 23、`15` §5 DENY。
- **前端网关**：`xfjk-web/nginx.conf` 除 `\.do$` 外必须代理 `/auth/`（登录/登出/验证码入口为 `/auth/**`，不以 `.do` 结尾），否则命中静态规则返回 404，见 `17` 决策 24。
- 框架默认端口、上下文路径、Sa-Token 配置以框架约定为准。

## 6. 版本与构建约束（精确，锁定）

> 本表是**全项目唯一版本真值来源**。`15` §2 若与本表不一致，以本表为准并报告冲突。

| 项 | 取值 | 来源 |
|---|---|---|
| JDK | **25** | `pom.xml` `<java.version>` |
| RuoYi-Vue-Plus | **5.6.2**（底座） | 上游基线 |
| Spring Boot | **4.1.1**（Spring Framework 7.0.9） | `pom.xml` `<spring-boot.version>`；本项目升级 |
| JSON | **Jackson 3**（`tools.jackson`） | 随 Spring Boot 4.1.1 |
| Sa-Token | **1.46.0** | `pom.xml` `<satoken.version>` |
| MyBatis-Plus | **3.5.17** | `pom.xml` `<mybatis-plus.version>` |
| Hutool / Lombok | **5.8.48 / 1.18.48** | `pom.xml`；依赖审计升级 |
| Maven | 3.9+ | 构建 |
| 项目产物版本 | `${revision}` = **5.6.2** | 本项目自身 artifact 版本号，**不代表底座或 Spring Boot 版本** |
| Node | **24+**（本机实测 v24.16.0） | `xfjk-app` 构建 |
| 包管理 | `xfjk-app` 用 **npm**（`package-lock.json`） | 无 pnpm 工程 |
| MySQL / Redis | 8.0 / 7.x | 中间件 |

- 后端各库版本**以本仓库根 `pom.xml` 的 `<properties>` 为准**；`xfjk-app` 以其 `package.json` 为准；`xfjk-web` 无 `package.json`，第三方库以 `plugins/`、`js/` 下 vendored 文件为准。
- **禁止**擅自升降版本、替换依赖、或修改锁文件做无关变更；确需变更先获批并**在 `17` 留决策记录**（见 `15` §2）。已批准的例外见 `17` 决策 20。
- **重命名范围**：仓库/模块目录、artifactId、groupId、Java 包均改为 `xfjk-` / `com.xinfei`；**框架核心类逻辑不改动**，仅改标识与包路径。
- 原项目名 `传智健康` / `health_parent` 仅作历史参照，新代码一律用 `xfjk-*`。

## 7. 验收（阶段 0）

前 5 项**已达成**（2026-10-22 实测）：
1. 底座重命名后 `mvn clean install` 全模块编译通过。
2. `docker-compose up -d` 起 MySQL/Redis/MinIO，应用可连上（开发环境指向 `192.168.20.130`）。
3. 启动 `xfjk-admin`，Swagger/SpringDoc 可见接口分组。
4. 框架登录入口为 **`POST /auth/login`**（JSON，带 `clientId` / `grantType`），可登录并返回 `access_token`；验证码入口 `GET /auth/code`。
5. 关闭多租户、移除工作流后，系统仍正常启动。
