# 05. 权限与认证

## 1. 权限模型（菜单 × 按钮）

采用 RuoYi-Vue-Plus 的 **RBAC + 菜单/按钮权限点**模型：

```
用户(sys_user) ──< 用户角色(sys_user_role) >── 角色(sys_role) ──< 角色菜单(sys_role_menu) >── 菜单(sys_menu)
```

- `sys_menu.menu_type`：`M` 目录 / `C` 菜单 / `F` 按钮。
- `sys_menu.perms`：权限标识字符串，格式 `模块:业务:动作`，如 `health:member:list`。
- 后端：`@SaCheckPermission("health:member:list")`、`@SaCheckRole("admin")`。
- 前端：`xfjk-web` 是 Vue 2 + Element-UI 静态页，**未注册 `v-hasPermi` / `v-hasRole` 指令**；按钮显隐当前由页面自行按登录态判断，**按权限点细粒度控制尚未实现**（`19` 与后续切片需补齐，方案见 §8 验收 3）。
- 菜单/权限**全部从库加载**，禁止硬编码。

## 2. 角色

| 角色 | role_key | 说明 | 数据范围 |
|---|---|---|---|
| 系统管理员 | `admin` | 全部菜单与按钮权限 + 系统设置 | 全部 |
| 健康管理师 | `health_manager` | 业务模块（会员/预约/评估/干预/知识库/统计） | 默认本部门，可按需扩展 |
| 会员 | —（不属于 `sys_role`） | C 端主体，见 `t_member`，非后台角色 | 仅本人 |

> 数据范围使用框架 `sys_role.data_scope`（全部/自定义/本部门/本部门及以下/仅本人），必要时在 Mapper 上加 `@DataColumn` 数据权限过滤。

## 4. 认证（Sa-Token）

- 认证框架：**Sa-Token**（`xfjk-common-satoken`），支持注解式登录/角色/权限校验。
- 登录用户上下文用框架 `LoginHelper` 获取当前 `userId`/`username`/`loginUser`。
- 请求头：`Authorization: Bearer <token>`（框架约定）。
- 密码校验：用编码器 `matches`（兼容原库 `$2a$` BCrypt，见 `17`）。
- 登录接口（**实测路径**）：后台 `POST /auth/login`（JSON，须带 `clientId` + `grantType: password`，响应返回 `access_token`）；图形验证码 `GET /auth/code`（返回 `captchaEnabled` / `img` base64 / `uuid`，算术题型，答案需计算且一次性、约 2 分钟过期）；登出 `POST /auth/logout`。C 端短信登录 `/app/auth/login` **尚未实现**。
- 前端须带 `ClientID` 请求头（`xfjk-web` 由 `js/api.js` 拦截器统一注入，值取 `js/config.js` 的 `clientId`，对应 `sys_client.client_id`，属公开标识非密钥）。

### 4.1 多端（客户端）

- 使用框架 **`sys_client`** 配置不同端（PC 后台、C 端 App/H5），分别控制 token 时效与登录方式。
- Sa-Token 使用不同 **loginType** 区分端（如 `pc`、`app`），避免 token 串端。
- C 端登录主体是 **会员（`t_member`）**，其登录标识存于 Sa-Token session，与后台 `sys_user` 区分。

### 4.2 会话与时效
- token 存 Redis（框架默认）；TTL 由 `sys_client` 配置（后台建议 30 分钟滑动续期，C 端可更长）。
- 支持**踢下线**：框架提供在线用户管理（`/system/online`）。
- 登出后 token 立即失效。

## 5. 接口访问控制

- **后台白名单**（无需认证）：登录、验证码、静态资源、SpringDoc/Swagger 路径。
- 后台其余 `/system/**`、`/health/**` 均需认证 + 对应权限。
- **C 端公开接口**：`/app/auth/login`、`/app/sms/**`（验证码）、`/app/setmeals/**`、`/app/articles/**`。
- **C 端需登录接口**：`/app/orders/**`（提交/查询本人）、`/app/reports/**`、`/app/assessments/**`、`/app/plans/**`、`/app/archives/**` —— 仅允许访问**本人**数据（按 `memberId` 过滤，越权返回 403）。
- 预约下单中**验证码校验**为业务层保障（见 `08`），登录态与业务校验并存。

## 6. 短信验证码
- **两条链路必须分清**（实测差异，详见 `12` §7.2）：
  - **框架链路**：`GET /resource/sms/code` 走 `SmsFactory.getSmsBlend("config1")` **真实发送**，键 `global:captcha_codes:{phone}`、TTL 2 分钟、4 位码、`@RateLimiter` 单号 60 秒 1 次。框架**没有**开发环境模拟分支，且 `sms.blends` 密钥当前为占位文案 ⇒ 该接口现状必然失败。
  - **业务链路（本期自实现）**：预约下单与 C 端登录验证码由业务侧发送器实现，键 `health:sms:<scene>:{phone}`、**5 分钟**过期、一次性（校验后即删），开发环境在日志输出验证码；**禁止**复用框架接口充当业务验证码。
- 场景 `scene`：`login`（登录）、`order`（预约）、`resetpwd`（找回密码，可选）。
- 验证码位数与有效期走 `sys_config` 键 `health:sms:code_length`、`health:sms:expire_minutes`（`12` §4.3），禁止写死。
- 短信厂商密钥未到位前，**C 端短信登录视为未交付**（`13`、`12` §12 验收）。

## 7. 安全与越权约束（强制）
- 写接口必须有 `@SaCheckPermission`；缺权限返回 403；禁止仅靠前端隐藏按钮做权限。
- C 端所有"本人数据"接口按 token 中 `memberId` 过滤；**禁止**信任前端传入的 `memberId`（防水平越权）。
- 敏感配置（DB/Redis/MinIO/短信密钥）走环境变量；**禁止**在日志/返回体打印密码、令牌、身份证、手机号全值（脱敏）。
- 验证码**一次性、5 分钟过期**；发送验证码接口需限流（`@RateLimiter`），禁止无限触发。
- 越权/遍历尝试记录日志并拒绝；登录失败计数与锁定按框架能力启用。

## 8. 验收
1. 管理员/健康管理师账号可登录并拿到 token；停用账号被拒（1002）。
2. 未带/失效 token 访问受保护接口返回 401；无权限返回 403。
3. 后台按钮按权限点显隐。`xfjk-web` 当前无 `v-hasPermi` 指令，需在切片中先定方案（注册 Vue 2 自定义指令读 `loginUser.permissions`，或页面 `v-if` 判断），**未实现前本项视为未达成**。
4. C 端验证码登录成功；验证码一次性且 5 分钟过期（2001）。
5. 登出后原 token 立即失效；踢下线生效。
6. C 端越权访问他人数据被拒（403）。
