## 1. 用途与范围

### 1.1 用途
体检中心的**主要收入来源是团体客户**（企业、机关、学校、事业单位）。团检模块负责把「一个单位的批量送检」组织成可执行的业务流水：
`单位台账 → 团检批次（任务计划书）→ 名单导入 → 自动分组 → 批次备单（生成订单）→ 到检与结果 → 团体报告`。

层级模型固定为四级（按 `18` H1）：**单位 → 团检批次 → 分组 → 套餐**；不同批次可关联同一单位。

### 1.2 本期做什么（对应 `18` H12）
1. 单位台账 + 单位多级部门树（`18` H4）。
2. 团检批次 / 任务计划书，一个单位可挂多份（`18` H5）。
3. 名单 Excel 导入，**逐行返回错误定位与原因**（`18` H2、H13~H15）。
4. 按性别 / 年龄段 / 婚姻状态自动分组，分组可人工复核调整（`18` H3）。
5. 批次备单：按分组套餐批量生成订单并扣减名额（复用 `08` §4.3 的原子扣减口径）。
6. 禁检与恢复（单位级 / 个人级）（`18` H9）。
7. 团体报告按单位查询、按部门/分组统计、批量生成（`18` H11）。
8. 回收站：单位、批次、名单误删可恢复（`18` H7）。
9. 从往年名单转入（匹配增减人员后批量再登记）（`18` H10）。

### 1.3 本期不做什么（对应 `18` H12、`17` 决策 26）
- **不做费用结算、公费限额、公费超额转自费、发票与单位对账**。
- 不做预约金/到店尾款（`18` §5.2 D-27）。
- 不做叫号与导检屏（D-28）。
- 到院加项与自身原因弃检**不做费用与退费处理**（`18` E12）。

> 与个人预约的关系：团检生成的记录仍是 `t_order` 行，**不得为团检新建订单表**（`04` §2.1 禁替代表）；批次归属通过 `t_health_order_ext.batch_id` 表达。

## 3. 状态机

### 3.1 批次状态（`t_health_batch.status`）
```
草稿 → 已确认 → 备单中 → 进行中 → 已完成
  ↘        ↘        ↘        ↘
            已取消（任一非「已完成」状态可进入，须填原因）
```
| 状态 | 进入条件 | 允许动作 | 禁止动作 |
|---|---|---|---|
| `草稿` | 新建 | 改单位/时间窗/标题/地点、导入名单、自动分组、删除 | 备单 |
| `已确认` | 手工确认，须已存在 ≥1 个分组且名单 ≥1 人 | 继续导入、重分组、按分组改套餐 | 改单位、改 `batch_no` |
| `备单中` | 触发备单 | 查询进度、对未成功行重试 | 改分组结构、删除名单 |
| `进行中` | 备单全部成功或有失败且人工放行 | 到诊登记（走 `08`）、恢复禁检、作废单个名单 | 改套餐结构 |
| `已完成` | 时间窗结束且无「未备单」名单 | 团体报告生成与导出 | 导入、分组、备单 |
| `已取消` | 手工取消并填原因 | 查询、恢复为 `草稿` | 备单 |

### 3.2 名单状态（`t_health_batch_member.status`）
`预登记 → 已分组 → 已备单 → 已作废`
- `预登记`：导入成功但未分组（按 `18` H6）。
- `已分组`：`examgroup_id` 与 `setmeal_id` 均非空。
- `已备单`：已生成 `t_order`，`order_id` 非空；此后到检环节状态由 `t_health_order_ext.flow_status` 承载（按 `18` C4，本表不重复记录）。
- `已作废`：单人作废，**不物理删除**，`total_count` 相应减少。
- 迁移约束：`已备单 → 已分组` 禁止（须先在 `08` 取消订单）；`已作废` 为终态，可「重新启用」回到 `预登记`。

### 3.3 与检查项级状态的关系
分组备单只负责生成订单，**不写项目级结果状态**；项目级状态（按 `18` C1）由 `07`/`08` 的录入环节维护，团检模块只读展示。

## 5. 关键口径落地

### 5.1 一号制（`18` F5、`17` 决策 41）
- 落位：`t_health_member_archive_no`（`04` §5.1），**唯一索引建在该新表上**，不动 `t_member`（`04` §2.1）。
- 生成规则：导入名单时按 `id_card` 精确匹配 `t_member`：
  1. 命中已有会员 → 取其档案号；
  2. 未命中 → 建 `t_member`（`fileNumber` 写入档案号，`regTime=now`，密码用默认口令策略见 `05`），并在 `t_health_member_archive_no` 建唯一行。
- **同一人不得因跨批次导入产生两个档案号**：校验点在档案号表，唯一冲突即复用。
- `t_member.fileNumber` 无唯一约束，故**任何写入路径都必须先查档案号表**，禁止「先写 `t_member` 再补关联」。

### 5.3 名额与防超卖
备单扣减必须复用 `08` §4.3 第 6 步的**条件更新**语句（`COALESCE` + 受影响行数判定），**禁止**先查后改；单日不足即该日该条失败回滚该条，不影响其他行（见 §8 事务边界）。

### 5.4 禁忌校验挂接点（`18` E13、`17` 决策 38）

### 6.2 逐行处理规则（`18` H2）
1. 一次读取上限 **2000 行**；超出返回 `20008`，提示拆分文件。
2. 表头不匹配 → 整体失败 `20009`，不逐行报错。
3. **逐行独立校验，失败行不落库**，成功行正常入库（不做「任一行失败全回滚」）；结果分三类返回：全部成功 / 部分成功 / 全部失败。

5. 同一文件内身份证重复：后出现者报错 `IM03`，前者保留。
6. 与批次现有名单重复（含回收站内未恢复的）：`IM03`。
7. 重名不做拦截，但**必须与性别匹配检查一并给出提示**：与既有同名不同身份证的名单标为「重名待核」写入 `remark`（`18` H2 的重名检查）。

## 7. 自动分组算法（`18` H3）

**输入**：批次内状态为 `预登记` 或 `已分组` 的名单 + 启用的 `t_health_group_rule`（按 `priority` 升序）。

**步骤**：
1. 若批次已有自动分组（`auto_flag=1`），先做**差异处理**：成员被移出组、空组删除、组名按新命中规则改名；人工分组（`auto_flag=0`）与其成员**不参与重算**。
2. 对每个成员按 `priority` 依次匹配规则：规则内各条件为 `AND`；条件值为 `NULL` 视为「不限」。
3. 命中第一条即停止；按 `group_name_tpl` 渲染组名，**同名分组复用**（同批次内 `name` 唯一）。
4. 复用分组时写入/更新 `t_health_examgroup_setmeal`：套餐不同则旧关联 `effect_flag=0`、新增 `effect_flag=1`。
5. 成员置 `已分组`，写 `examgroup_id`、`setmeal_id`、`rule_id`。
6. 无规则命中 → 保留 `预登记`，返回 `unmatched` 计数与身份证清单（前 50 条），**不静默丢弃**。
7. 校验 `拦截` 级禁忌（`18` E1/E2/E3/E8）：命中者从分组结果中剔除并计入 `forbidden` 列表，附可读原因。
8. 更新分组 `member_count` 与批次 `total_count`。

**接口响应**：`{ "groupCount": 4, "matched": 96, "unmatched": 3, "forbidden": 1, "groups": [...], "unmatchedIdCards": [...], "forbiddenList": [{"rowNo":7,"reason":"…"}] }`

**必须可复核**：自动分组后允许 §4.4 的人工移组；人工调整过的成员加 `remark` 标记「人工调整」，下次自动分组**不覆盖**其归属。

## 8. 批次备单（`18` H8）

### 8.1 前置条件
批次 `status ∈ {已确认, 进行中}`；待备单名单 ≥1；名单已分组（`examgroup_id` 非空）；分组有现行套餐。

### 8.2 日期摊派
1. 取批次 `start_date ~ end_date` 内的全部 `t_ordersetting` 行（按日剩余名额 = `COALESCE(number,0) - COALESCE(reservations,0)`）。
2. 预览接口按「先近后远」逐日分配，返回每日 `可备/已分配/缺口`。
3. 名额不足 → `20010`，并返回缺口日明细；允许用户改时间窗或减少人数后重试。

### 8.3 执行与事务边界
- **按成员逐条独立事务**（单条内部与 `08` §4.3 步骤 4~7 一致：识别/建档会员 → 插 `t_order` → 条件更新扣减名额 → 写 `t_health_order_ext`（含 `batch_id`、`flow_status`）→ 写 `t_health_order_log`）。
- 单条失败仅回滚该条，其余继续；失败原因记入进度接口。
- 全部成功 → 批次 `进行中`；有失败 → 保持 `备单中`，可重试点未成功行。
- 备单**不校验短信验证码**（`08` §4.3 第 1 步仅适用 C 端下单），禁止为此加开关。
- 幂等：`t_health_batch_member.order_id` 非空者跳过，重复调用不产生第二张订单。

### 8.4 批量调整项目（`18` H8）
备单前可对分组整体增删检查组：**不修改 `t_setmeal`**，而是把差异写入该分组的成员订单关联（本期实现方式：为分组维护「临时加减项」清单并在备单时落入 `t_health_order_ext`，由 `07` 结果录入按分组项目清单生成明细）。本期**不做**单人行级换套餐（记入 `17` 待确认）。

### 8.5 指引单/条码（`18` H8）
本期只做**数据准备**：提供 §4.6 与 `/health/batches/{id}/members` 的导出，打印模板（空表/指引单/条码/医技申请单）本期**不做**，登记为后续版本项（`18` §5.3）。
