# 11. 知识库

> 文档编号：11
> 上级：[需求与开发规范总纲](./README.md)
> 关联：03、04、05、07、08、09、10、12、13、18
> 模块：`com.xinfei.health.knowledge` / Maven `xfjk-health-knowledge`
> 本文按 `17` 决策 40 **重写**：知识库不是「疾病库 + 方案库 + 资讯」的内容堆，而是**总检工作台与建议产出的数据源**，必须含 `18` F9 要求的三套可维护字典。

## 1. 用途与范围

维护三套字典 + 三类内容，供上下游引用：

| 层 | 表 | 服务对象 | 口径 |
|---|---|---|---|
| 第一层 **结论词库** | `t_health_conclusion_dict` | `07` 总检结论（`t_health_report_conclusion.conclusion_dict_id`）、`08` 套餐默认正常结论 | `18` F7/F8/F9/D6/D9 |
| 第二层 **建议 / 处理意见模板库** | `t_health_advice_template` | `07` 报告建议段、`09` 评估建议、`10` 干预条目 | `18` F6/F9 |
| 第三层 **疾病与健教知识库** | `t_health_disease` + `t_health_conclusion_dict_ref` | 结论词的解释、健教文案、干预方案引用 | `18` F9 |
| 内容层 | `t_health_plan_library`、`t_health_article`、`t_health_article_category` | 方案复用、C 端健教资讯 | 原有能力保留 |
| 规则层 | `t_health_kb_rule` | `18` E10 等「登记但不进校验」的可配规则 | `17` 决策 29 |

## 2. 数据表

表清单以 `04` §5.5 为准（8 张）。通用约束同 `09` §2 引言。

### 2.1 `t_health_conclusion_dict`（结论词库，第一层）

| 列 | 类型 | 约束 | 说明 / 口径 |
|---|---|---|---|
| `id` | bigint | PK | 雪花 |
| `code` | varchar(64) | 非空，`uk_code` | 结论词编码，全局唯一 |
| `term` | varchar(128) | 非空 | **统一用词**（`18` F8），全机构只用这一个写法 |
| `conclusion_type` | varchar(16) | 非空 | `disease` 疾病诊断 / `positive` 阳性发现 / `other` 其他结论（`18` F7 三类固定） |
| `dept_scope` | varchar(255) | 可空 | 适用科室码逗号串，NULL = 全科室 |
| `abnormal_grade` | varchar(8) | 可空 | `A` 需立即干预 / `B` 需进一步检查或治疗（`18` D6）；正常结论为 NULL |
| `normal_flag` | tinyint | 非空默认 0 | 1 = 属「正常结论 / 正常处理意见」候选，供套餐与科室一键写入（`18` F9） |
| `major_positive_flag` | tinyint | 非空默认 0 | 1 = 重大阳性发现候选（`18` D7，联动 `07` §2 报告明细） |
| `merge_group_code` | varchar(32) | 可空 | **合并组码**（`18` D9）：同组异常指标合并为一条结论展示；`07` 的 `t_health_report_item.merge_group_id` / `t_health_report_conclusion.merge_group_id` 存的就是本列值 |
| `merge_target_code` | varchar(64) | 可空 | 合并后落地的结论词 `code`（如多个血脂异常 → 「脂肪肝」相关结论）；须指向同表存在的 `code`，否则 `11003` |
| `synonyms` | varchar(512) | 可空 | 同义词逗号串，用于录入检索与**新增查重**（F8） |
| `basis` | varchar(1024) | 可空 | 结论依据说明（报告五段之「依据」的可复用文案，`18` F6） |
| `icd_code` | varchar(32) | 可空 | 人工填写的疾病编码，本期不做标准库对接 |
| `health_education_id` | bigint | 可空 | 关联 `t_health_disease`，出结论时带健教入口 |
| `default_advice_id` | bigint | 可空 | 默认处理意见模板（`t_health_advice_template.id`），一键写入用（`18` F9） |
| `critical_note` | varchar(255) | 可空 | 危急提示语（仅文案，判定线在 `12` 配置，`18` D4） |
| `usage_count` | int | 非空默认 0 | 被引用次数冗余（`07` 结论条目落库时 +1，用于统计与停用保护） |
| `status` | varchar(16) | 非空默认 `published` | `draft` / `published` / `disabled` |
| `sort` / `remark` | — | 可空 | — |

索引：`uk_code`、`idx_term`、`idx_type_status`、`idx_merge_group`。

**查重规则（新增/改名时强制）**：`term` 归一化（去空格、全半角统一）后与库内 `term` + `synonyms` 逐项比对，命中即返回 `11001` 并回显已存在的 `code/term` —— 这是 `18` F8「同一机构异常结论用词须统一」的落地方式，禁止靠人工记忆。

`id`、`code` 唯一、`name`、`category`（同 `10` §2.1 字典）、`crowd_id` 可空、`disease_id` 可空、`content` text、`item_json` text（条目快照，结构同 `10` §2.2）、`status`、`usage_count`、`sort`、`remark`。与 `10` 的模板区别：**方案库是内容素材，模板是可下发结构**；`10` 建方案可从方案库复制为模板（不反向依赖）。

## 3. 引用与产出规则

### 3.1 结论词在总检中的用法（联动 `07`）

1. 总检医生从结论词库选取（按 `term/synonyms` 检索、按 `dept_scope` 过滤、按 `conclusion_type` 分列三类）。
2. 落库为 `t_health_report_conclusion`，`conclusion_dict_id` 必填；仅 `conclusion_type=other` 允许自由文本（`07` §5）。
3. 同 `merge_group_code` 的条目合并展示为一条（`18` D9）；`merge_target_code` 存在时以其为最终展示用词。
4. `abnormal_grade` 随结论词带出（`18` D6）；`major_positive_flag=1` 的词在总检界面命中时触发弹框（`18` D7，交互见 `07`/`13`）。
5. 停用保护：`usage_count > 0` 的结论词只可 `disabled` 不可删除（`11002`），历史报告仍按 ID 取词。

### 3.2 建议模板与变量占位

占位符白名单固定为：`{term}` 结论词、`{value}` 结果值、`{unit}` 单位、`{ref}` 参考区间、`{grade}` 异常分级、`{date}` 日期、`{dept}` 科室。渲染在服务端做，未识别的 `{}` 原样输出并记 WARN；**禁止**引入 SpEL/OGNL 等表达式求值（`15` 严禁项）。

套餐侧一键写入（`18` F9）：`08` §2.2/§2.4/§2.5 的 `t_health_checkitem_ext.default_conclusion_id`、`t_health_checkgroup_ext.default_conclusion_id`、`t_health_setmeal_ext.default_conclusion_id` / `default_advice_id` 引用**本模块表的 `id`**（结论词 `normal_flag=1`、模板 `normal_flag=1`），到检后批量写入正常项目的小结与处理意见；`08` 侧下拉数据来自 `GET /health/conclusions/normal` 与 `GET /health/advicetemplates/normal`。

### 3.3 资讯与健教联动

- C 端资讯列表只出 `status=published`；`offline/draft` 一律不可见。
- 结论词带 `health_education_id` 时，`07` 报告详情页给出「了解更多」入口（不内嵌医学建议正文，避免报告被改写）。
- 浏览量 `views` 自增用原子更新（`UPDATE ... SET views = views + 1`），可异步。

## 7. 错误码（`MMNNN` 五位块，`03` §3 同步）

| code | 含义 |
|---|---|

## 10. 约束与禁止

- **三套字典缺一不算知识库**（`18` F9）：结论词库、建议/处理意见模板库、疾病与健教知识库必须同时存在且互相引用，禁止只做疾病库交付。
- 结论用词**必须统一**（`18` F8）：同一含义只允许一个 `term`，靠 §2.1 查重保证，禁止靠人工约定或代码内映射表。
- 结论类型固定三值 `disease/positive/other`（`18` F7），异常分级固定 `A/B`（`18` D6），禁止自造档位。
- 合并关系用 `merge_group_code` + `merge_target_code` 承载，**禁止新建合并组表**（不在 `04` §5.5 登记范围内）。
- 知识内容（疾病、健教、建议）**必须有出处**（`source_ref`），禁止无源编造医学表述（`18` §7 禁止无源口径）。
- `t_health_kb_rule` **只提示不拦截**（`17` 决策 29）；把拦截级规则塞进本表以绕过 `08` 禁忌校验，属违规（`11005`）。
- 建议模板禁止表达式求值（SpEL/OGNL/`${}`），只允许白名单占位符（`11007`）。
- 被引用的字典条目**禁止物理删除**，一律 `disabled`（`11002`）；历史报告/评估按 ID 取词。
- 富文本必须走框架 XSS 能力；C 端公开接口禁止返回草稿/下架内容、字典内部编码与分级。
- `t_health_disease` 为疾病**单一数据源**，禁止另建疾病表或在 `10` 复制一份（`04` §5.5）。
- 知识库模块不得读写冻结表（`04` §2.1）；对报告/套餐/评估只暴露 ID 与文案，不改写它们的判定结果（判定唯一在服务端，`18` D1~D3）。
