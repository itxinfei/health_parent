# 11. 知识库

> 文档编号：11
> 上级：[需求与开发规范总纲](./README.md)
> 关联：03、04、05、10、13、18
> 模块：`com.xinfei.health.knowledge`

## 1. 用途
沉淀与运营健康知识内容：**疾病库、健康方案库、健康资讯**，支撑健康干预（方案引用疾病/方案）与 C 端健康教育。

## 2. 数据表
见 `04` §5.5：`t_health_disease`、`t_health_plan_library`、`t_health_article`、`t_health_article_category`。

### 2.1 关键列
| 表 | 关键列 |
|---|---|
| disease | `id`、`code`、`name`、`category`、`symptom`、`cause`、`diagnosis`、`treatment`、`prevention`、`advice`、`status` |
| plan_library | `id`、`code`、`name`、`category`、`crowd_id`、`content`、`status` |
| article | `id`、`title`、`category_id`、`cover`、`summary`、`content`、`author`、`publish_time`、`status`(草稿/发布)、`views`、`top` |
| article_category | `id`、`name`、`parent_id`、`sort`、`status` |

- 新增表均含审计字段与 `del_flag`（见 `04` §4）。
- `t_health_disease` 为**单一数据源**，同时服务「健康干预-疾病库」与「知识库-疾病库」，不重复建表。

## 4. 业务规则
- 疾病 `code` 唯一；被干预模板/方案引用时，删除前校验（存在引用则禁止或提示）。
- 资讯：仅「发布」状态对 C 端可见；草稿不可见；支持置顶与分类。
- 资讯详情浏览自增 `views`（可异步，避免热点行锁）。
- 富文本内容应做 XSS 过滤（框架 `xfjk-common-web` 的 XSS 处理，见 `03`）。
- 封面图存 MinIO（目录 `article/`）。

## 5. 页面（后台）
疾病库、健康方案库、资讯列表/编辑、资讯分类；C 端资讯列表/详情。

## 6. 验收
1. 疾病库 CRUD 生效；被引用时删除被校验。
2. 方案库 CRUD 生效，可被干预模块引用。
3. 资讯 CRUD、发布/下架、分类、置顶生效；草稿对 C 端不可见。
4. C 端资讯列表/详情正常展示，浏览量自增。
5. 富文本经 XSS 过滤，无脚本注入。

## 7. 约束与禁止
- 资讯富文本**必须 XSS 过滤**（框架能力），禁止直接输出未过滤 HTML。
- 仅「发布」状态对 C 端可见；**禁止**草稿/未发布内容泄漏。
- **禁止另建重复的疾病表**：`t_health_disease` 为单一数据源（干预与知识库共用）。
- 疾病被干预模板/方案引用时，删除前须校验，禁止直接删除导致悬空引用。
- 浏览量自增用**原子更新**（或异步），避免热点行锁。
- 封面图走 OSS 抽象；公开接口禁止返回未发布/敏感内容。
