# 14. 非功能需求与阶段验收

> 文档编号：14
> 上级：[需求与开发规范总纲](./README.md)
> 关联：02、15

## 1. 非功能需求

| 项 | 要求 |
|---|---|
| 性能 | 列表接口 P95 < 500ms；分页走索引；避免 N+1（批量查询代替循环单查）；大数据量报表异步或缓存 |
| 安全 | 见 `03` 第 6 节；写接口鉴权 + 权限点；输入校验；XSS/SQL 注入防护；C 端越权防护 |
| 事务 | 涉及多表写必须 `@Transactional`；只读操作不加写事务 |
| 并发 | 预约名额扣减必须条件更新防超卖（见 `08` §4.3） |
| 一致性 | 关联差异更新（检查组/套餐）不得"只删不增"；删除前引用校验 |
| 可维护 | 分层清晰、依赖方向正确、无跨模块 Mapper 访问、命名达意 |
| 可测试 | Service 层单元测试；关键接口集成测试；核心业务（预约、删除校验、评估计分）必须有测试 |
| 兼容 | 原库 `t_*` 冻结；原库 BCrypt 密码可直接登录；废弃 RBAC 表由 `sys_*` 承接（见 `16`） |
| 国际化 | 校验提示与通用文案走框架 i18n（本期默认中文） |
| 审计 | 写操作记录操作日志；登录记录登录日志（框架能力） |

## 2. 阶段划分与验收

> 按**业务闭环**推进，C 端页随对应功能一并交付。

| 阶段 | 内容 | 验收（DoD 摘要） |
|---|---|---|
| 0 | 工程底座 | RuoYi-Vue-Plus 重命名后 `mvn install` 通过；Docker Compose 起 MySQL/Redis/MinIO；启动后 SpringDoc 可见；框架登录可用返回 token；多租户关闭、工作流移除 |
| 1 | 系统与权限 | 用户/角色/菜单/部门/岗位/字典/参数 CRUD；角色分配菜单后菜单与按钮权限生效；`health:*` 权限点种子下发 |
| 2 | 预约-基础数据 | 检查项/检查组/套餐 CRUD；关联差异更新正确；删除校验 3001/3002/4001；套餐图片上传 |
| 3 | 预约-预约与到诊 | 预约设置（Excel 导入不重置 `reservations`、日历）；预约列表；到诊登记；C 端下单全流程；**并发不超卖** |
| 4 | 会员管理 | 会员档案（基础/动态/病史）CRUD；报告上传与结果解析（异常标记）；会员统计 |
| 5 | 健康评估 | 问卷/题库/量表 CRUD；SCL-90 与中医体质计分正确；评估记录/建议/人群分类；C 端作答 |
| 6 | 健康干预 | 模板/方案/随访/运动库/膳食库；由模板生成方案；C 端查看方案 |
| 7 | 知识库 | 疾病库/方案库/资讯 CRUD；资讯发布；C 端资讯与疾病查看 |
| 8 | 统计分析 | 工作台（8 卡 + 6 待办 + 3 趋势图，`06` §4）；P01~P12 报表按 `06` §2.2 **L0~L5 分级交付**（L2~L5 依赖前序阶段，未就绪返回 `6105` 而非空数据）；四层阳性分列、检出率、工作量六口径、质控四率；**到诊统计非 0**（`06` §2.4 缺陷 1~4 关闭）；Excel 导出（`06` §10，含 `api.js` blob 分支）；`t_health_stat_snapshot` 建表与幂等（`06` §2.5） |
| 9 | 团检管理 | `20` 四级（单位→批次→名单→分组/备单）全流程；名单导入上限 `health:import:member_max_rows`；自动分组与禁检拦截；团体报告（检出率口径引用 `06` §5.3）；错误码 `20001~20013` 全绿 |
| 10 | 收尾 | 无效图片定时任务（SnailJob）；C 端全量页面联调；原缺陷修正清单全绿（见 `15` §6） |

单个功能点的 DoD 见 `15-AI开发约束` 第 3 节。阶段验收通过即该阶段完成。
