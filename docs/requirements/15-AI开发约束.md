# 15. AI 开发约束与执行协议

> 文档编号：15
> 上级：[需求与开发规范总纲](./README.md)
> 适用：**所有 AI 编码代理**。**动手前必读；本文件优先级高于 AI 的默认习惯。**
> 定位：本文件是项目的**硬约束层**。功能文档（`06`~`13`）说明"做什么"，本文件规定"**怎么做、不能怎么做、如何证明做对了**"。

---

## 0. AI 执行协议（流程约束）

### 0.1 读取顺序
开工前按需读取：`README`（索引）→ `02`（架构/版本）→ `03`（规范）→ **本文件** → 目标模块文档（`04` + `06`~`13`）；改造原系统时加读 `16`。**只读与当前任务相关的文档**，避免上下文浪费。

### 0.2 任务前置（Definition of Ready）
- 明确：目标模块、对应文档编号、涉及的表/接口、验收标准。
- 若上述任一项在文档中找不到 → **先提问**，禁止开猜（见 §0.3）。

### 0.3 歧义与未知处理（禁止编造）
- 文档未定义的表/列/接口/错误码/依赖/命令/配置项：**不得臆造**。
- 处理顺序：① 查本目录文档 → ② 查现有代码 → ③ 查官方文档（RuoYi-Vue-Plus / Spring Boot / Sa-Token / MyBatis-Plus / Vue 2 / Element-UI 2 / uni-app 官方）→ ④ 仍无则**停下来提问**。
- **注意**：本项目底座已升级到 Spring Boot 4.1.1 / JDK 25，**上游官方文档默认版本与本仓库实际版本不一致**（官方 5.6.2 配套 SB 3.5 / JDK 17）。照抄官方示例前必须先确认其 API 在 SB 4.1.1 / Jackson 3 下仍然存在。
- **严禁**编造：接口路径、字段名、错误码、Maven/npm 坐标与版本、命令行参数、配置键。

### 0.4 范围控制
- **只实现文档已定义的内容**；不得实现"文档外"的功能/表/列/接口/依赖/页面。
- 需要扩展（新表、新列、新依赖、新接口）→ 先说明理由并获批准，再实现。

### 0.5 上下文与进度（跨会话）
- 上下文达到窗口 **80%** 时停止推进并提醒，总结进度；**不默默截断**。
- 每完成一个功能点/阶段，汇报：**已完成 / 进行中 / 阻塞 / 下一步**。

### 0.6 变更与文件
- 只改**与任务相关**的文件；**不得改动未点名的文件**；**不得顺手重构**无关代码。
- **禁改清单**（§5.2）中的对象，未获批准一律不动。

### 0.7 停止条件（触发即停）
- 触碰 §5 禁止清单；或对**生产环境（公网 IP）**的写操作；或需求歧义未澄清；或需修改禁改清单对象而未获批。

## 1. 铁律（必须 / 禁止）

1. **先方案后编码**：涉及 3 个以上文件改动，先输出中文实施方案（改哪些文件、改什么、为什么），等确认再动手。
2. **不得变更技术栈与版本**（见 `02` §1、本文 §2）；不得引入未列出的依赖。
3. **遵守依赖方向**（见 `02` §3）；不得跨模块调 Mapper/Entity；业务模块只依赖 `xfjk-common`。
4. **权限用 Sa-Token 注解**（`@SaCheckPermission`）；Controller 不写业务逻辑；Service 不返回 Entity 给外部。
5. **禁止硬编码**密钥/密码/地址；一律走配置与环境变量。
6. **禁止字符串拼接 SQL**；用参数绑定 / `LambdaQueryWrapper`。
7. **禁止 `System.out.println`**；用 SLF4J（`@Slf4j`）。
8. **禁止吞异常**；异常统一走 `ServiceException` + 全局处理，且必须记录日志。
9. **日期用 `java.time`**，禁止 `java.util.Date`（Entity 映射除外）。
10. **冻结表不得改结构**（`t_*` 不加列）；新增表遵循 `04` §4 约定。
11. **跨模块只经 `service` 接口**，禁止跨模块读表/实体。
12. **禁止编造**（见 §0.3）。
13. **每完成一个功能点**：必须编译通过 + 给出验证命令与实际输出（见 §4.2）。
14. 默认**不生成 md 文档**（本需求目录除外）；不合格的文件不提交。
15. **不自动 git add/commit/push**；需要时先 `git diff` 给用户确认（message 用中文 `type: 简述`）。
16. 遇到标记为 deny / 生产环境的写操作**立即停止**，不绕过、不"换个方式试试"。
17. **保留开源协议**：底座 RuoYi-Vue-Plus 为 **MIT**，须保留其 LICENSE/协议文件与版权声明。

## 2. 技术栈与版本（精确，锁定）

> **版本真值以 `02` §6 为准**，本表为其摘录。两者不一致时按 `02` §6 执行并报告冲突。

| 项 | 版本/说明 |
|---|---|
| JDK | **25**（语言特性可用至 25；禁止引入 `javax.*` 旧包，Jakarta EE 用 `jakarta.*`） |
| RuoYi-Vue-Plus | **5.6.2**（底座）；本项目已自行升级运行时与主框架，批准记录见 `17` 决策 20 |
| Spring Boot | **4.1.1**（Spring Framework 7.0.9）；**不得擅自升降** |
| JSON | **Jackson 3**，包名 `tools.jackson`（**不是** `com.fasterxml.jackson`）；自研代码统一用 `tools.jackson` |
| Sa-Token | **1.46.0** |
| MyBatis-Plus | **3.5.17** |
| Hutool / Lombok | **5.8.48 / 1.18.48** |
| 构建 | Maven 3.9+；单仓库多模块 |
| 数据库 | MySQL 8.0 |
| Redis | 7.x |
| 其它后端库 | **以本仓库根 `pom.xml` 的 `<properties>` 为准**，不得擅自升降 |
| 后台前端 | `xfjk-web`：Vue **2** + Element-UI **2**（UMD vendored）+ axios 0.18.0 + echarts，**无构建**（`17` 决策 21） |
| C 端前端 | `xfjk-app`：uniapp 3 + Vue **3** + TS + vite（`17` 决策 22） |
| Node / 包管理 | Node **24+**（本机实测 v24.16.0）、**npm** 11+（`xfjk-app` 用 `package-lock.json`；无 pnpm 工程） |

> 规则：升级/替换任何版本或依赖 → 必须先说明理由并获批准，且**在 `17` 补决策记录**。禁止修改锁文件（`pom.xml` 版本段、`package-lock.json`）做无关变更。
>
> **已批准的例外**：`17` 决策 20（JDK 17→25、Spring Boot 3.5→4.1.1、Jackson 2→3、Lombok/Hutool 依赖审计升级）。除该记录所列，版本铁律仍然有效。
>
> **前端版本铁律的实际含义**：`xfjk-web` 无 `package.json`，第三方库是 `js/`、`plugins/` 下的 vendored 文件——**换库等于替换文件**，同样需要批准；且因无构建，Vue 2 / Element-UI 2 的 API 边界是硬约束（用不了 Vue 3 / Element Plus 语法与组件）。

## 3. 代码生成 Checklist（每段代码逐条自检）

- [ ] 包路径在 `com.xinfei.*` 正确位置（业务在 `com.xinfei.health.<module>`），依赖方向正确。
- [ ] Entity 映射正确：冻结表字段名与列名一致且有 `@TableField`；新表含审计/逻辑删除字段。
- [ ] 入参用 Jakarta Validation 注解校验。
- [ ] 返回统一 `R` / `TableDataInfo`；业务错误走 `ServiceException` + 错误码表（见 `03` §3）。
- [ ] 分页用框架 `PageQuery` + `TableDataInfo`。
- [ ] 写接口标注 `@SaCheckPermission`；写操作按需 `@Log`、`@RepeatSubmit`。
- [ ] 多表写操作有 `@Transactional`。
- [ ] 删除/关联更新有引用校验与差异更新（不得"只删不增"）。
- [ ] 无硬编码、无 `System.out`、无 `java.util.Date`、无字符串拼 SQL。
- [ ] 有 SLF4J 关键日志（禁打印敏感信息）。
- [ ] 新增接口有 SpringDoc 注解（`@Tag`/`@Operation`）。
- [ ] 符合 `03` §11 代码风格与静态检查要求。
- [ ] 关键业务有测试并通过（见 `03` §12）。

## 4. Definition of Done 与验收证据

### 4.1 DoD（每个功能点）
1. 实现符合对应功能文档（`06`~`13`）与本文件约束。
2. `mvn clean install` 通过；前端 `pnpm build`（或类型检查）通过。
3. 关键业务有单元/集成测试且通过。
4. 给出验证方式与**实际输出**（见 §4.2）。
5. 无违反 §1 铁律与 §5 禁止清单。

### 4.2 验收证据协议（强制）
- 每个功能点必须给出：**验证命令 + 实际执行输出 + 预期结果**，三者一致才算完成。
- **禁止**只写"应该可以了""大概没问题"等口头结论；无证据视为未完成。
- 接口级验证给：Swagger 截图描述或可复制的 `curl` + 返回体。

## 5. 禁止清单（DENY，可用于机检）

### 5.1 通用禁止（grep 关键词）
下列模式出现即视为违规：

| 类别 | 禁止 | 说明 |
|---|---|---|
| 日志 | `System.out`、`System.err`、`printStackTrace` | 用 SLF4J |
| 日期 | `java.util.Date`、`new Date()` | 用 `java.time` |
| SQL | 字符串拼接 `"select" + ...`、`${}` 注入 | 用参数绑定 |
| 密钥 | 明文 `password=`、`secret=`、`AK/SK`、私钥 | 走环境变量 |
| 依赖 | 未批准的第三方坐标、未批准版本 | 见 §2 |
| 注释 | 作为沟通手段的 `// TODO: 问用户` 之类 | 直接沟通 |
| 表 | 对 `t_*` 冻结表 `ALTER/ADD COLUMN` | 见 §5.2 |
| JSON | 自研代码新增 `com.fasterxml.jackson.*` 导入 | 本项目已迁 Jackson 3，统一用 `tools.jackson.*`；仅框架 vendored 兼容层可保留旧包 |
| 前端 | 在 `xfjk-web` 使用 Vue 3 / Element Plus 语法或组件（`<script setup>`、`el-empty` 等） | `xfjk-web` 是 Vue 2 + Element-UI 2，无构建，见 `03` §9.1 |
| 接口 | 新增 `.do` 结尾的后端接口 | `.do` 是原系统存量，新接口一律 `/health/**`、`/app/**`、`/system/**` |

### 5.2 禁改清单（未经批准不得改动）
- **冻结表** `t_checkitem`、`t_checkgroup`、`t_checkgroup_checkitem`、`t_setmeal`、`t_setmeal_checkgroup`、`t_ordersetting`、`t_order`、`t_member` 的结构。
- **框架核心**：`xfjk-common/*`、`xfjk-system/*` 的核心类（仅在必要时通过**扩展**而非直改）。
- 未点名的文件/目录；`docs/requirements/` 之外的需求文档。
- 底座 LICENSE/协议文件（只能保留，不能删除）。

### 5.3 安全红线（触碰即停）
- 禁止 `rm -rf` 非临时目录；禁止无 `WHERE` 的 `UPDATE/DELETE/TRUNCATE/DROP`。
- 禁止 `git push --force`、`git reset --hard`、`git clean -fd`（除非明确要求）。
- 禁止对生产环境（公网 IP）做任何写操作；开发/测试内网环境可改。
- 禁止提交密钥、令牌、`.env` 真实值。
- 禁止对生产数据库执行 DDL。
- **`api-decrypt.enabled` 当前为 `false`**（内网开发/测试限定，见 `17` 决策 23）：**对外部署前必须恢复为 `true` 并连同前端加密实现一起交付**，否则 `@ApiEncrypt` 接口以明文暴露。禁止把"关闭加密"当作常态写进生产配置或 `application-prod.yml`。

### 5.4 机检脚本（强制使用）
- 脚本：`scripts/check-deny.ps1`（对应本节 §5.1 规则，可机检）。
- 时机：**每次提交前必须运行**，ERROR 未清零不得提交。
- 命令与预期：

```powershell
# 全量检查（默认排除旧 health_* 模块与 docs）
powershell -ExecutionPolicy Bypass -File .\scripts\check-deny.ps1
# 预期：无违规则输出「DENY 检查通过：未发现违规。」且退出码 0；有 ERROR 退出码 1

# 需要审查旧模块时
powershell -ExecutionPolicy Bypass -File .\scripts\check-deny.ps1 -IncludeLegacy
```

> 覆盖规则：`System.out/err`、`printStackTrace`、`java.util.Date`、字符串拼 SQL、MyBatis XML `${}`、明文密钥/私钥、冻结表 `ALTER`、`@PreAuthorize`、`@Scheduled`、`org.dromara` 残留、`ruoyi-` artifact 残留、前端 `console.*`、`@CrossOrigin`。脚本自身与 `docs/` 默认不扫描。

## 6. 原项目缺陷修正清单（重写必须修正，作为验收项）

| # | 原缺陷 | 修正要求 |
|---|---|---|
| 1 | C 端登录 Cookie 遍历空指针 | 用 Sa-Token 会话，不手工遍历 Cookie |
| 2 | 登录验证码用 `expire` 而非 `set` | 验证码写入 Redis 用 `set` + TTL（一次性） |
| 3 | 预约设置更新把 `reservations` 重置为 0 | 仅更新 `number`，不得重置 `reservations`（见 `08`） |
| 4 | 到诊统计用 `到诊`（与实际 `已到诊` 不符，恒 0） | 统一用 `已到诊`（见 `06`） |
| 5 | 检查组/套餐更新"只删不增" | 关联差异更新（删旧 + 插新，见 `08`） |
| 6 | 预约逻辑 `member1` 空指针、用未落库 id | 先落库再关联，判空（见 `08` §4.3） |
| 7 | 分页判空用 `!= ""` | 用标准分页与判空 |
| 8 | 环境配置硬编码（zk/mysql/redis） | 走配置与环境变量（见 `02` §5） |
| 9 | 定时任务每 30 秒频次过高 | 改为每日 03:00（见 `12`） |

> 原系统详细对照与迁移见 `16`。

## 7. 违规处理
- 发现违反 §1/§5：**立即停止**，回退到违规前状态，说明原因后重新出方案。
- 禁止"带病继续"或"下次再改"。
- 每次违规须在进度汇报中记录（问题 → 原因 → 修正）。
