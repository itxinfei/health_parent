## 0. AI 执行协议（流程约束）

### 0.1 读取顺序
开工前按需读取：`README`（索引）→ `02`（架构/版本）→ `03`（规范）→ **本文件** → 目标模块文档（`04` + `06`~`13`、`20`）；改造原系统时加读 `16`。**只读与当前任务相关的文档**，避免上下文浪费。

- 找阈值/分母/公式：**先查 `18` §3 口径登记表**，功能文档只告诉怎么用（`README` 冲突裁决四层分工）。
- 找页面承载与路由/`component`：**只认 `19` §3.2 一张表**（`12` §5.1 的 `component` 值由它派生）。
- 文档之间冲突：按 `README`「冲突裁决」表取权威文档，**并报告冲突**，不要自行调和成第三种口径。

### 0.2 任务前置（Definition of Ready）
- 明确：目标模块、对应文档编号、涉及的表/接口、验收标准。
- 上述任一项在文档中找不到 → **走 §0.3 阶梯自行判定，不要先提问**；阶梯走完仍无解才按 §0.3.2 的 4 类例外打断人类。

### 0.3 确定性缺口解决阶梯（禁止编造，也禁止一有疑问就问）

目标：**技术问题零拍板**。文档没写的技术细节，按下面固定顺序自行确定，并把采用的依据一句话写进完成汇报；只有 §0.3.2 的四类才允许打断人类。

**阶梯（逐级下降级，前一级有答案就停）**：

1. **本目录文档**：`18` §3（阈值/公式/分母唯一数值来源）→ 功能文档 `04`~`13`/`20` → `03`（规范/错误码/前缀）→ `12`（配置键/字典/菜单）→ `02`（架构/版本）→ `19`（页面承载）→ `05`（权限）。
2. **`legacy/` 原实现**：业务规则、字段语义、边界条件的可查证来源。先读同名能力的旧 Controller/Service（`com.pangzhao`），**只取语义，禁止复制代码**（`16`）。⚠ 2026-10-23 起 `legacy/` 已取消 git 跟踪、只在负责人本机存在——会话环境里找不到该目录时，向人类索取相关文件片段，**不得**据此判定「无旧实现可查」直接跳到第 5 级。
3. **本仓库既有同类模块样板**：新业务模块一律对齐 `xfjk-modules/xfjk-health-appointment` 的分层、命名、`R`/`TableDataInfo`、错误码、差异更新与引用校验写法（`17` 决策 25 指定它为样板）。**有样板就照样板，不自造第三种写法。**
4. **框架与前端基座源码**：读仓库内的真实代码，不读记忆——后端 `xfjk-common/**`、`xfjk-system/**`；前端 `xfjk-web/src/utils/request.ts`、`plugins/**`、`directive/**`、`store/modules/**`。**以本地文件与本地依赖版本为真值**（`xfjk-web/node_modules`、根 `pom.xml` `<properties>`）。
5. **默认口径表（§0.3.1）**：仍无解时按表取确定性默认，并在汇报中标注「文档未定义，按 §0.3.1 默认 X 实现」。
6. **停下来问**：仅当落入 §0.3.2 四类，或默认口径表明确标注「须提问」。

**注意**：本项目底座已升级到 Spring Boot 4.1.1 / JDK 25，**上游官方文档默认版本与本仓库实际版本不一致**（官方 5.6.2 配套 SB 3.5 / JDK 17）。照抄官方示例前必须先确认其 API 在 SB 4.1.1 / Jackson 3 下仍然存在。
前端同理：plus-ui 官方示例可能来自更高的 6.x 线或不同 Element Plus 小版本，**以本地 `node_modules` 实际版本为准**（版本对锁 `v5.6.2-v2.6.2`，`17` 决策 47），不要照抄上游 master 写法。

**仍然严禁编造**（阶梯第 4/5 步是"查"和"取默认"，不是"造"）：接口路径、字段名、错误码、Maven/npm 坐标与版本、命令行参数、配置键——凡 §2 与 `03`/`04`/`12` 已登记而**没查**就写，视为违规。

#### 0.3.2 只允许这四类打断人类（其余技术问题自行判定）

1. **业务口径**：阈值、判定标准、计数分母、医学结论边界——`18` §3 未登记或登记表内部冲突。
2. **数据暴露范围**：脱敏级别、某角色能否看明文/身份证/医疗结论。
3. **范围扩张**：新增依赖（Maven/npm）、改版本、建新表新列、改 §5.2 禁改清单对象、动 `application*.yml` / `Dockerfile` / `nginx.conf` / CI 配置。
4. **破坏性或共享环境**：生产库、公网 IP、删数据、`ALTER` 冻结表、任何不可逆操作。

提问格式要求：一句话问题 + 已查过哪几级阶梯 + 候选选项（推荐项在前）+ 不决定的后果。**不许问"你想要什么风格"这类开放题。**

### 0.4 范围控制
- **只实现文档已定义的内容**；不得实现"文档外"的功能/表/列/接口/依赖/页面。
- 需要扩展（新表、新列、新依赖、新接口）→ 先说明理由并获批准，再实现（属 §0.3.2 第 3 类）。
- **范围歧义的默认取向**：文档同时支持"做宽/做窄"时**取窄**（少做一个接口、少写一列），并在汇报里写明"取了窄口径，宽口径需追加"。少做可补，多做要拆。

### 0.5 上下文与进度（跨会话）
- 上下文达到窗口 **80%** 时停止推进并提醒，总结进度；**不默默截断**。
- 每完成一个功能点/阶段，汇报：**已完成 / 进行中 / 阻塞 / 下一步**。
- 汇报还必须列出：**本次用过 §0.3 阶梯的哪几级、取了哪些 §0.3.1 默认值**。取过的默认值若与你的预期不符，由这条清单提供回退入口；**默认值本身不需要事先批准**。

### 0.6 变更与文件
- 只改**与任务相关**的文件；**不得改动未点名的文件**；**不得顺手重构**无关代码。
- **禁改清单**（§5.2）中的对象，未获批准一律不动。

### 0.7 停止条件（触发即停）
- 触碰 §5 禁止清单；或对**生产环境（公网 IP）**的写操作；或落入 **§0.3.2 四类**且未完成阶梯前 5 级；或需修改禁改清单对象而未获批。
- **不构成停止条件**：文档没写的技术细节（走 §0.3 阶梯）、默认口径表已给出取值的项（直接实现并登记）。

## 1. 铁律（必须 / 禁止）

1. **先方案后编码**：涉及 3 个以上文件改动，先输出中文实施方案（改哪些文件、改什么、为什么），等确认再动手。
2. **不得变更技术栈与版本**（见 `02` §1、本文 §2）；不得引入未列出的依赖。
3. **遵守依赖方向**（见 `02` §3）；不得跨模块调 Mapper/Entity；业务模块只依赖 `xfjk-common`。
4. **权限用 Sa-Token 注解**（`@SaCheckPermission`）；Controller 不写业务逻辑；Service 不返回 Entity 给外部。
5. **禁止硬编码**密钥/密码/地址；一律走配置与环境变量。
6. **禁止字符串拼接 SQL**；用参数绑定 / `LambdaQueryWrapper`。
7. **禁止 `System.out.println`**；用 SLF4J（`@Slf4j`）。
8. **禁止吞异常**；异常统一走 `ServiceException` + 全局处理，且必须记录日志。
9. **日期用 `java.time`**，禁止 `java.util.Date`（Entity 映射除外）。
10. **冻结表不得改结构**（`t_*` 不加列）；新增表遵循 `04` §4 约定。
11. **跨模块只经 `service` 接口**，禁止跨模块读表/实体。
12. **技术问题零拍板**：禁止编造，也禁止一有疑问就问——缺口按 §0.3 阶梯逐级自行确定；只有 §0.3.2 的四类才允许打断人类。
13. **每完成一个功能点**：必须编译通过 + 给出验证命令与实际输出（见 §4.2）。
14. 默认**不生成 md 文档**（本需求目录除外）；不合格的文件不提交。
15. **不自动 git add/commit/push**；需要时先 `git diff` 给用户确认（message 用中文 `type: 简述`）。
16. 遇到标记为 deny / 生产环境的写操作**立即停止**，不绕过、不"换个方式试试"。
17. **保留开源协议**：底座 RuoYi-Vue-Plus 为 **MIT**，须保留其 LICENSE/协议文件与版权声明。

### 5.3 安全红线（触碰即停）
- 禁止 `rm -rf` 非临时目录；禁止无 `WHERE` 的 `UPDATE/DELETE/TRUNCATE/DROP`。
- 禁止 `git push --force`、`git reset --hard`、`git clean -fd`（除非明确要求）。
- 禁止对生产环境（公网 IP）做任何写操作；开发/测试内网环境可改。
- 禁止提交密钥、令牌、`.env` 真实值。
- 禁止对生产数据库执行 DDL。
- **`api-decrypt.enabled` 当前为 `false`**（内网开发/测试限定，见 `17` 决策 23）：**对外部署前必须恢复为 `true` 并连同前端加密实现一起交付**，否则 `@ApiEncrypt` 接口以明文暴露。禁止把"关闭加密"当作常态写进生产配置或 `application-prod.yml`。

### 5.4 机检脚本（强制使用）
- 脚本：`scripts/check-deny.ps1`（对应 §5.1 的 DENY-001~020）。**2026-10-23 起该目录已取消 git 跟踪（仅本机存在）**，脚本本体与被扫的业务页仍须照常跑；AI 会话执行时用相对仓库根路径 `.\scripts\check-deny.ps1`，本机缺文件即视为环境未就绪，向人类索取而不是跳过 gate。
- 时机：**每次提交前必须运行**，**默认范围内** ERROR 未清零不得提交。

**默认范围 = 业务代码白名单**（这是 gate 可满足的前提，不要改动这个默认）：

| 扫 | 不扫 |
|---|---|
| `xfjk-modules/xfjk-health-*/**` | `xfjk-common/**`、`xfjk-system/**`、`xfjk-modules/{demo,generator,job,system}/**`、`xfjk-admin/**`、`xfjk-extend/**` —— 框架 vendored 代码 |
| `xfjk-web/{src,mock}/**`、`xfjk-app/{src,mock}/**` | `xfjk-web/pages/**`、`xfjk-web/js/**`、`xfjk-web/plugins/**` —— 待废弃静态页存量（`.html` 本就不在扫描扩展名内，`js/` 下的 vendored 库会恒报 `console.*`） |
| 各级 `.env*` 文件（DENY-020 用）、`docs/sql/**`（DENY-008 用） | `legacy/**`（`-IncludeLegacy` 才扫）、`target/`、`node_modules/`、`dist/`、`*.min.js` |

```powershell
# 日常：业务代码范围（提交前必跑）
powershell -ExecutionPolicy Bypass -File .\scripts\check-deny.ps1
# 预期：输出「DENY 检查通过：未发现违规。」或仅 WARN，退出码 0；有 ERROR 退出码 1

# 全量审计（含框架 vendored 代码，已知存在大量历史违规，仅供整改参考）
powershell -ExecutionPolicy Bypass -File .\scripts\check-deny.ps1 -IncludeFramework

# 连 legacy/ 一起看
powershell -ExecutionPolicy Bypass -File .\scripts\check-deny.ps1 -IncludeLegacy -IncludeFramework -Format json
```

> **为什么默认不扫框架代码（实测，2026-10-22）**：全量档当前有 **84 处 ERROR**，全部来自 vendored 代码——启动横幅 `System.out.println`（`XinfeiApplication`、`MonitorAdminApplication`）、`BaseEntity`/`SysUser` 等实体用 `java.util.Date`（铁律 9 本就豁免 Entity 映射）、`DateUtils`/`InjectionMetaObjectHandler` 里的日期与元数据写法。若把这些纳入默认 gate，则 §5.4「ERROR 清零」**永远不可能满足**，AI 每次都会面对 84 条无法行动的报错，只能忽略 gate 或去重构禁改清单里的框架代码（违反 §5.2）——两条都是坏结果。所以范围分层，不是放松约束。
>
> 当前**默认档实测**：ERROR 0、WARN 3（`xfjk-app/src/App.vue` 三条 `console.log`，uniapp 生命周期示例代码）。
>
> 覆盖规则：`System.out/err`、`printStackTrace`、`java.util.Date`、字符串拼 SQL、MyBatis XML `${}`、明文密钥/私钥、冻结表 `ALTER`、`@PreAuthorize`、`@Scheduled`、`org.dromara` 残留、`ruoyi-` artifact 残留、前端 `console.*`、`@CrossOrigin`、**`v-hasRole` 单数、自建 axios、Vue2/Element-UI2 形态、业务页硬编码色值、`.do` 调用、`VITE_APP_ENCRYPT=true`**。脚本自身不扫描。
>
> **新增规则的方式（供后续扩展，不要另造第二个脚本）**：规则是 `$rules` 数组里的一条哈希表，含 `Scope`（路径必须匹配）与 `NotScope`（路径不得匹配）两个可选字段——前端规则一律用它们锁定到 `xfjk-web|app` 的 `src`，避免误报静态页存量；`docs/sql` 通过 `$alwaysScan` 突破 `docs` 的整体排除。
