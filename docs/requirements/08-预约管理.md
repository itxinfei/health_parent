# 08. 预约管理

> 文档编号：08
> 上级：[需求与开发规范总纲](./README.md)
> 关联：03、04、05、07、13、16
> 模块：`com.xinfei.health.appointment`

## 1. 用途
体检预约全流程与体检**基础数据**维护：检查项、检查组、套餐、预约设置、预约订单/到诊登记。

## 2. 数据表
`t_checkitem`、`t_checkgroup`、`t_checkgroup_checkitem`、`t_setmeal`、`t_setmeal_checkgroup`、`t_ordersetting`、`t_order`（均为原库冻结表）；新增 `t_health_order_log`（订单流水）。（字段见 `04` §2；列名含驼峰须 `@TableField`。）

## 4. 业务规则

### 4.1 基础数据
- 检查项 `code` 唯一；**删除检查项**校验 `t_checkgroup_checkitem` 引用，被引用返回 `3001`。
- 检查组 `code` 唯一；**编辑**差异更新关联（删除不在新 `checkItemIds` 的旧关联、补插新增，**修正"只删不增"缺陷**）；**删除**经 `CheckGroupUsageService` 校验是否被套餐引用，被引用返回 `3002`；否则先删 `t_checkgroup_checkitem` 再删组。
- 套餐 `code` 唯一；**编辑**差异更新 `t_setmeal_checkgroup`；**删除**经 `SetmealUsageService` 校验是否存在订单，存在返回 `4001`；否则先删 `t_setmeal_checkgroup` 再删套餐。
- 套餐图片：上传 MinIO（目录 `setmeal/`），成功记 Redis `health:img:uploaded`；套餐保存时记 `health:img:used`。孤儿图清理见 `12`。

### 4.2 预约设置
- Excel 格式：`[日期, 可预约人数]`。
- **导入**：仅导入**晚于今天**的日期；已存在则更新 `number`，**不重置 `reservations`**；不存在则插入且 `reservations=0`。
- **单日设置**：仅更新 `number`，**不得重置 `reservations`**（修正原缺陷）。
- 日历查询返回当月每天的 `date/number/reservations`。

### 4.3 预约下单（C 端，事务）
1. 校验短信验证码（`health:sms:order:{phone}`，一次性）。
2. 校验日期已设置且 `COALESCE(number,0) - COALESCE(reservations,0) > 0`，否则 `5001`/`5002`（`reservations` 可能为 NULL）。
3. 判断重复预约（同会员/同日/同套餐），重复返回 `5003`。
4. 会员按**姓名 + 身份证**识别，未匹配到则注册（`regTime=now`）。
5. 插入订单（`orderType=微信预约`，`orderStatus=未到诊`）。
6. `reservations` +1：**条件更新** —— `UPDATE t_ordersetting SET reservations = COALESCE(reservations,0)+1 WHERE orderDate=? AND COALESCE(number,0)-COALESCE(reservations,0) > 0`；受影响行数为 0 则回滚返回 `5002`（**防超卖**）。
7. 写 `t_health_order_log`（动作=预约）。
8. 全流程一个事务。

### 4.4 到诊登记
- 订单状态置 `已到诊`；写 `t_health_order_log`（动作=到诊）。

## 5. 页面（后台）
检查项/检查组/套餐管理页、预约设置（日历 + Excel 导入）、预约列表（筛选 + 到诊登记）、订单/套餐导出。

## 6. 验收
1. 检查项/检查组/套餐 CRUD 生效；编辑关联差异更新正确；删除校验 3001/3002/4001 生效。
2. 套餐图片上传成功且可访问；`health:img:uploaded/used` 正确。
3. Excel 导入不重置已有 `reservations`；日历查询正确。
4. C 端下单全流程可完成并落库；重复返回 5003、满额返回 5002、未设置返回 5001。
5. **并发压测不超卖**（预约总数 ≤ number）。
6. 到诊登记后状态为「已到诊」，订单流水正确。

## 7. 约束与禁止
- 冻结表**禁止 `ALTER`/加列**；仅允许新增 `t_health_order_log`。
- 预约下单必须**同一事务 + 条件更新**扣减，**禁止**"先查后改"的非原子扣减（防超卖）。
- 必须用 `COALESCE` 处理 `reservations` 为 NULL 的情况。
- 关联更新必须**差异更新**（删旧 + 插新），**禁止**"只删不增"或"只增不删"。
- 删除检查项/检查组/套餐**必须先做引用校验**（3001/3002/4001）。
- 图片走 OSS 抽象；Redis 集合键固定为 `health:img:uploaded` / `health:img:used`，禁止另起键名。
- 状态/方式取值固定：`已到诊`/`未到诊`、`电话预约`/`微信预约`，禁止自造取值。
- C 端下单校验验证码为业务强制步骤，**禁止**绕过。
