## 1. 用途
体检预约全流程与体检**基础数据**维护：检查项、检查组、套餐、预约设置、预约订单与到检流转。
本模块是 8 张冻结表唯一的业务写入入口，也是 `20` 团检备单的落库终点。

`t_checkitem`、`t_checkgroup`、`t_checkgroup_checkitem`、`t_setmeal`、`t_setmeal_checkgroup`、`t_ordersetting`、`t_order`。
硬约束见 `04` §2.1；列名含驼峰须 `@TableField`，主键 `Integer` + `IdType.AUTO`（`03` §2.1）。

## 3. 状态机

### 3.1 项目级状态（`18` C1，落 `t_health_report_item.item_status`，本模块只读展示）
`未检` / `已检` / `待查` / `弃检` / `延期`；后台可改（改动作走 §2.8 留痕）。
- 弃检必须生成弃检说明；延期项必须逐项录入「延期」，否则报告不得显示「未见异常」（`18` C2，由 `07` 校验拦截）。

### 3.2 报告级流程状态（`18` C4，落 `t_health_order_ext.flow_status`）
```
已预约 → 已到诊 → 检查中 → 待总检 → 已总检 → 报告已打印 → 报告已发放
   ↘ 已取消        ↘ 延期（可恢复回 已到诊/检查中）
```
| 状态 | 进入动作 | 允许 | 禁止 |
|---|---|---|---|
| `已预约` | C 端下单（§5.3）/ 团检备单（`20` §8） | 到诊登记、取消、改期 | 录入结果 |
| `已到诊` | 到诊登记，生成 `exam_no`、建 `t_health_report` 草稿 | 科室录入、改项目、延期、取消 | 直接发放报告 |
| `检查中` | 任一项结果首次落库 | 科室录入、弃检、复查、重置 | 改 `setmeal_id`（须走加减项留痕） |
| `待总检` | 全部项目均非 `未检`/`待查`（`18` C1） | 总检提交、异常打回（回 `检查中`，`18` C9） | 科室改结果（`18` C9 禁止） |
| `已总检` | 总检提交且三级质控满足（`18` C8） | 打印、总检撤销（回 `待总检`，须填原因） | 未撤销前科室改结果 |
| `报告已打印` | 打印动作 | 发放 | 改结论 |
| `报告已发放` | 发放动作 | 只读、复查申请 | 任何结果与结论修改 |
| `已取消` | 取消动作，必填 `cancel_reason` | 恢复为 `已预约`（当日名额须回退） | 录入结果 |
| `延期` | 延期动作，必填 `postpone_until` | 延期恢复（`18` C6） | 备单/发放 |

- 每次迁移写 `t_health_order_log`；非法迁移返回 `5006`。
- 三级质控时限（科室当日 / 主检 3 日内 / 终审签发）按 `18` C8 执行，责任人记录在 `07` 的报告表。

### 3.3 与 `t_order.orderStatus` 的关系
`t_order.orderStatus` 继续按原语义读写（`未到诊` / `已到诊`），**不得改写为流程状态**；两者一致性规则：`orderStatus=已到诊` 当且仅当 `flow_status ∈ {已到诊, 检查中, 待总检, 已总检, 报告已打印, 报告已发放}`。`04` §8 验收 4 要求此映射可核对。

## 5. 业务规则

### 5.1 基础数据（**已实现，口径不变**）
- 检查项 `code` 唯一；删除校验 `t_checkgroup_checkitem` 引用 → `3001`。
- 检查组 `code` 唯一；编辑**差异更新**关联（修正原「只删不增」缺陷）；删除校验被套餐引用 → `3002`。校验落在 `CheckgroupServiceImpl`（`17` §1.2 第 7 条）。
- 套餐 `code` 唯一；编辑差异更新 `t_setmeal_checkgroup`；删除校验存在订单 → `4001`。校验落在 `SetmealServiceImpl`。
- 套餐图片走框架 OSS，`t_setmeal.img` 存 `sys_oss.oss_id`；Redis 键固定 `health:img:uploaded` / `health:img:used`。

### 5.2 预约设置
- 导入：**仅导入晚于今天的日期**；已存在则更新 `number`，**不重置 `reservations`**；不存在则插入且 `reservations=0`。
- 单日设置：仅更新 `number`，**不得重置 `reservations`**。
- 月历返回当月每天 `date/number/reservations/remain`（`remain` 由 `COALESCE` 计算）。
- 删除某日设置：存在订单则 `5008`。

### 5.3 预约下单（C 端，事务；口径不变）
1. 校验短信验证码（`health:sms:order:{phone}`，一次性）。**预检与消费分两处**：`POST /app/orders/check-code`（`13` §6 R5）**只比对不删除**，供前端提前反馈；最终**校验并删除**必须发生在本步骤所在的下单事务内，`POST /app/orders` 入参**必带 `smsCode`**。禁止在两处都删码（删一次后第二次校验必然失败）。
2. 校验日期已设置且剩余名额 > 0，否则 `5001`/`5002`（`reservations` 可空须 `COALESCE`）。
3. 重复预约（同会员/同日/同套餐）→ `5003`。
4. 会员按 **姓名 + 身份证** 识别，未匹配则注册（`regTime=now`）。
5. **禁忌校验**（本期新增）：按 §2.7 规则命中 `action=0` → `5009` 并返回 `tip_text`（`18` E13）；`action=1` → 放行并把须知写入订单备注与返回体；`action=2` → 返回「建议延后补检」并由用户确认，确认后放行且记 `postpone` 候选。
6. 插入订单（`orderType=微信预约`，`orderStatus=未到诊`）+ `t_health_order_ext`（`flow_status=已预约`）。
7. `reservations` +1：**条件更新** —— `UPDATE t_ordersetting SET reservations = COALESCE(reservations,0)+1 WHERE orderDate=? AND COALESCE(number,0)-COALESCE(reservations,0) > 0`；受影响行数 0 则回滚 → `5002`（**防超卖**）。
8. 写 `t_health_order_log`（动作=预约）。
9. 全流程一个事务。

> 步骤 5 必须在步骤 7 之前：禁忌拦截不得占用名额。

### 5.4 改期
- 校验目标日期存在名额（同 §5.3 步骤 2）。
- **原子双更新**：先对目标日条件更新 `+1`，成功后再对原日 `-1`；任一步影响行数为 0 即整体回滚 `5002`。禁止「先 -1 再 +1」（失败会把人挤出去）。
- 禁忌重算：改期后按新日期重算 §2.7（妊娠/经期状态可能变化），`拦截` 级 → `5009`。
- 写流水（动作=改期，`from_status`/`to_status` 不变，仅 `orderDate`）。

### 5.5 到诊登记
- 前置：`flow_status=已预约` 且 `orderDate` 为今天或之前（未来日期须先改期）。
- 动作：生成 `exam_no`（`t_member` 档案号按 `07`/`20` §5.1 取得）、`flow_status=已到诊`、`t_order.orderStatus=已到诊`、建 `t_health_report` 草稿（`07` §2）、写流水。
- 换人（原预约人未到、他人代检）**本期禁止**：`t_order.member_id` 不改，冲突返回 `5010`（`17` §1.2 已登记 `last_member_id` 为后续项）。

### 5.6 取消
- 必填 `cancel_reason`；`flow_status=已取消`、`t_order.orderStatus=未到诊`（回写原语义）。
- 名额回退用条件更新 `reservations = GREATEST(COALESCE(reservations,0)-1, 0)`；`已到诊` 及之后的状态取消须先撤销登记，否则 `5006`。

### 5.7 项目重置 / 数据重收 / 复查（`18` C6/C7/D11）
- 重置：把某项结果清空回 `未检`，**必须在 `t_health_item_reset_log` 记 `before_value`**；`已总检` 之后禁止重置，须先总检撤销（`18` C9）。
- 复查登记：必须记 **复查项目 + 时间 + 原因**，并生成复查申请交总检医生审核（`audit_status`）；复查结果在总检界面须与初检、历次复检同屏可比（`18` C7）。
- 延期恢复：项目级回 `未检`，`postpone_count` +1（**实现口径**：计数在延期动作时即 +1，恢复不再重复加，一个延期周期净 +1 次；`postpone_until` 保留作最近延期记录；项目级 `未检` 重置随 `07` 结果录入模块落地，本期订单侧仅恢复 `flow_status=已到诊`），上限次数与可延期范围本期不做硬阈值（记入 `17` 待确认）。

### 5.8 团检备单的衔接
`20` §8 通过本模块服务方法落单：`orderType=电话预约`、`orderStatus=未到诊`、`flow_status=已预约`、`t_health_order_ext.batch_id/batch_member_id` 非空；**不校验短信验证码**。

## 12. 约束与禁止
- 冻结表**禁止 `ALTER`/加列/加索引**；允许的扩展见 `04` §9 落位对照（`17` 决策 42）。
- 预约下单/备单/改期/取消的名额增减必须**同一事务 + 条件更新**，**禁止**先查后改（防超卖）。
- 必须用 `COALESCE` 处理 `reservations` 为 NULL。
- 关联更新必须**差异更新**（删旧 + 插新），禁止「只删不增」或「只增不删」。
- 删除检查项/检查组/套餐必须先做引用校验（`3001/3002/4001`）。
- 图片走 OSS 抽象；Redis 键固定 `health:img:uploaded` / `health:img:used`，禁止另起键名。
